## 폼 칸 1 — 해결하고자 했던 문제 (Problem Definition, 300자 내외)

관세청 수입통계에서 kg당 단가나 상대국 점유율이 전년 같은 달보다 크게 바뀐 경보는 많지만, 담당자가 한 건씩 원인(하위품목 구성 변화, 자료 결측·불일치, 설명되지 않는 변동)을 가려낼 시간은 모자란다. 조사를 언어 모델에 맡기면 숫자·단위·증감 방향을 잘못 쓰는 사실 오류가 섞여 그대로 믿기 어렵다. TradeSentry는 모델이 근거를 찾되 숫자는 검증된 값만 쓰게 하고, 오류율이 실제로 낮아지는지 봉인한 실자료로 증명하려고 만들었다. 부정·위법·원산지 판정이 아니라 무역통계 담당자(가상)의 다음 업무를 제안하는 도구다.

(298자)

## 폼 칸 2 — 서비스 소개 및 주요 기능 (Solution, 500자 내외)

경보마다 Nemotron 조사자가 조회 도구 5개(비교 가능성·이력·상대국 비교·하위품목 분해·근거 검증)로 읽기 전용 스냅샷만 조회해 근거를 모으고 초안을 쓴다. 별도 문맥의 검수자(Critic)가 누락·반대 설명을 지적하면 수정 1회를 거치고, 검증기(코드)가 숫자·단위·증감·근거 ID를 원본 행과 대조해 틀린 보고서를 막는다. 통과한 한국어 보고서는 담당자의 다음 업무를 검토 유지(MAINTAIN)·모니터링(MONITOR)·자료 보류(HOLD) 중 하나로 제안한다. 모델 모드는 규칙 참고값을 보고 판정하며, 필수 조회가 빠지면 도구 호출을 요구받는다. 흐름: 운영자 요청 → NemoClaw 에이전트 → tradesentry 스킬 → OpenShell 샌드박스 안 CLI(detect·run-case) → 보고서·trace. Streamlit 화면 1개로 조회 이유·실행 도구·판정 전후를 본다. 점수용 실행은 샌드박스 안 CLI를 직접 부르고, 밖의 독립 채점기가 정답과 대조한다.

(500자)

- 자료 표본이 커질 때(품목·상대국·기간이 늘고 사후 확인 기록이 쌓일 때) 추가: (5) GraphRAG(지식 그래프 위에서 관련 문맥을 찾아 모델에 건네는 검색 증강 생성) — HS 품목 계층, 상대국·비교국, 사례·판정·사후 확인 이력을 그래프로 이어 조사자가 유사 사례, 하위품목 구성 변화, 같은 상대국의 이력 문맥을 찾는 데 쓴다. 숫자와 근거 ID는 지금처럼 검증된 값과 검증기에서만 나오고, 그래프 검색은 문맥 후보를 대는 역할에 한정한다. (6) 특화 학습 로컬 AI(기관 안에서 도는, 이 업무에 맞게 추가 학습한 모델) — 사후 확인 기록이 학습 자료로 충분히 모이면 Nemotron 계열 소형 모델을 NeMo(NVIDIA의 모델 학습·커스터마이징 프레임워크) 계열 도구로 미세조정해 기관 안 GPU의 NIM 컨테이너로 두고(외부 전송 없음), 경보 분류·초안 작성·Critic 같은 특화 업무를 맡긴다. 바꾼 모델은 같은 봉인 평가 방법(봉인 실자료를 한 번만 채점, 기준선 대비 보고서 단위 오류율)으로 다시 검증하고 새 룰북 버전으로 기록한다.
