# X1 NemoClaw 재시도의 마감과 시험 방식

| 제목 | X1 NemoClaw 재시도의 마감과 시험 방식 |
| 결정 | ① 마감: X1(구현 첫날의 세로형 최소 통합 시험)의 NemoClaw(OpenShell 위에서 에이전트를 돌리는 NVIDIA 참조 스택) 재시도는 벽시계로 같은 날 19:30에 끝낸다. 19:15가 되면 새 시도를 멈추고 기록·커밋한다. ② 사용자를 기다린 시간(16:07~17:12)은 X1의 3시간 시한에 넣지 않는다. ③ 시험 방식: 요건 (b)를 채우는 구성 하나만 시험한다. 요건 (b)는 외부 전송을 NVIDIA 추론 엔드포인트로만 허용하고, L7(HTTP 요청 수준) method·path를 명시하며, `rules`(요청 허용 규칙) 생략과 범용 바이너리(`curl`·`python3`·`node`처럼 어떤 요청이든 보낼 수 있는 실행 파일) + `/**`(모든 경로) 조합을 쓰지 않는 정책 요건이다(`docs/plan/DEV_PLAN.md` §4.1). 구성은 세 가지다. 게이트웨이(샌드박스 밖에서 정책을 적용하고 요청을 중계하는 OpenShell 구성요소)의 추론 경로를 지워 `inference.local`(샌드박스가 보는 관리형 추론 주소)을 끈다. OpenClaw(NemoClaw의 기본 에이전트)를 credential placeholder rewrite로 `integrate.api.nvidia.com`에 직접 잇는다. 이 방식은 샌드박스에는 자리표시 문자열만 두고, 게이트웨이가 요청 헤더에 실제 키를 넣는다(개발 플랜 §4.6은 헤더에 넣는 동작을 `[미확인]`으로 적었고, X1 1차 시험이 확인했다 `[사실: X1 PR로 병합할 artifacts/openshell/violation_tests.md의 키 주입 행]`). 정책은 `openclaw` 실행 파일과 `POST /v1/chat/completions`만 연다. ④ 17:45 무렵 보탠 판단: OpenClaw 2026.7.1의 `openclaw`는 node 스크립트라서, 샌드박스는 OpenClaw가 보낸 요청의 실행 파일을 `/usr/local/bin/node`로 판정한다. 추론 블록(`nvidia`)의 바이너리를 `openclaw`만 두었을 때 모델 호출이 거부됐다 `[사실: X1 PR로 병합할 artifacts/openshell/logs/20260924-x1-demo-openshell-logs.txt 528~530행, node가 `nvidia` 블록에서 거부된 NET:OPEN DENIED 행]`. 설계가 요건 (b) 위반으로 드는 것은 기본 블록 세 개(`clawhub`·`openclaw_docs`·`npm_registry`), 범용 바이너리 + `/**` 허가, `rules` 생략이다(개발 플랜 §4.8). 03 문서(OpenShell 정책 구조 참고 문서 `03-openshell-policy-yaml-구조.md`) §5의 축소 시 체크 포인트 2번도 범용 바이너리와 `/**` 가운데 하나를 반드시 좁히라고 한다. 그래서 추론 블록에 node를 넣고 경로를 `POST /v1/chat/completions` 하나로 좁히는 것은 요건 (b)에 맞는다고 보았다 `[추론]`. 다만 이 구성은 개발 플랜 §4.8 방침 `[DESIGN]`에서 벗어난다. 그 방침은 03 문서 §5 하드닝 템플릿(기본 정책의 허용을 빼거나 좁히는 정책 예시)의 제거·축소를 적용해 추론 블록 바이너리를 `openclaw`만 두는 것이다. 벗어나는 이유는 위의 판정 방식 때문에 `openclaw`만 두면 OpenClaw의 모델 호출이 막힌다는 것이다. 또 온보딩(NemoClaw 설치 뒤 초기 설정·등록 단계) 직후 라이브 정책(실제 적용된 정책)의 `nvidia` 블록 바이너리는 `openclaw` 하나였다 `[사실: X1 PR로 병합할 artifacts/openshell/logs/20260924-x1-demo-policy.txt]`. 그래서 node는 새 허용이고, 새 허용은 위협 근거와 함께 PR로 올린다(개발 플랜 §4.1 작성 원칙). 바이너리 신원은 실행 파일 경로와 조상 프로세스 경로로만 판정하므로(03 문서 §3.3), 이 허가는 OpenClaw만이 아니라 샌드박스 안의 모든 node 프로세스와 그 자손 프로세스에 간다. 허가 범위와 위협 근거는 X1 PR 본문에 적고 보안 검토를 받는다. 개발 플랜 §4.8 문구를 고칠지도 그 PR에서 정한다. ⑤ 그래도 돌지 않거나, `/**`·`rules` 생략·다른 호스트 허용이 필요하면 승인된 예외(`20260924-1504-user-approval-x1-exception.md`)대로 멈추고 사용자 결정을 받는다. 키를 샌드박스에 넣는 우회는 하지 않는다(운용 규칙 §1.4 (b)). 에이전트에 요청을 보내기 전에 요건 (c)(샌드박스 안 키 비보유) 키 조회 시험을 먼저 돌린다. 기록 뒤 확인한 것: 기본 정책에서 온 `openclaw_gateway_dialback` 블록(내부 주소를 규칙 없이 통째로 여는 블록, `access: full`)이 2판(17:24)과 3판(17:46, node 추가)에 남아 있었다. 4판(17:55)에서 이 블록을 지웠고, 지운 뒤에도 한 줄 경로가 다시 돌아 ⑤의 멈춤 조건에는 들지 않았다 `[사실: X1 PR로 병합할 artifacts/openshell/logs/20260924-x1-demo-policy.txt 4·6·7절]`. 그래서 요건 (b)를 채운 구성의 통과 증거는 4판 실행뿐이고, X1 PR은 요건 (b) 판정과 통과 증거를 4판 기준으로 적는다 |
| 19:30에 닿으면 | 한 줄 경로가 통과하지 못했으면 로드맵 §7.1대로 한다. 원인이 두 예외(키 주입 두 방식 모두 실패, 요건 (b) 미충족)면 즉시 사용자 결정을 받는다. 그 밖이면 Brev(NVIDIA 원클릭 클라우드 개발 환경) 단계로 가야 한다. 다만 Brev 계정과 인스턴스는 사용자 몫이고 키를 클라우드 호스트에서 쓰게 되므로, 옮기기 전에 사용자에게 알린다. 19:30은 X1이 실제로 쓴 시간이 약 3시간(1차 48분 + 17:12부터 2시간 18분)에 닿는 시각과 거의 같다 |
| 이유와 근거 | ① 로드맵의 오늘 도착점과 내일 MVP(최소 기능 제품) 시험이 가깝다 `[사실: docs/plan/ROADMAP.md §1]`. ② 3시간 시한은 기술적 난도를 재려는 것이라, 사용자 결정을 기다린 시간을 넣지 않았다 `[DESIGN]`. 이 제외는 계획 문서에 없던 새 판단이다. 대체 경로(Brev → OpenShell만)를 여는 시점을 그만큼 늦춘다. 대체 경로가 발동하면 자기채점 `1c`(NemoClaw 활용 깊이 지표)가 0~1점, `1a`(NVIDIA 기술 개수 지표)가 구성요소 4개 이하로 묶이므로, 가능하면 NemoClaw 경로를 살리는 쪽으로 판단했다 `[추론: 룰북 A2 1c 주석, 부록 39번]`. ③ X1 1차 시험에서 `inference.local`이 샌드박스 정책 밖의 게이트웨이 라우터로 처리돼 어떤 실행 파일이든 쓸 수 있었다. 정책 블록으로 좁히면 요청이 멈췄다 `[사실: X1 1차 시험 기록, X1 PR로 병합 예정]`. 그래서 `inference.local`을 좁히는 반복 시도는 시간만 쓴다고 보았다 `[추론]` |
| 검토한 대안 | 마감 없이 3시간 시한만 쓰는 안: 사용자 대기가 끼면 밤까지 밀린다. `inference.local`을 좁혀 다시 시험하는 안: 위 ③의 이유로 버렸다 |
