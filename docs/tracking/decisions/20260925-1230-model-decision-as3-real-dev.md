# AS3 두 번째 PR: `real_dev` 실행 경로, 인프라 실패 재실행, 내려받기 보강

조립 작업 AS3의 두 번째 PR에서 정한 것을 적는다. 첫 PR(#45, 결정 기록 `20260925-0935-model-decision-as3-evaluate.md`) 검토의 V1 관문 권고 두 가지와 보안 권고를 코드로 반영했다. 평가 방법론 검토의 권고 5(`real_dev` 경로)·권고 1(재실행), 보안 검토의 권고 1·2·4·5는 코드로, 권고 3·6은 기록으로 반영했다. 코드와 시험은 같은 PR에 있다.

용어

- `real_dev`·`real_sealed`: 실자료 품목×상대국 계열 64개를 개발용 21개와 봉인용 43개로 나눈 묶음. 분할 기록은 `data/reference/real_split_kcs_202201_202412_v2.json`이다.
- 좁히기: 관측 값을 읽기 전에 분할 기록으로 `real_dev` 계열만 남기는 일(병렬 개발 규칙 §7.2의 5).
- 인프라 실패 재실행: 모델 제공자 쪽 오류(`PROVIDER_HTTP_5XX`·`PROVIDER_CONNECTION`)로만 `FAILED`가 된 실행을 같은 설정으로 한 번 다시 돌리는 일(룰북 B5).
- 격리: 거부한 내려받기 임시 폴더를 `.quarantine-*`로 이름을 바꿔 두는 일. 사례 폴더로 옮기지 않는다.

## 결정 내용

① **`run-case`가 실자료 사례를 받는다(`real_dev` 계열만)** — 확정

- `RUN_CASE_SOURCE_KINDS`는 `controlled`·`real`이다. 실자료 스냅샷이면 `real_case_scope`가 관측 값을 읽기 전에 두 가지를 본다. 먼저 분할 기록을 읽는다(AS1의 `load_real_split` 그대로, 대응표 `REAL_SPLIT_FILES`). 이어서 `--case`의 계열 (HS6, 상대국)이 `real_dev`인지 본다. `real_sealed`이거나 기록을 쓸 수 없으면 종료 코드 1이다(`RUN_CASE_SEALED_REFUSAL`·`RUN_CASE_SPLIT_REFUSAL`, 받은 값은 문장에 넣지 않는다).
- 통과하면 묶음은 `real_dev`, 비교 대상 집합은 `g0`(`REAL_GROUPING_VERSION`, DT7 최종 빌드와 같다)이다. 단위 P2에는 `dataset=real_dev`와 분할 기록 전체의 배정을 넘긴다(P2의 묶음 제한이 마지막 방어선이다). 도구의 조회 범위(비교국·전체국가 분모)는 좁히지 않는다(병렬 개발 규칙 §7.2의 5).
- 시험(`tests/units/F2/test_run_case_real.py`)은 출처 종류가 real인 합성 스냅샷으로 본다. `real_dev` 사례는 실제 조립(`checklist`)으로 `COMPLETED`다. `real_sealed` 사례는 K3의 관측 값 읽기 9종 호출이 0이고 실행 폴더가 비어 있다. 좁히기를 끈 변이(`real_case_scope` 대역)에서는 같은 사례가 JP 계열 `parent_series`를 부른다. 그래서 거부 시험이 이 변이를 잡는다.
- 샌드박스 이미지 포함 목록(`configs/openshell/image/include.txt`)에 분할 기록을 더했다. 샌드박스 안 `run-case`가 읽기 때문이다. 이 파일은 계열 배정만 담는다. 봉인 표본·정답은 봉인 폴더에만 있다.

② **`evaluate --snapshot kcs_202201_202412_v2`의 사례 목록** — 확정

- 새 파일을 두지 않고 실행 때 만든다. `build_case_list`(detect와 같은 길: 분할 기록 → `real_dev` 계열 → 지표 → P1 → P2. `_detect`도 이 함수를 쓴다)가 경보 목록을 내고, `select_real_dev_mvp`가 DT7 규칙으로 고른다. 규칙은 sha256(`"real_dev-mvp-20260925:" + case_id`) 16진수 오름차순 앞 20건이다. 20건 이하면 전부이고, 층화하지 않는다. 계획 사례는 순위 순서이고, `detect` 실행 폴더는 만들지 않는다.
- 모드는 `PLANNED_MODES["real_dev"]` = `freeform`·`full`이다(룰북 B2, 평가 스킬 ②).
- DT7 결정 기록 표 ④(경보 221건)에 규칙을 다시 적용하면 표 ⑤의 20건과 순위 값이 순서까지 같다(`Dt7SelectionRuleTest`). 정본 빌드(`data/snapshots/kcs_202201_202412_v2/snapshot_build.sqlite`)가 이 작업 폴더에 없어서, 실제 경보 목록과의 대조는 오케스트레이터 명령으로 남긴다(보고 AS3-2).
- 정책은 `--policy` 값이다. DT7 목록은 `policy_v1`로 만들었으므로, 다른 정책이면 경보 목록이 달라진다. 그 목록과 정책 버전은 ③의 기록에 남는다.

③ **실행 조건 입력 파일에 남기는 것** — 잠정(이름은 형식 확정 때)

- `planned_cases`: 고른 사례(분모). 채점 요약이 "real_dev 경보 목록(분모)"으로 적는다(자료 계약 §8.2).
- `snapshot.real_dev_alerts`: `{policy_version, count, case_ids(경보 목록 전체, P2 순서), selected, selection(규칙 문장)}`. 채점기는 `snapshot` 객체의 `file`만 읽으므로 이 값은 요약에 옮겨지지 않고 파일에만 남는다.
- `prescoring_checks.final_status`(평가 스킬 ② 채점 전 확인 1): 모든 묶음에 쓰는 문장이다. 예: "참: 예정 실행 40건 가운데 줄 없는 조합 0건, 인프라 실패 재실행(룰북 B5) 대상 n건·재실행 n건". 값이 있으면 재실행 규칙을 적용한 묶음이고, 없으면 채점기 요약에 "미기재"다. 그래서 "재실행 안 함(0건)"과 "해당 없음"이 갈린다.

④ **인프라 실패 재실행(룰북 B5)** — 확정

- 단위 E1 `execute_batch`는 첫 실행이 모두 끝난 뒤, 첫 실행 줄 가운데 단위 L3 `infra_rerun_eligible` 줄을 첫 실행 순서대로 같은 설정으로 한 번씩 다시 돌린다. 그런 줄은 `FAILED`이고 원인이 `PROVIDER_HTTP_5XX`·`PROVIDER_CONNECTION`뿐이다. 재실행마다 새 실행명을 확보하고 같은 묶음 기록에 줄을 더한다. 원래 줄은 그대로 둔다. 재실행 줄은 다시 돌리지 않고, 다른 실패도 돌리지 않는다.
- 채점기의 재실행 모양(`check_rerun_shape`: 같은 (사례, 모드)의 줄은 실행명 시각 순으로 "FAILED 한 줄 뒤 재실행 한 줄"까지)과 맞다. 채점기 요약은 가장 늦은 줄을 분모 행으로 쓰고, 재실행 건수를 모드별로 센다(`eval/scorer/summary.py` `Plan.reruns`, 읽기만 해 확인).
- 단위 E3의 줄 단위 건수는 재실행 줄까지 센다. 재실행이 다시 인프라 실패로 끝나면 그 줄도 E3 재실행 대상 목록에 든다. (사례 × 모드) 최종 행 기준 건수는 MT7 다음 PR 7이다.

⑤ **내려받기 보강(보안 권고 1·2·4·5)** — 확정

- 권고 1: `os.walk(followlinks=False, onerror=…)`가 읽을 수 없는 하위 폴더를 모은다. 하나라도 있으면 거부·격리한다(그 아래 링크를 훑지 못하므로).
- 권고 4: 링크 수가 2 이상인 일반 파일(하드링크)을 특수 항목으로 보고 거부한다.
- 권고 2(N6·N7 배치와 NAT 파일): 옮기기 전에 최상위 항목이 `{도메인명}-{그 실행명의 시각}.{확장자}` 파일이나 `{도메인명}-{시각}/` 폴더인지 본다. 아니면 거부한다. 옮긴 뒤 `workflow_nat_wrap-{시각}/`에 NAT 프로파일 파일 5개(단위 I13 `PROFILE_FILES`)가 모두 있는지 보고, 없으면 사건 한 줄을 남긴다. 실행 기록은 그대로 받는다: 결과가 난 실행을 버리지 않고, E4 `profile_files_complete`에도 드러난다.
- 권고 5: 훑는 중 입출력 오류나 옮기기 충돌이 나면 임시 폴더를 `.quarantine-*`로 격리한다. 그래서 `outputs/`에 `.download-*`가 남지 않는다. 받기 자체가 실패하면 임시 폴더를 지운다.
- 거부는 모두 `harness:DownloadRejected`(충돌은 `harness:DownloadMoveConflict`) `FAILED` 줄로 분모에 남는다(첫 PR ④ 그대로, 재실행 대상 아님).

⑥ **호스트 제한 시간과 원격 실행(보안 권고 3)** — 기록

- 샌드박스 안 `run-case`는 자기 사례당 wall time 한도(모델 설정 `limits.wall_ms` 300,000ms, 흐름 조정 I12의 `DEADLINE`)로 원격에서 스스로 멈추고 기록을 남긴다. NAT 내보내기 대기는 최대 30초(`nat_wrap.EXPORT_WAIT_S`)다.
- 호스트 쪽 제한은 그보다 길다: `openshell sandbox exec --timeout`이 한도 + 120초(420초), 하위 프로세스 제한이 거기에 30초를 더한 값이다. 그래서 정상 경로에서는 원격 `run-case`가 먼저 끝난다.
- 호스트 제한에 걸린 경우(`SandboxExecFailed`) 원격 프로세스가 끝나는지는 실측 전이다 `[미확인]`. 오케스트레이터 실측 목록에 넣었다(보고 AS3-2).

⑦ **첫 PR 결정 기록 문구 바로잡기(보안 권고 6)** — 기록

- 첫 기록 "영향과 넘길 곳"의 "download가 상대경로 받는 곳을 받는지"는 해당이 없다. `tempfile.mkdtemp`는 절대경로를 돌려주므로 받는 곳은 절대경로로 넘긴다. 결정 기록은 고치지 않으므로 여기에 적는다.
- 원격 인자 안전성: `openshell sandbox exec`가 인자를 원격에서 셸로 다시 잇는지는 확인하지 않았다. 넘기는 값의 안전성은 단위 F1 검사(스냅샷 ID·정책 이름·사례 인자·실행명의 좁은 문자 집합)에 기댄다.

## 검토한 대안

- `real_dev` 20건을 파일로 커밋하기: 새 경로라 사용자 승인 대상이다. 규칙이 결정적이고 DT7 표로 재현을 시험하므로 실행 때 만든다.
- 경보 목록 전체를 새 최상위 키로 두기: 채점기가 약속 밖 키를 거부한다. 기존 `snapshot` 객체 아래에 두었다.
- 재실행을 E3 목록 → 별도 명령으로: 실행 조건 입력 파일을 evaluate가 배타 생성하므로 같은 실행 안에서 끝내야 한다. E1 끝에 넣었다.
- NAT 파일이 없으면 사례를 실패로: 결과가 난 실행을 버리게 된다. 사건과 E4 건수로 드러내는 쪽을 골랐다.

## 영향과 넘길 곳

- 오케스트레이터: 정본 빌드가 있는 저장소에서 `real_dev` 목록 대조를 돌리고, 이미지를 다시 스테이징한 뒤 샌드박스 스모크를 돈다. 이미지에는 분할 기록과 v2 빌드가 들어가야 한다(`?data/snapshots/kcs_202201_202412_v2/…`는 선택 항목이다). 명령은 보고 AS3-2에 있다.
- MT7 다음 PR·DT8: 실행 조건 입력 파일 형식 확정 때 `snapshot.real_dev_alerts`와 `prescoring_checks.final_status` 문장을 확정한다. E3 최종 행 기준 건수도 이때다.
- 조립 점검(AS4): 조립체 3·4의 단위 판정 변경은 없다. 1단계(경계 시험)·5단계(골든·조립 시험)는 보고 AS3-2의 종료 코드다.
