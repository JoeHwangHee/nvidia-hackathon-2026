# MT2 조회 도구·예산의 해석과 입출력 약속

MT2(조회 도구 5개와 예산 집행, 모델 트랙) 구현(단위 I1~I6, PR #31)에서 자료 계약이 모델 트랙(M)에 맡겼거나 정하지 않은 세부와, 검토 1회차(무역통계·관세, 평가 방법론, 보안)가 요구한 해석을 적는다. 코드와 시험은 PR #31의 `src/tradesentry/tools/`와 `tests/units/I1~I6/`에 있다. 항목마다 **확정** 또는 **잠정**을 붙였다. 잠정 항목은 적힌 조건이 채워지면 새 기록으로 확정하거나 바꾼다.

용어

- 도구 5개: I1 `check_comparability`(비교 가능성), I2 `get_history`(이력), I3 `compare_partners`(비교국), I4 `decompose_hs`(HS10 분해), I5 `verify_evidence`(근거 대조). I6 `budget`(예산 집행)은 도구 시도의 허용·거부를 정한다.
- 봉투(envelope): 도구 5개가 같은 키 11개로 돌려주는 출력 틀(자료 계약 §5.2).
- 요청: 흐름 조정(단위 I12)이 도구에 넘기는 입력. 모델 인자(모델의 도구 호출에 실려 오는 `args`)와 코드가 채우는 나머지 키로 나뉜다.
- 막힌 시도(blocked): 흐름이나 예산이 도구에 넘기지 않고 거부한 도구 호출. 예산을 쓴 시도(consumed): 도구에 닿았거나(`ok`·`failed`) 저장해 둔 결과로 답한(`cache_hit`) 시도.
- C형: 그 달 대상국 부모 HS6 행은 있는데 HS10 하위 자료만 상태 행(값 없이 관측 상태만 적은 행)인 경우. 합성 사례 oracle C가 이 경우다(자료 계약 §2.3.2 행 규칙 4).
- 정확값: 표시 자릿수로 반올림하기 전의 값. 지표 단위(X1~X3)의 `exact_value`가 분수로 준다.

## 결정 내용

① **도구 요청 모양** — 확정

- 요청: `{"case_id", "snapshot_id", "scope": {"hs6", "partner", "month", "baseline_month"}, "attempt", "args"?, "policy_version"?, "grouping_version"?, "envelopes"?}`.
  - `scope`는 사례가 정하는 네 키뿐이다(판정 정책 단위 P2가 만든다). 비교국과 HS10 범위는 도구가 스냅샷에서 정한다(자료 계약 §5.1이 M에게 맡긴 범위 객체).
  - `attempt`(사례 안 도구 시도 순번, 1 이상 정수)는 필수다. `query_id`에 넣어 호출마다 고유하게 한다(자료 계약 §4.5). 같은 인자로 두 번 부르는 `verify_evidence`(기본·최종)도 겹치지 않는다(평가 방법론 권고 6).
  - `policy_version`은 I1·I4·I5가 필수로 받아 정책 수치(단위 K4)를 읽는다. `grouping_version`은 I3이 필수로 받는다. `envelopes`(이 사례에서 앞서 받은 봉투 원본)는 I5만 받는다.
  - 경로·SQL·URL·셸 명령은 요청 어디에도 받지 않는다. 승인 전 개발 빌드는 부르는 코드가 자료 접근층 `open_snapshot(…, path=)`으로 열어 각 도구 모듈의 `query(snap, 요청)`에 넘긴다. `run(요청)`은 정본 빌드만 연다.
- 오류: 요청 모양·스냅샷·범위 밖 사례·행 규칙 위반은 `ToolError`(재시도할 수 없는 오류)다. 파일·SQLite 오류(OSError·sqlite3.Error)는 예외 이름만 담은 `ToolError`로 바꾼다(문장에 경로가 들지 않게, 자료 계약 §10.3 N13, 보안 권고 1). 모델 인자가 허용 밖이면 도구를 돌리지 않고 `retryable_error: {"code": "invalid_args", "detail", "allowed"?}` 봉투를 돌려준다.
- 모델 인자는 둘뿐이다: `compare_partners.partners`(허용 비교국 가운데 1~5개, 겹침 없음, 영문 대문자 두 글자를 글자 그대로 검사)와 `verify_evidence`의 `metric_ids`·`evidence_ids`(흐름이 초안에서 뽑는다. 목록마다 200개, 문자열마다 256자. 둘 다 비면 `invalid_args`로 거부해 빈 대조가 "모두 통과"로 읽히지 않게 한다). 나머지 도구는 인자를 받지 않는다.

② **봉투 공통 모양** — 확정

- 봉투는 단위 K5 `make_envelope`로 만든다. `query_id` = `{도구}-{sha256(case_id·snapshot_id·도구·정규화한 args·attempt)의 앞 16자}`. `elapsed_ms`는 단조 시계로 잰다.
- `scope`(실제로 조회한 범위): 사례 네 키 + `months`(읽은 달), `partners`(읽은 상대국, 분모는 `ALL`), `hs10`(읽은 대상국 HS10 코드). I3은 `grouping_version`을 더한다.
- `missingness`: 자료 접근층(단위 K3)의 빠진 자료 항목 `{"evidence_id", "request_id", "partner_code", "hs_code", "month", "flow", "observation_status"}`을 싣는다(키 이름 변환 없음. 판정 정책 P3가 `partner_code`를 읽는다). 근거 ID로 중복을 뺀다. `CONFIRMED_NO_TRADE`(승격된 무거래 확정)는 빠진 자료가 아니라 싣지 않고 근거 ID와 상태 표시에만 둔다. `ALL` 분모는 행 규칙 5·6의 중복 제거 뒤에도 값 행이 없는 달만 싣는다(판정 정책 결정 ⑫를 지킴). C형 항목은 ④.
- 지표: 지표 단위(X1 단가, X2 점유율, X3 분해)의 출력을 고치지 않고 싣는다. I2는 X1·X2의 10개, I3은 비교국마다 `r_U`·`d_s`, I4는 X3 전부(분해 세 값과 HS10마다 `U@`·`r_U@`·`w@`, 자료 계약 §2.3.4), I1·I5는 없다.

③ **도구별 `comparability`** — 확정

- I1: `comparable`(두 신호 가운데 하나라도 계산할 수 있으면 참. 흐름은 거짓이면 이력·하위 조회를 건너뛴다), `period`, `units`·`units_ok`, `hs_version`, `parent`(달별 관측 상태와 `weight_zero`), `denominator`(`ALL` 달별 상태·HS10 행 수), `children`(달별 상태·행 수·관측 코드 `codes`, `same_hs10_set`), `signals.{unit_value,share}.{evaluable,issues}`, `rounding`(⑨). `issues`는 빠진 자료 밖의 문제만 적는다: `units_mismatch`, `no_trade:{달}`, `zero_weight:{달}`, `zero_baseline:{달}`, `zero_denominator:{달}`. 판정 상태는 돌려주지 않는다.
- I2: `history`(기준월~비교월 13개월의 대상국 부모 HS6 관측 상태와 원본 행 근거 ID, 값 없음), `denominator`. `missingness`는 두 사례 달만.
- I3: `grouping_version`, `comparable`·`issues`(허용 비교국이 없으면 거짓과 `no_allowed_peers`. 비교를 수행하지 못한 것을 "비교 완료"로 옮기지 않게, 무역통계 검토 지적 3), `denominator`, `peers_allowed`, `peers`(비교국별 두 달의 관측 상태와 `amount_zero`(수입 0 명시)). 무거래 비교국은 비교를 마친 것, 빠진 자료만 미완료로 볼 수 있게 남긴다(판정 정책 결정 ⑦).
- I4: `parent_check`(X3의 달별 부모 대조), `hs10`(달별 하위자료 상태와 코드), `same_hs10_set`.
- I5: `ok`, `metrics`(metric_id마다 문제 코드와 다른 키), `evidence`(근거 ID마다 문제 코드와 어긋난 풀림 규칙).

④ **C형의 빠진 HS10 코드** — 모양은 확정, 출처 순서는 잠정

- 모양(확정): C형 달의 하위자료 상태 항목(HS6 요청이 남긴 상태 행)에 두 키를 더한다. `"hs10_codes"`(빠진 HS10 코드 목록)와 `"hs10_codes_source"`(출처). 상태 행 하나(근거 ID 하나)에 코드가 여럿이라 목록 필드로 둔다. 근거 ID로 중복을 빼도 코드가 남는다. 코드마다 `observation_status@<HS10>` 자료 상태로 펼치는 일은 받는 쪽(흐름 조정·조립 AS2)이 한다. 검증기 결정(`20260925-0048-model-decision-mt3-validator.md` ⑨)은 C형 자료 상태를 빠진 HS10 코드마다 쓰도록 정했다.
- C형만 붙인다: 그 달 대상국 부모 HS6 행이 `OBSERVED`일 때다. 부모 행도 없는 달의 상태 행은 그 달 자체가 빠진 것이라 붙이지 않는다(HS6 수준 자료 상태).
- 출처 순서(잠정. 앞에서 얻으면 멈춘다)
  1. `other_case_month`: 사례의 다른 달(기준월↔비교월)에 관측된 이 상대국·HS6의 HS10 코드. 분해에서 비교할 코드와 같다.
  2. `other_months`: 스냅샷의 나머지 달에 관측된 이 상대국·HS6의 HS10 코드 합집합. 두 사례 달 모두 하위자료가 빠진 경우다.
  3. `reference_table`: 참고 품목표 `data/reference/hs10_ch85_itemcode_vs_2026.json`의 `hs10_ch85`(관세청 조회코드 품목코드 시트) 가운데 그 HS6로 시작하는 코드. 스냅샷 어느 달에도 이 상대국·HS6의 HS10 행이 없는 경우다.
  4. `none`: 빈 목록. 참고 품목표를 읽을 수 없을 때만 생긴다.
  - 조건: DT5의 합성 C형 시나리오와 채점기(DT8)의 기대 코드가 이 순서와 맞는지 `RB-1` 동결 전에 대조해 확정한다. v2 실자료는 요청 실패와 부모·하위 한쪽만 있는 조합이 0건이라 이 규칙이 쓰이지 않는다.
- 무거래 확정 달의 하위 행에는 부모의 무거래 확정 근거(같은 상태 행)를 붙인다. 자료 접근층 `children()`이 이 달의 근거를 주지 않기 때문이다(DT1에 요청).

⑤ **예산 판정 규칙(단위 I6)** — 확정

- 판정 순서: deadline → 도구 이름(`unknown_tool`) → 정규화할 수 없는 후보 인자(`invalid_args`) → Critic 차례(`critic_no_tools`) → 예산 8회(`tool_attempts_limit`) → 수정 단계 1회(`revision_limit`) → 단계 몫(`basic_limit`(기본 경로 5회, 그 가운데 1회는 `verify_evidence` 몫), `requery_limit`(수정 단계 조회 2회), `final_verify_only`·`final_verify_limit`) → 같은 인자(`same_args`).
- 예산을 쓰는 결과는 `ok`·`failed`·`cache_hit`다. 같은 도구를 다른 인자로 다시 부른 시도와 `verify_evidence`도 쓴다(자료 계약 §5.3). 막힌 시도는 예산을 쓰지 않는다. 단계 몫(5·2·1)의 합이 한도 8과 같아, 막힌 시도가 예산을 쓰면 한 차례에 도구 호출을 여럿 낸 모델이 예약된 최종 검증 몫을 빼앗기 때문이다. 흐름 조정(MT4)의 단계 몫도 실행한 시도만 세어 두 단위의 집행이 같다(평가 방법론 검토 보고 2절). 평가 방법론 검토는 이 규칙이 모드 사이에 공정하다고 봤다(`checklist`는 거부가 없고, 모델 모드의 거부는 모델 요청·토큰으로 비용을 치른다).
- 같은 인자는 정규화해서 비교한다: 객체 키 순서와 목록 순서는 따지지 않고, 목록의 중복은 따진다. 중복을 없애면 `partners` `["CN","CN"]`이 `invalid_args`로 실패한 뒤 고친 `["CN"]`이 같은 인자로 막혀 룰북 B1 시나리오 9(복구할 수 있는 잘못된 조회 범위)를 복구할 수 없다(평가 방법론 권고 5). `verify_evidence`는 같은 인자 차단에서 뺀다(흐름이 예약한 차례에만 부르고, 그사이 받은 봉투가 늘면 대조 결과가 달라질 수 있다).
- 한도 값은 흐름 조정 설정(`configs/model/model.json`)과 같은 키를 받고, 빠진 키는 계약 값(8·5·1·2·1)이다. 계약 값보다 큰 값은 거부한다(설정이 한도를 넓히지 못한다, 보안 권고 2). 시험용으로 낮추는 것은 된다.
- `ToolBudget`에 `deadline_ms`를 주면 `now_ms`가 꼭 있어야 한다(조용히 건너뛰지 않는다).

⑥ **실행 결과 기록의 `tool_attempts`에 무엇을 적나** — 잠정(사용자 확인 대기)

- (가) 예산을 쓴 시도 수(`consumed`)를 적고, 막힌 시도는 trace(실행 추적 기록)의 `budget_block` 사건으로만 남긴다. 기록 값에서도 "`tool_attempts ≤ 8`"과 "9번째 시도 차단"(로드맵 §3 체크리스트 2번)이 글자 그대로 참이고, `model_requests`(보낸 요청만 셈)와 뜻이 같다.
- (나) 막힌 시도까지 센 수(`recorded`)를 적는다. 정상 완료(`COMPLETED`) 실행도 9 이상이 될 수 있다.
- 평가 방법론 검토는 (가)를 권한다. MT4 결정 기록(PR #29, 병합 전)의 잠정 해석은 지금 (나)다. 단위 I6는 두 수를 모두 돌려주고 어느 쪽도 정하지 않는다. 조건: 사용자가 정하면 새 기록으로 확정하고, (가)면 자료 계약 §5.3·§8.1에 풀이를 더하는 공용 약속 절차를 밟는다.

⑦ **수정 단계 판단의 범위** — 확정

- I6는 예산을 쓴 시도의 순서에서 `revision`이 이어진 덩어리 하나를 수정 단계 하나로 본다. 보조 장치다. 도구를 부르지 않은 수정 단계와 Critic 차례만 사이에 낀 재진입은 도구 시도 순서에 드러나지 않아 보지 못한다. MVP 체크리스트 2번의 "두 번째 수정 단계 차단"·"수정 단계의 세 번째 재조회 차단"·"전체 deadline 우선 종료"의 증거는 흐름 조정(단위 I12)의 시험이다. 도구 쪽 증거는 "9번째 도구 시도 차단"(I6 골든)이다.

⑧ **`verify_evidence`의 대조 범위** — 확정(개발 플랜 §6.5 표와 다름)

- 대조하는 것: 수치(같은 원본 행을 같은 지표 단위로 다시 계산한 지표와 글자까지 같은가), 단위(계약 단위), 원본 행(풀림 규칙 1~4, 사례 범위, 총계 행), 출처(앞서 받은 봉투가 돌려준 지표·근거인가).
- 대조하지 않는 것: 필수 근거, 허용 상태, 명시적 금지 문구. 도구는 초안 글을 받지 않는다. 필수 근거는 판정 정책 결정 ⑬이 검증기(단위 R3)에 배정했고, 허용 상태·금지 문구는 개발 플랜 §7.4가 검증기의 검사로 적는다. 도구의 허용 import에 `validator`가 없어 둘째 목록을 두면 어긋날 위험이 있다.
- 검토 판단: 무역통계 검토는 막을 일이 아니라고 봤다. 평가 방법론 검토는 받아들일 만하고 오히려 낫다고 봤다(두 모드가 같은 도구 피드백을 받고 산문·필수 근거 검사는 검증기·정책에 남아 룰북 B2의 `freeform`·`full` 차이가 깨끗하다). 개발 플랜 §6.5에 보완 주석을 다는 일은 문서 PR 후보다.
- 봉투의 `evidence_ids`·`metrics`는 늘 비운다. 대조한 ID를 "도구가 돌려준 근거"로 다시 실으면 모델이 지어낸 실제 행 ID가 검증기의 출처 검사를 통과하기 때문이다. `envelopes`에는 흐름이 도구에서 실제로 받은 봉투 원본만 넘긴다(모델 출력이나 모델에게 보인 축약본이 아니다, 보안 권고 3).

⑨ **반올림 민감도(`check_comparability`의 `rounding`)** — 잠정(판정 정책 결정 ⑤와 같은 정의, 사용자 확인 U4 대기)

- 부모 HS6 행 중량이 행마다 정수 kg로 반올림돼 참값이 Q ± δ(δ = 정책 `tolerance.weight_rounding_kg`, 행 하나 몫이라 자료 계약 §11.1 식의 행수 0)에 있다고 보고, 그 범위에서 `r_U`의 최소·최대(분수로 계산, 표시 소수 1자리 사사오입)와 부호·탐지 임계값 충족이 바뀌는지(`direction_stable`·`threshold_stable`, 하나라도 바뀌면 `unstable`)를 준다. Q ≤ δ인 달이 있으면 범위는 null이고 `unstable`이다. 금액은 정확 일치라 넣지 않는다. 임계값은 정책 `thresholds.unit_value`에서 읽는다.

⑩ **HS 버전은 스냅샷 단위로만 본다** — 확정

- 자료 접근층이 행의 `hs_version`을 주지 않아 두 달의 개정판 차이를 달별로 비교하지 못한다. 스냅샷 메타의 `hs_version`을 싣는다. v2와 합성 자료는 모두 `HSK`다(무역통계 권고 7). 달별 비교가 필요하면 DT1에 행 `hs_version`을 요청한다.

⑪ **`resolved_after_correction`은 도구가 내지 않는다** — 확정

- 교정 전후 두 스냅샷이 사례 범위에 없어 스냅샷 하나로는 만들 수 없다. 판정 정책 P3에는 거짓으로 들어간다.

⑫ **`Q`(순중량) 지표는 도구가 내지 않는다** — 확정(D17 후보)

- 지표 단위가 `Q` 지표를 내지 않는다. 반올림 불안정 보류의 필수 근거(`precision_sensitivity_shown`)를 어떤 주장으로 채울지는 D17(원 작업 병합 뒤 같은 작업 ID로 내는 "F1 전" 보완 PR)에서 DT2와 함께 정한다(무역통계 권고 6).

⑬ **시험 방식** — 확정

- 도구 시험은 진짜 수집기·스냅샷 빌더(단위 S2)로 만든 합성 스냅샷(`tests/units/I1/tools_fixture.py`, `unit_fixture_tools`)을 진짜 자료 접근층과 진짜 지표 단위로 돌린다. 지표 단위가 병합된 뒤라 대역(가짜 계산)을 쓰지 않는다. 호출 기록이 필요하면 `unittest.mock.patch.object(…, wraps=진짜 run)`으로 감싼다(`metrics_spy.py`).
- 합성 스냅샷의 C형: CN(한 달 실패, 출처 1), IN(두 사례 달 모두 빠짐, 출처 2), KH(모든 구간 실패, 출처 3).

## 검토한 대안

- ④ (나) 코드 목록을 조립 AS2가 봉투의 다른 곳(분해 도구의 실패 달 `U@` null 지표나 다른 달 코드)에서 도출한다: 흐름이 비교 불가로 일찍 끝나 분해 도구를 부르지 않으면 코드를 얻을 곳이 없고, 두 달 모두 실패하면 도출할 수 없어 버렸다. 코드마다 `missingness` 항목을 따로 둔다: 근거 ID로 중복을 빼는 곳(도구 `finish`, MT4 변환)에서 한 항목만 남아 버렸다. 두 달 모두 실패일 때 `ALL` HS10 코드(분모 행 코드)를 쓴다: 대상국과 무관한 전체국가 코드라 참고 품목표보다 근거가 약하고, 분모도 빠진 달에는 쓸 수 없어 택하지 않았다.
- ⑤ 막힌 시도도 예산을 쓴다: 최종 검증 예약이 깨지고, 모델 모드만 도구 없이 예산을 잃어 비교군이 기울어 버렸다. 같은 인자에서 목록 중복도 없앤다(1회차 구현): 시나리오 9 복구를 막아 버렸다. `invalid_args` 실패를 같은 인자 비교에서 뺀다: 같은 잘못된 인자를 되풀이하는 호출까지 허용해 버렸다.
- ⑧ 도구 안에 금지 문구 목록과 필수 근거 대조를 둔다: 검증기 목록과 두 벌이 되어 어긋날 위험이 있고, 초안 글을 도구에 넘기면 글을 통한 주입 표면이 생겨 버렸다.
- I3 허용 비교국 0을 `ToolError`로 멈춘다: 흐름이 실행 실패로 끝나 자료 상태·설정 오류의 뜻이 사라지고, 오케스트레이터가 명시 표시를 택했다.

## 영향과 넘길 곳

- 파일: `src/tradesentry/tools/`(I1~I6), `tests/units/I1~I6/`.
- 흐름 조정(MT4 `unit_ports`)·조립 AS2
  - 도구 요청에 `attempt`(시도 순번), `policy_version`(사례의 값), `grouping_version`(실행 맥락), `verify_evidence`에는 `envelopes`(받은 봉투 원본)를 넣는다. 없으면 `ToolError`다.
  - C형 `missingness` 항목의 `hs10_codes`를 코드마다 `observation_status@<HS10>` 자료 상태로 펼친다(④).
  - I3 `comparability.comparable`이 거짓(`no_allowed_peers`)이면 비교국 비교를 `not_performed`로 옮긴다. 조회한 비교국의 자료가 모두 빠졌으면 `incomplete`다(비교국별 관측 상태로 가린다).
  - 판정 정책 P3 근거 상태로 옮길 때 `missingness`는 키 이름을 바꾸지 않고 넘기고, 수(`U_baseline`, 분해 세 값, 하위품목 `r_U`)는 표시 값이 아니라 지표 단위의 `exact_value`(정확값)로 옮긴다(판정 정책 결정 ②, DT2 결정 ②).
  - 예산: 한도 다섯 키를 모두 넘기고, 막힌 시도를 넘기면 `outcome: "blocked"`, `retryable_error` 봉투나 `ToolError`는 `failed`로 기록한다. 실행 기록 `tool_attempts`는 ⑥이 정해지면 그 뜻대로 적는다.
- DT5(합성 자료)·DT8(채점기): C형 자료 상태의 코드 목록과 출처 순서(④)를 같게 쓴다.
- DT1: 자료 접근층 `children()`이 무거래 확정 달의 근거 ID를 주도록, 필요하면 행의 `hs_version`도 주도록 요청한다(④·⑩).
- 문서 PR 후보: 개발 플랜 §6.5에 `verify_evidence` 대조 범위 보완 주석(⑧). ⑥이 (가)로 정해지면 자료 계약 §5.3·§8.1 풀이(공용 약속 절차).
