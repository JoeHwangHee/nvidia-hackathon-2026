# MT3 코드 PR: 검증기 R3의 산문 규칙을 채점기 C2에 맞춤(룰북 B3-2 "둘이 어긋나면 채점기 판정이 기준")

룰북 `RB-1`(평가 룰북의 첫 동결 버전) 동결(2026-09-26(토) 18:00) 전 확정 항목 "MT3 검증기와 채점기의 산문 규칙 불일치"를 **검증기 쪽만** 고쳐 채점기에 맞춘 기록이다. 근거는 두 구현을 같은 문장 약 190개로 대조한 읽기 전용 분석(규칙 수준 불일치 14곳, 커밋된 실제 결과에서 드러난 불일치 0건) `[사실: 오케스트레이터 분석 보고 PROSE1-1]`이고, 결과를 보고 유리하게 고친 것이 아니다(`CLAUDE.md` 절대 규칙 5). 룰북 문장·채점기(`eval/scorer/`)·판정 정책·프롬프트(`configs/model/`)·금지 표현 목록(`FORBIDDEN_PHRASES`)은 바꾸지 않았다.

용어

- 검증기 R3(`src/tradesentry/validator/validate.py`): 실행 중에 보고서를 검사해 뒷받침되지 않는 산문 숫자·증감 표현을 `PROSE_UNBACKED` 사유로 적는 코드. `full`·`agent`·`checklist`에서는 막고 `freeform`에서는 기록만 한다(단위 R4가 정한다).
- 채점기 C2(`eval/scorer/prose.py`): 실행이 끝난 뒤 샌드박스 밖에서 같은 산문 규칙으로 `UNBACKED_PROSE`를 매기는 독립 채점기. 룰북 B3-2 끝 문장대로 둘이 어긋나면 채점기 판정이 기준이다.
- 산문 패턴 PT-n·빼는 표현 EX-n: 룰북 B3-2의 분류(PT-1 백분율 … PT-8 "X에서 Y로", EX-1 날짜·기간 … EX-6 지표 이름).
- 불일치 유형 (가)·(나): (가) 검증기가 채점기보다 관대하면 `full` 보고서에 뒷받침 없는 산문이 남아 채점에서 `UNBACKED_PROSE`가 되고, (나) 검증기가 채점기보다 엄하면 수정 1회 뒤 `INVALID`(분모에 남는 실패)가 된다. 둘 다 `full`에 불리하고 `freeform`에는 영향이 없다.

## 까닭

- 룰북 B3-2 마지막 문단: "런타임 검증기와 채점기는 이 절을 각자 구현한다. 이 절이 정본이고, 둘이 어긋나면 채점기 판정이 기준이다." 검증기가 채점기보다 관대한 곳은 `full`이 채점에서 감점되고, 엄한 곳은 `full`이 무효로 끝난다.
- 분석 보고서(2026-09-26(토), scratchpad `PROSE1-1`) §1 규칙 대조표는 규칙 수준 불일치 14곳을 찾았고 `[사실: 오케스트레이터 분석 보고 PROSE1-1]`, §2는 커밋된 4개 묶음에서 `full` 보고서 가운데 검증기가 통과시켰는데 채점기가 잡은 건이 0건, 실행 trace 464개에서 불일치 표현이 나온 실행이 0건임을 확인했다. 따라서 이 변경은 관찰된 결과를 뒤집지 않으며 규칙 불일치만 없앤다.

## Codex(검증기) 1회차 반영

- 지적 1(EX-1·EX-4 새 패턴의 공백): 지적은 "채점기가 공백을 허용하지 않는다"였으나 채점기 `eval/scorer/prose.py` 86·97·100행은 `\s*+`(공백 0개 이상, 소유 한정자)이고 실측에서도 "2 주 동안"·"제 3 국"·"1 kg 당"을 뺀다. 그래서 공백 비허용으로 바꾸지 않고, 검증기의 `\s?`(0~1개)를 채점기와 같은 `\s*`(0개 이상)로 맞췄다(`N일`·`N주`와 `연속` 앞, `제N`, `Nkg당`). 두 칸 이상 띄운 "2  주"에서 나던 차이가 사라진다.
