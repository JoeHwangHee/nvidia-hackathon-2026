# 봉인 묶음 실행 사슬의 출력 범위(결정 기록 1720 "경계와 순서" ① 보완)

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-09-24(목) 20:03(기록 시각) |
| 제목 | 봉인 묶음 실행 사슬의 샌드박스 밖 출력도 `outputs/sealed/`에 둔다 |
| 결정 | ① `outputs/sealed/`에는 봉인 묶음(개발 중 보지 않도록 봉인한 평가 자료 묶음. holdout40과 `real_sealed`)을 실행하는 사슬의 출력을 둔다. 샌드박스에서 내려받은 출력에 더해, 샌드박스 밖에서 생기는 봉인 관련 출력 네 가지도 각자의 실행 폴더로 둔다. 네 가지는 단위 E2(샌드박스 밖 실행기)의 묶음 기록, 실행 조건 입력 파일(채점기가 모르는 실행 조건 값을 담아 호스트 쪽 프로그램이 배타 생성하는 파일), 단위 E3(추출 명령)의 인프라 실패 재실행 대상 목록, 봉인 기간의 `openshell logs` 발췌다. ② 봉인 자료(holdout40 입력·정답표, `real_sealed` 사례 목록·표본, seed)는 지금처럼 저장소 밖 봉인 폴더에만 둔다. ③ 봉인 묶음을 채점한 채점기 출력은 계획 경로 표대로 `outputs/score-{시각}/`에 둔다. 채점기가 시작 직후 자기가 확보한 실행 폴더 이름을 알리고, 평가 스킬 ②가 그 이름을 봉인 사건 "채점 시작"에 덧붙인다. ④ 금지를 푸는 조건은 하나다. 정답 대조 채점이 끝나야 하고(채점기 종료 코드 0과 봉인 사건 "채점 완료" 기록), `real_sealed`이면 표본 추출 seed 공개 기록도 있어야 한다. 이 조건은 `outputs/sealed/` 아래 전부와 봉인 묶음을 채점한 채점기 출력 폴더에 똑같이 적용한다. ⑤ 열람 금지의 예외는 늘리지 않는다(결정 기록 1720 "경계와 순서" ⑤). 봉인 실행 출력이 있어야 만드는 값(NAT 프로파일 요약, 한국어 품질 표본 점검)은 ④의 조건이 채워진 뒤 결과표(로드맵 R1)에 적고, 채점기 요약에는 넣지 않는다 |
| 결정 1720 ①과의 관계 | 결정 기록 `20260924-1720-user-decision-domain-restructure.md` "경계와 순서" ①은 이렇게 적었다: "봉인 자료(…)는 계속 저장소 밖 봉인 폴더에만 둔다. `outputs/sealed/`에는 봉인 묶음을 샌드박스에서 실행한 출력만 둔다." 둘째 문장의 "만"은 첫 문장과 짝을 이뤄 실행 출력과 봉인 자료를 가르는 말로 읽는다. 사용자가 고른 선택지 문구는 "봉인 묶음 실행 출력은 outputs/sealed/"였다 `[사실: 2026-09-24(목) 채팅]`. 1720 기록은 "경계와 순서"를 오케스트레이터가 정리했고 자료 계약 PR에서 문서로 확정한다고 적었다. 그래서 이 기록이 ①을 보완한다. 병합된 1720 기록은 고치지 않는다 |
| 이유와 근거 | PR #18 검토 2회차에서 평가 방법론 검토자(막는 지적 1)와 보안 검토자(막는 지적 1, 권고 2·3)가 같은 구조 문제를 따로 짚었다 `[사실: PR #18 검토 표]`. 좁게 읽으면 세 가지가 부딪친다. 자료 계약 §8.2는 봉인 묶음의 실행 쪽 기록을 이미 `outputs/sealed/` 아래에 둔다. 봉인 묶음의 `<run_dir>`(채점기에 넘기는 실행 폴더)가 `outputs/sealed/{실행명}/`이라 실행 조건 입력 파일도 그 안에 있어야 한다. 샌드박스 밖 봉인 관련 출력이 `outputs/` 여기저기에 생기면, 에이전트가 내용을 열지 않고 대상 폴더를 알아볼 방법이 없다 |
| 검토한 대안 | 좁은 읽기 유지: 봉인 묶음의 `<run_dir>`를 `outputs/sealed/` 밖으로 다시 정의하고, 모든 관련 폴더 이름을 봉인 사건에 기록하는 장치를 더하는 안이다. 장치가 늘고, 기록 하나가 빠지면 곧 노출로 이어진다. 그래서 버렸다. N10 예외를 늘려 채점 전에 봉인 출력을 읽는 안: 결정 기록 1720 ⑤를 바꾸는 일이라 사용자 승인이 필요하다. 그래서 버렸다 |
