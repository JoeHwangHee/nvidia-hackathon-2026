용어

- HTTP 429: 요청 한도를 넘었을 때 제공자가 돌려주는 응답 코드("Too Many Requests", 호출 한도 초과).
- 재전송: 한 실행 안에서 같은 요청을 다시 보내는 것(단위 I7). 재실행: 묶음 실행이 첫 실행을 모두 마친 뒤 인프라 실패로 끝난 (사례, 모드)를 한 번 더 돌리는 것(룰북 B5, 단위 E1).
- 지수 대기(exponential backoff): 재전송 회차마다 대기를 기준값 × 인자^회차로 늘리는 방식.

## 까닭

- 사용자 결정 1552: 429도 5xx처럼 요청당 최대 3회 다시 보내고, 대기를 5·10·20초로 늘리고(5xx도 같게), 묶음 끝 재실행 대상에 429를 넣는다.
- `real_dev`(실자료 개발 묶음) 확인 실측(2026-09-25 15:28~15:36, 결정 1552 배경): `full` 모드 5건 가운데 3건이 HTTP 429로 `FAILED`(`PROVIDER_HTTP_4XX`)였다. 다른 호출이 없는 상태에서 작은 요청 5번 가운데 2번이 HTTP 503이었다 `[사실: 결정 1552 기록]`. 429는 제공자 쪽 처리 용량 문제로 보인다 `[추론, 결정 1552]`.

## 결정 내용

① **단위 I7 재전송(`src/tradesentry/workflow/model_client.py`)**
- HTTP 429를 5xx와 같은 재전송 고리로 다룬다. 5xx와 429를 합쳐 한 요청의 재전송 횟수를 센다(설정 `retry.max_5xx_retries` 3회). 키 이름은 바꾸지 않고, 429도 이 한도를 쓴다고 머리 주석과 `configs/model/README.md`에 적었다.
- 대기는 `backoff_base_ms` × `backoff_factor`^회차다. 한도를 다 쓰면 마지막 응답의 상태로 코드를 가른다(5xx면 `PROVIDER_HTTP_5XX`, 429면 `PROVIDER_HTTP_4XX`). detail은 둘 다 "HTTP {상태}(재전송 N회 뒤)"다.
- trace `model_error`의 `retrying`·`backoff_ms`는 5xx와 같다. 대기가 deadline을 넘으면 `DEADLINE`, 재전송 전에 모델 요청 10회에 닿으면 `BUDGET_MODEL_REQUESTS`(5xx 규칙 그대로).
- 다른 4xx(400·401·403·404·422 등)와 정책 프록시 거부(CONNECT 403·407, L7 403 `policy_denied`)는 지금처럼 재전송하지 않고 곧바로 멈춘다.

② **모델 설정 `model-1.4`(`configs/model/model.json`)** — `retry.backoff_base_ms` 1000 → 5000(인자 2 그대로, 5·10·20초). 요청 본문과 지침 글은 그대로다. 대기값은 조정값이다.

③ **단위 L3 재실행 대상(`src/tradesentry/runlog/cause_codes.py`)**
- `infra_rerun_eligible`은 `PROVIDER_HTTP_5XX`·`PROVIDER_CONNECTION`에 더해, `PROVIDER_HTTP_4XX` 가운데 detail이 `HTTP 429`로 시작하고 바로 뒤에 숫자가 없는 항목(정규식 `HTTP 429(?!\d)`, 맨 앞 일치)도 대상으로 본다. 가르는 함수는 `rate_limited_entry` 하나다.
- `run`은 http_status 실패의 probe에 I7과 같은 모양의 detail("HTTP {상태}")을 붙여, 429면 `infra_rerun`이 참이다.

④ **단위 E1·E3** — E3(추출 명령)는 원래 `infra_rerun_eligible` 하나로만 가른다(코드 변경 없음). E1(묶음 실행)의 재실행도 같은 함수를 쓴다. E1의 속도 조절(429 뒤 120초 쉼)이 따로 두던 정규식은 지우고 L3 `rate_limited_entry`를 쓴다. 재실행 줄도 속도 조절을 받는다.

## 시험

- I7: 429 뒤 성공, 429 네 번이면 `PROVIDER_HTTP_4XX`·"HTTP 429(재전송 3회 뒤)"·재실행 대상, 500·429 섞임이 같은 횟수(마지막 상태로 코드), 대기 5000·10000·20000, 400·403·404 재전송 없음, 429의 deadline·모델 요청 한도. 골든 기대값의 `backoff_ms`를 1000·2000에서 5000·10000으로 고쳤다(대기 기준값 변경).
- L3: 429 detail 대상, 400·401·403·404·422·`HTTP 4290`·정책 거부 비대상, 5xx·연결 그대로, `run`의 429 `infra_rerun` 참.
- E1: 429 줄은 재실행, 400·다른 4xx 줄은 재실행 안 함. 속도 조절 시험의 기대값을 고쳤다(429 줄이 이제 재실행 대상이라 줄 5개·재실행 1회, 재실행도 쉼을 받음).
- E3: 재실행 대상 목록에 429 줄만 든다.
- 모델 설정: `config_version` `model-1.4`, `retry` 세 값.
