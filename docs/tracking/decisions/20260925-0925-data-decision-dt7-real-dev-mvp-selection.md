# DT7 ① `real_dev` MVP 실행 사례를 고르는 방법(목록을 보기 전에 고정)

로드맵 DT7 ①(`real_dev` 경보·사례 목록과 MVP 실행용 사례 고르기)에서 사례를 고르는 방법을 경보 목록을 보기 전에 적는다. 경보 목록과 고른 사례는 `tradesentry detect`를 돌린 뒤 이 기록에 더한다(아래 "목록" 절).

용어

- `real_dev`: 실자료 품목×상대국 계열 64개 가운데 개발에 쓰는 21개(분할 기록 `data/reference/real_split_kcs_202201_202412_v2.json`, 결정 기록 `20260924-2340-dt4-real-split-and-sample-seed.md`). 공개 개발 묶음이다.
- 경보 목록: `tradesentry detect --snapshot kcs_202201_202412_v2 --policy policy_v1`의 출력 `outputs/detect-{시각}/policy_case_build-{시각}.json`의 `cases` 항목(사례) 전체. `data_quality` 항목(최소 기준 미달 등으로 평가하지 않은 신호)은 사례가 아니어서 들지 않는다.
- 순위 값: 사례마다 계산하는 sha256(내용 지문) 16진수 글자열. 고르는 순서를 사람이 정하지 않게 하려고 쓴다.
- 층화: 판정 상태나 신호 종류별로 몫을 나눠 뽑는 일. 여기서는 하지 않는다.

## 고르는 방법

① **모집단**: 경보 목록의 사례 전체. 판정 상태·신호 종류(단가·점유율)와 관계없이 모두 넣는다. 층화하지 않는다.

② **순위 값**: 사례마다 글자열 `real_dev-mvp-20260925` + `:` + `case_id`(사례 ID, 자료 계약 §4.5)를 UTF-8 바이트로 바꿔 sha256을 구하고 16진수 소문자 64자로 적는다. 파이썬으로는 `hashlib.sha256(("real_dev-mvp-20260925" + ":" + case_id).encode("utf-8")).hexdigest()`다. 접두어는 비밀이 아니다(`real_dev`는 공개 개발 묶음이다).

③ **고르기**: 순위 값 오름차순으로 줄 세워 앞 20건을 고른다. 사례가 20건 이하면 모두 고른다. 순위 값이 같은 두 사례는 `case_id`가 다르면 생기지 않는다고 보고 따로 규칙을 두지 않는다 `[추론: sha256 충돌]`.

④ **한 번만**: 고른 뒤 결과(판정·채점)를 보고 다시 고르지 않는다. 탐지 코드나 정책이 바뀌어 경보 목록이 달라지면 같은 방법으로 다시 고르고, 새 목록과 그때의 탐지 코드 커밋을 이 기록 뒤에 새 기록으로 남긴다.

⑤ **기록할 것**: `detect`를 돌린 탐지 코드의 커밋(`git rev-parse HEAD`, AS1 결정 기록 `20260925-0901-model-decision-as1-real-dev.md` ⑤), 스냅샷 `normalized_sha256`(`20260925-0920-data-decision-dt7-final-build.md`), 정책 `policy_v1`, 경보 목록 전체의 `case_id`와 사례 수, DT4 ② 통계의 예상(사례 221건)과의 대조, 고른 20건의 `case_id`와 순위 값.
