| 분할 방법 | 출력 표시 `method` = `hs6_stratified_sha256_rank`. ① 키마다 문자열 `{seed}:{snapshot_id}:{hs6}:{partner}`(예: `20260924:kcs_202201_202412_v2:850450:CN`)의 UTF-8 바이트 sha256(16진수 소문자)을 순위 값으로 쓴다. 파이썬 `random` 모듈을 쓰지 않아 `shasum -a 256`으로도 다시 계산된다 ② HS6(품목 코드 6자리)가 같은 키끼리 층(무리)으로 묶고, 최대 나머지 방식(비례 몫의 정수 부분을 먼저 주고 남은 자리를 나머지가 큰 층부터 주는 배분)으로 층마다 `real_dev` 자리를 준다. 층마다 몫 5, 나머지는 모두 같아 남은 1자리는 다음 차례 키의 순위 값이 가장 작은 층(`850490`)에 갔다 ③ 층 안에서 순위 값 오름차순으로 앞에서부터 자리 수만큼 `real_dev`로 둔다 |

| 배정에서 드러난 사실 | 상대국 `DE`, `FR`, `TW`, `VN`은 네 시계열이 모두 `real_sealed`다. 층화를 HS6로만 하기로 분할 전에 정했고 다시 나누지 않는다. 그래서 이 네 나라를 대상국으로 하는 경보는 개발 실행과 기준값 조정 통계에 나오지 않는다. 비교국 조회는 두 묶음 모두 스냅샷 전체를 읽으므로(병렬 개발 규칙 §7.2의 5) 이 나라들도 비교 자료로는 쓰인다. HS6별 `real_dev` 자리가 5·5·5·6이면 한 나라의 네 시계열이 모두 `real_sealed`일 확률은 (11/16)³ × (10/16) ≈ 0.203이고, 16개국 가운데 그런 나라의 기대 수는 약 3.25개다 `[추론: 계산]` |
| 실행 증거 | 코드 `eval/datagen/split.py`(단위 V5, sha256 `ee35f0fb95ed9eac8d2046701970e509807b911baf6ff8e77653d492606105bc`). 입력 `tests/units/V5/input.json`(sha256 `3fd15807d48d3c64a96e30a303232f79d25c8f4bf413e47b9bbb0875a28a935e`). 명령 `env -u NVIDIA_API_KEY -u DATA_GO_KR_SERVICE_KEY -u TRADESENTRY_SEALED_DIR uv run --locked python -m tradesentry.units V5 --in tests/units/V5/input.json`, 종료 코드 0, 실행명 `datagen_split-260924233410`. 출력 파일(커밋 안 함)의 sha256 `fe9797d2ef57f97fa2de5be6e8924b6615915d92bab0a20899f5e468407db2d0`은 골든 기대 출력 `tests/units/V5/expected.json`과 같다. 그래서 골든 시험이 이 배정을 고정하고, 코드가 바뀌어 배정이 달라지면 실패한다. 오케스트레이터가 위 방법 설명만으로 따로 다시 계산해 같은 21개를 얻었다 |
