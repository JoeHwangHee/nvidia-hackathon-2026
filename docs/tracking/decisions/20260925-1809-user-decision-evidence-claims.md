# 필수 근거 주장을 코드가 덧붙임

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-09-25(금) 18:09 무렵. 사용자가 채팅으로 답했다("코드가 덧붙이는 방식으로 진행해") |
| 제목 | 보고서가 판정에 필요한 필수 근거(시나리오 명세 `eval/scenarios/SCENARIO_SPEC.md` §5.3 판정 조건표)를 보이지 못하는 문제를 어떻게 다룰지 |
| 배경 | ① V1(MVP 시험) dev20 묶음(`evaluate-260925163949`, 채점 `score-260925175348`)에서 끝까지 돈 실행의 판정 상태는 거의 맞았다(`checklist` 20/20, `agent` 17/17, `full` 7/8). 그러나 채점기의 필수 근거 검사(`required_evidence_ok`)는 `full` 8건 전부, `agent` 17건 가운데 15건, `checklist` 20건 가운데 8건이 떨어졌다. 숫자·출처 검사는 모두 통과했다 ② 오케스트레이터가 채점기의 판정 함수로 빠진 근거를 셌다. 모델 모드에서 자주 빠진 것은 `parent_child_match_V_and_Q`·`partner_comparison_done`·`weight_share_decomposition`·`country_and_world_change_shown`·`per_child_unit_value_stable`이었고, `checklist`는 `country_and_world_change_shown` 5건이 가장 많았다. 모델은 주장을 한두 개(자기 계열 변화율)만 넣는다 ③ 필수 근거는 holdout40 보조 지표(근거 충족 처리정확도, 등급 C)에 쓰이고, 대표 지표(실자료 보고서 단위 오류율)에는 쓰이지 않는다(실자료는 `required_evidence_ok`가 null) |
| 질문 | 오케스트레이터가 선택지 셋("코드가 덧붙임 (권장)" / "지침에 안내 추가" / "그대로")을 올렸고, 사용자가 설명을 청해 오케스트레이터가 뜻·영향·비용을 설명했다(필수 근거의 예, 코드가 덧붙이는 일, holdout40 보조 지표는 오르고 대표 지표는 더한 주장이 맞는 한 그대로, 모든 모드 같은 규칙, "모델이 필수 근거를 스스로 챙기는가"는 더 이상 재지 않음, 2시간쯤과 dev20 재실행) |
| 답(글자 그대로) | "코드가 덧붙이는 방식으로 진행해" |
| 결정 | ① 보고서를 만들 때(초안·검증·최종 모두) 코드가, 보고서의 신호별 판정에 필요한 필수 근거 코드마다 그 근거를 보여 주는 주장이 없으면 이미 받은 근거의 검증된 지표·자료 상태에서 골라 덧붙인다. 채울지의 기준은 시나리오 명세 `eval/scenarios/SCENARIO_SPEC.md` §5.3 판정 조건표다 ② 모델(또는 `checklist` 규칙)이 쓴 판정·주장·설명·가설은 바꾸거나 지우지 않는다. 같은 주장이 이미 있으면 덧붙이지 않는다. 받은 근거에 없으면 덧붙이지 않는다(도구를 새로 부르지 않고 값을 지어내지 않는다) ③ 모든 모드(`checklist`·`agent`·`full`·`freeform`)에 같은 규칙이다 ④ 덧붙인 주장은 실행 추적(trace)에 남기고, 결과 요약에 모드별로 공개한다 ⑤ 병합 뒤 dev20과 `real_dev`를 다시 돌린다 |
| 조건 | holdout40·`real_sealed`의 결과를 보지 않은 상태에서 정했다. 조정 근거는 dev20(공개 합성 개발 자료) 결과다. 이 규칙이 생기면 근거 충족 처리정확도는 "모델이 필수 근거를 스스로 챙기는가"가 아니라 "시스템이 보고서에 필수 근거를 보이는가"를 잰다. 제출서와 결과 요약에 이 점을 밝힌다 |
