# MT3 검증기·보고서의 세부 결정(소유 트랙 M)

로드맵 MT3(검증기·보고서, 단위 R1~R4)을 구현하며 소유 트랙(M)이 정한 세부와 해석을 남긴다. 자료 계약의 값·키·상태값은 바꾸지 않았다. 구현은 PR #25의 `src/tradesentry/reports/`와 `src/tradesentry/validator/`에 있다. 항목마다 [확정]·[잠정]을 붙였다. [잠정] 항목은 적힌 조건(다른 작업의 확인, 룰북 동결)이 채워지면 새 기록으로 확정하거나 바꾼다.

용어

- 단위 R1~R4: 네 단위다(`docs/plan/UNITS.md` §3).
  - R1 typed claim 채우기(`reports_claims`)
  - R2 한국어 보고서 틀(`reports_render_ko`)
  - R3 검증 규칙(`validator_validate`)
  - R4 차단 판정(`validator_gate`)
- 사유(finding): 검증기가 보고서에서 찾은 문제 하나. 보고서의 `validator_findings`에 담는다.
- 스키마 검사와 검증기 검사
  - 스키마 검사: 보고서의 형식·자료형과 발동 신호별 주장 요건을 본다. 모든 모드에서 막는다.
  - 검증기 검사: 숫자·단위·원본 행·출처·스냅샷·허용 상태·금지 문구·산문을 본다. `freeform`에서는 막지 않고 기록만 한다.
  - 이 구분은 자료 계약 §3.3의 `INVALID` 정의를 따른다.
- C형: 부모 HS6 행은 있는데 HS10 하위 자료 요청만 실패한 경우. 합성 사례 oracle C가 이 경우다(자료 계약 §2.3.2 행 규칙 4).
- 상태 행: 값 없이 관측 상태만 적은 행. 수집기가 쓰는 `UNRESOLVED_ZERO`·`REQUEST_FAILED`와, 스냅샷 빌드가 만드는 `NOT_COLLECTED`가 있다.
- D17: 원 작업을 병합한 뒤 같은 작업 ID로 내는 "F1 전" 보완 PR. 구현 계획 승인(2026-09-24(목) 23:09) 때의 사용자 결정이다.
