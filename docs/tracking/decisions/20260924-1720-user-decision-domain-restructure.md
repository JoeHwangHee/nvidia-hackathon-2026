# 도메인 재편 A안과 이름·출력 규칙 사용자 결정

| 항목 | 내용 |
|---|---|

| 제목 | 도메인 재편 A안(패키지 재배치)과 이름·출력 규칙 |
| 결정 | ① 구현은 도메인(책임 하나와 소유자 하나를 가진 기능 묶음)별 앱, 곧 혼자 실행하고 시험할 수 있는 단위로 따로 만든 뒤 조립하는 방식을 기초로 한다. 이를 위해 도메인을 최소 단위로 재분배하고, 조립할 때 버릴 것과 합칠 것을 확인한다. 배치는 A안이다: 계획 모듈 이름을 패키지로 바꾸고(`metrics.py` → `metrics/` 등, import 경로는 그대로), 새 이름 다섯 개(`contract`, `snapshot`, `runlog`, `units`, `eval/datagen`)를 둔다. ② 이름·출력 규칙은 아래 "사용자 원문"과 "확인 답"대로 한다 |
| 사용자 원문 | "1. 이름이나 규칙은 명확하게. 2. 각 도메인별 출력물은 ./outputs/ 에 쌓는다 3. 도메인명엔 버전을 시간대별로 명시하기위해 {도메인명}-{yymmddhhmmss].{확장자명} 사용". 원문의 `]`는 `}`의 오타로 읽었다 |
| 확인 답 | 사용자가 선택지 질문으로 답했다. **출력 구조**: 실행별 폴더다. 실행 하나가 `outputs/{실행명}-{시각}/` 폴더 하나이고, 그 안에 `{도메인명}-{시각}.{확장자}` 파일을 둔다. **커밋 증거물**(평가 결과 묶음·자기채점·OpenShell 증거): 같은 이름 규칙을 쓴다. 룰북과 평가 스킬의 파일 이름 규칙은 `RB-1`(평가 룰북의 첫 동결 버전) 동결 전에 고친다. **봉인 묶음 실행 출력**: `outputs/sealed/`에 두고, 정답 대조 채점이 끝나기 전에는 에이전트가 열지 않는다. **세부**: 시각은 KST 24시간 12자리다. 도메인명은 `{패키지}_{단위}`이고 단위 표에서 한 번 정하면 조립 때 합쳐도 바꾸지 않는다. 쓰려는 이름이 이미 있으면 덮어쓰지 않고 그 실행을 실패로 끝낸다. `outputs/`는 커밋하지 않는다 |
| 이유와 근거 | 사용자 결정이다. 한 도메인 안에서도 단위 파일별로 동시에 작업하고, 조립 때 버릴 것과 합칠 것을 명시적으로 가리려는 것이다. 근거 자료는 오케스트레이터(작업을 나누고 PR(GitHub 변경 요청)을 병합하는 주관 에이전트)가 같은 날 만든 도메인 재편 제안서다. 제안서에는 최소 단위 64개와 조립 계획이 있다 |
| 검토한 대안 | B안(경로 유지, 단위는 파일 안 함수): 조건 1을 약하게 채운다. C안(단위별 설치 패키지): 문서와 일정 비용이 크다. 출력 완전 평면안: 채점기 명령과 룰북·평가 스킬을 다시 써야 한다. 커밋 증거물의 룰북 파일 이름 유지안: 오케스트레이터가 권했지만, 사용자는 같은 이름 규칙을 골랐다. 봉인 출력을 저장소 밖 봉인 폴더에 두는 안 |
