# 최종 스냅샷 빌드 파일 위치와 g0 해석 사용자 결정

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-09-24(목) 22:12(기록 시각). 사용자의 답은 같은 날 21:51에 채팅의 선택지 질문으로 받았다 |
| 제목 | 최종 스냅샷 빌드는 동결 폴더에 새 이름 `snapshot_build.sqlite`로 두고, `g0`는 대상국을 뺀 15개국 중 상위 5개국 |
| 결정 | ① 최종 스냅샷 빌드(단위 S2 `snapshot_build`가 raw 응답과 manifest(수집 요청 목록)로 만드는 정규화 SQLite. 승인된 무거래 확정 승격을 적용한 파생 저장소)의 정본 파일은 `data/snapshots/{snapshot_id}/snapshot_build.sqlite`다. v2면 `data/snapshots/kcs_202201_202412_v2/snapshot_build.sqlite`다. 동결 스냅샷 폴더에 새 이름으로 더하고, 기존 파일(수집기의 `snapshot.sqlite`, `snapshot_hash.json`, `raw/`, manifest)은 바꾸지 않는다. 빌드는 `outputs/snapshot_build-{시각}/`에서 만들고, 동결·승인 뒤 자료 계약 §10.3 N12대로 옮긴다. ② `g0`(MVP 시험용 고정 비교국 목록)는 품목(HS6)마다 대상국을 뺀 15개국 가운데 2023년 수입금액 상위 5개국이다. 자료 계약 §2.3.6이 채택해 둔 해석이다 |
| 사용자에게 보인 질문과 답 | 질문 1: "최종 스냅샷 빌드(수집한 원자료로 만드는 정규화 SQLite 파일)를 어디에 둘까요? v2 폴더에는 수집기가 만든 snapshot.sqlite가 이미 있어서 같은 이름으로는 쓸 수 없습니다. 내일 첫 빌드 전에 정해야 합니다." 답: "v2 폴더에 새 이름". 질문 2: "g0(MVP 시험용 고정 비교국 목록)을 어떻게 뽑을까요? 품목(HS6)마다 2023년 수입금액 순으로 5개국을 고릅니다." 답: "대상국 뺀 15개국 중 5개" `[사실: 2026-09-24(목) 채팅]` |
| 오케스트레이터가 붙이는 조건 | S0 검토(보안·NVIDIA 스택)의 권고다. 옮기기는 이미 있으면 실패하는 방식(`os.link` 뒤 원본 지우기나 `"xb"` 모드 복사)으로 하고, 같은 이름을 조용히 덮는 `os.rename`·`shutil.move`는 쓰지 않는다. 자료 접근층(`dal/`)은 이 파일을 읽기 전용 URI(`mode=ro`)로 연다. `normalized_sha256`(정규화한 스냅샷 내용의 해시)은 `snapshot_hash.json`을 고치지 않고 새 파일(예: 같은 폴더의 `snapshot_build.json`)이나 결정 기록에 둔다. 동결 전에 WAL(미리 쓰기 로그) 모드가 아닌 상태로 정리한다. `.gitignore`에 `data/snapshots/*/*.sqlite`와 `data/snapshots/*/*.sqlite-*`를 더해 커밋되지 않게 한다(S0). upload는 `.gitignore`를 따르므로 샌드박스에는 이 파일을 이름을 지정해 올리거나 이미지에 넣는다(로드맵 MT5) |
| 이유와 근거 | ① 수집기의 `snapshot.sqlite`와 이름이 달라 동결 v1·v2의 기존 파일을 바꾸지 않는다(`CLAUDE.md` 절대 규칙 2). 자료 계약 N12는 동결 스냅샷 폴더를 정본 자료를 옮겨 둘 자리로 정한다(2026-09-24(목) 사용자 확인, PR #18). 계획 경로 표의 "동결 스냅샷" 행 안의 파일이라 표를 바꾸지 않는다. 재료 준비에서 이 이름은 로드맵 DT7 ②보다 이른 v2 첫 빌드 전에 필요하다는 점이 드러났다. ② 비교국이 늘 5개라 사례끼리 비교 조건이 같다 |
