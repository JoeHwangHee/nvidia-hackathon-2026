## 결정 내용

① **룰북 문장(`docs/eval/RULEBOOK.md` B3-2 "빼는 표현" EX-2 행)** — 기존 정의 뒤에 `[DESIGN: 2026-09-26(토) 사용자 결정 ②, 결정 기록 20260926-0810-…]` 태그로 확장을 덧붙였다. 확장 집합은 셋이다: ① `HSK`와 함께 쓴 숫자, ② 분류 자릿수 표기 "N단위"·"N자리"("N자릿수"는 글자(릿)가 달라 집합에 없다), ③ 품목 규격의 전기 단위 `VA`(볼트암페어)·`kVA`·`MVA`·`kV`(킬로볼트)·`kW`(킬로와트)가 바로 뒤에 붙은 숫자. 글자 규칙은 구현과 같게 정확히 적었다(Claude 독립 검토 1회차 지적 1): 접두 `k`만 대소문자 무관(`K` 허용), `VA`·`V`·`W`·`M`은 대문자만, `HS`·`HSK`는 대문자만, 숫자와 단위 사이 공백 0개 이상, 숫자는 앞자리가 있는 정수·소수(`.5kVA`는 집합 밖), 단위 뒤에 라틴 글자가 이어지면 집합 밖. 홑 글자 단위(`V`·`A`)와 `kVAr`·`kWh`는 집합에 없다. 예에 "HSK 8504501010", "HSK  10", "10단위", "10 자리", "16kVA", "16 KVA", "1.5MVA", "220 kV", "10kW"를 더했다. 경계 사례 표에 23(HSK·단위·자리 통과), 24(16kVA를 빼고 40%·하락만 검사), 25(집합 밖: 10 V·5 A·16kg·10개국·10자릿수·16kVAr·10kWh는 채점)를 더했다. DOCS13이 표 아래에 둔 "EX-2는 … 확장 예정이다" 문장은 넣은 상태를 적는 문장으로 바꿨다. §0.1 버전 표기는 `RB-1`(동결 전 초안) 그대로다(확인). 다른 절은 건드리지 않았다.

② **채점기 정규식(`eval/scorer/prose.py` `EXCLUDE_PATTERNS`의 EX-2 구간)** `[사실]`

| 집합 | 채점기(이 PR) | 검증기(읽기만, `EXCLUDE_RES`) |
|---|---|---|
| HS·HSK 숫자 | `HSK?\s*+(?:코드\s*+)?\d[\d.\-]*`(기존 HS 패턴에 `K?`를 더함) | `(?<![A-Za-z])[Hh][Ss][Kk]\s?\d+`(HS 패턴과 별도) |
| N단위·N자리 | `(?<!\d)\d++\s*+(?:단위\|자리)` | `\d+\s?(?:단위\|자리)` |
| 전기 단위 | `(?<![\d.])\d++(?:\.\d++)?\s*+(?:[kKM]?VA\|[kK]V\|[kK]W)(?![A-Za-z])` | `\d+(?:\.\d+)?\s?(?:[kKM]?VA\|[kK]V\|[kK]W)(?![A-Za-z])` |

- 채점기 정규식은 채점기의 선형 시간 규약(소유 한정자 `\s*+`·`\d++`, 앞 글자 고정)을 따라 썼다. 룰북 문장 기준으로 채점기는 문장과 같고, 검증기는 세 곳(⑥)이 달라 `model/MT3-prose-alignment` 반영 뒤 같아진다.
- 대조: 확장 예문 14개("16kVA", "1.5MVA", "220 kV", "10kW", "500VA", "HSK 10", "10단위", "6자리" → 둘 다 뺌 / "10자릿수", "16kVAr", "10kWh", "10 V", "5 A", "16kg" → 둘 다 안 뺌)를 두 구현의 빼는 정규식에 넣어 결과가 모두 같았다(`uv run --locked python`, 종료 코드 0).
- 채점기는 `tradesentry`를 import하지 않는다(경계 시험 `tests/test_boundaries.py` 그대로 통과).

③ **산문 패턴 목록 지문이 바뀐다** `[사실]` — `pattern_list_sha256()`이 `9184cbe2695231a2b4388c1418c0fa116e9bdff07acfe634bd30a61448017595`에서 `ce8f62765b3607127c24ed053b0e141bc47166275df58eacd7e191d6616eaec4`로 바뀐다. 이 값은 채점기 출력 `meta.prose_patterns_sha256`과 결과 요약 0절에 적히므로, 이 PR 병합 뒤 채점한 묶음은 이전 묶음(V1 4·5차 커밋 증거)과 지문이 다르다. `RB-1` 동결 때 동결 커밋으로 식별하는 값이 이 새 지문이다.

⑤ **영향 측정(읽기만, 보고용)** `[사실]` — 커밋된 보고서 원문 `artifacts/eval/score-*/run_case-*/reports_render_ko-*.json` 4개 묶음(`score-260925234445` 58건: checklist 20·full 18·agent 20 / `score-260926003407` 35건: full 17·freeform 18 / `score-260926020005` 58건: checklist 20·agent 19·full 19 / `score-260926034242` 21건: full 9·freeform 12, 합계 172건)의 산문을 옛 채점기(`origin/main`의 `prose.py`)와 새 채점기로 채점해 (필드·표현·판정) 목록을 비교했다. 결과가 바뀐 보고서는 **모든 묶음·모든 모드에서 0건**이다. 스냅샷 SQLite 대신 보고서의 주장(`hs6`·`@HS10`)과 사례 ID에서 모은 HS 코드 집합을 썼으므로 절대 판정 수는 실제 채점과 다르지만, 옛·새 채점기에 같은 집합을 넣었으므로 차이 0건은 확장 패턴만의 영향이다.

⑥ **한계와 검증기 어긋남**(Claude 독립 검토 1회차 지적 2) — 검증기(`origin/main`의 `src/tradesentry/validator/validate.py` 917행 `[Hh][Ss][Kk]\s?\d+`, 916~918행 근처 전기 단위·단위·자리)와 채점기는 룰북 문장 기준으로 세 곳이 어긋난다. (a) 소문자 `hsk 10`: 검증기만 뺀다(채점기·룰북은 대문자만. 채점기 EX-3 식별자 패턴은 `hsk`만 잡아 10이 남는다). (b) 숫자와 단위 사이 공백 2개 이상(`HSK  10`, `10  단위`, `16  kVA`): 채점기만 뺀다(`\s*+` 대 `\s?`). (c) 앞자리 없는 소수 `.5kVA`: 검증기만 뺀다(`\d+`가 `5kVA`를 잡는다. 채점기는 `(?<![\d.])`로 막아 5가 PT-5로 남는다). 검증기를 채점기(정본 문장)에 맞추는 수정은 `model/MT3-prose-alignment` PR이 맡으며, 그 PR 병합이 두 구현 일치의 조건이다. 그 밖에 "N자릿수"는 두 구현 모두 빼지 않는다(룰북에 적었다).
