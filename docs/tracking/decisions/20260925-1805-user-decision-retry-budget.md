# 재전송을 모델 요청 한도에서 뺌

| 항목 | 내용 |
|---|---|

| 제목 | HTTP 5xx·429 재전송을 사례당 모델 요청 한도(10회)에 셀지 |
| 배경 | ① V1(MVP 시험) dev20 묶음(`evaluate-260925163949`, main 690f3eb, 16:39~17:53)에서 NIM(NVIDIA 클라우드 추론 API)의 HTTP 429·5xx가 계속 났다. 요청당 3회 재전송(대기 5·10·20초, 결정 기록 `20260925-1552-user-decision-429-retry.md`)과 묶음 끝 재실행 12건 뒤에도 `full` 12건, `agent` 3건이 끝까지 돌지 못했다 ② 그 가운데 8건(`full` 6, `agent` 2)은 원인이 `BUDGET_MODEL_REQUESTS`("HTTP 429 재전송 전에 모델 요청 한도에 닿았다")였다. 재전송도 모델 요청 10회에 세는 규칙 때문에, 제공자 쪽 오류가 모델 요청 한도 초과(`BUDGET_EXCEEDED`)로 바뀌었다. 이 상태는 인프라 실패 재실행 대상도 아니다 ③ 대표 지표(보고서 단위 오류율, 룰북 B3)는 `COMPLETED`가 아닌 실행을 모두 실패로 센다. 뒤이은 `real_dev` 묶음(`evaluate-260925175348`)도 처음 세 건 가운데 두 건이 같은 식으로 끝났다 |

| 결정 | ① 사례당 모델 요청 한도 10회는 재전송을 빼고 센다. 재전송(5xx·429, 요청당 최대 3회, 대기 5·10·20초)은 요청당 3회와 사례당 wall time 300초로만 묶는다 ② 실행 결과 기록의 `model_requests`도 같은 뜻(재전송을 뺀 모델 요청 수)으로 적는다. 재전송은 실행 추적(trace)의 `model_error` 사건(재전송 여부·대기)에 남는다 ③ 모든 모드에 같은 규칙이다 ④ 진행 중이던 `real_dev` 묶음(`evaluate-260925175348`, 9줄에서 멈춤)은 중단했고, 고친 뒤 다시 돌린다. 중단한 묶음은 채점하지 않는다 |
