용어

- 배경 하위 프로세스: 화면 스크립트와 따로 도는 자식 프로세스. Streamlit은 위젯을 누를 때마다 스크립트를 처음부터 다시 돌리므로, 조사를 스크립트 안에서 기다리면(동기 실행) 다른 버튼을 누르는 순간 끊긴다. 그래서 조사를 자식 프로세스로 띄우고 화면은 그 상태만 읽는다.
- 조각(`st.fragment`): 페이지 전체가 아니라 함수 하나만 다시 그리는 Streamlit 단위. `run_every`를 주면 그 주기로 스스로 다시 그린다.
- 로딩 창: 조사하는 동안 화면 전체를 흐리게 덮는 가운데 창(디자인 `Loading2`).
- 조사 중 표시: 로딩 창을 닫은 뒤 모든 페이지 오른쪽 아래에 고정되는 가로로 긴 작은 버튼(디자인 `Main2_running`). 누르면 로딩 창이 다시 열린다.
- 내부 식별자: 사람이 아니라 프로그램이 쓰는 이름. 여기서는 HS6(6자리 품목분류 코드) 코드, 스냅샷 ID, 실행 폴더 이름, 정책 이름, 해시, 영문 상태 코드(`MAINTAIN` 등)를 말한다.

## 사용자 피드백 요지

- 의미 없는 요소를 없애고 담당자에게 필요한 데이터만 보인다.
- 요약 카드 영역 · 조회 조건(정렬·필터) 영역 · 데이터 영역을 시각적으로 나눈다.
- 열 내용에 내부 변수명·식별자(HS6 코드, 스냅샷 ID, 실행 폴더 이름, 정책 이름, 해시, 상태 코드)를 보이지 않는다.
- 조사 중에는 전체 화면을 덮는 로딩을 보인다. "목록으로"를 누르면 조사는 계속되고, 모든 화면 오른쪽 아래에 작은 "조사 중" 표시가 뜨며 누르면 로딩 창이 다시 열린다.
- 사용자가 직접 지정한 세부: ① 경보 목록 3번째 열 이름 "변화내용"(EN "Change details") ② 사례 검토의 "다음 업무 제안" 카드는 아래 오른쪽 열과 같은 폭·같은 끝선 ③ "결정 저장" 버튼은 위 입력칸과 같은 폭, 안내 문구는 버튼 아래 작게 ④ "다시 조사" 버튼은 오른쪽 정렬 ⑤ 로딩 창 버튼 "목록으로"(EN "Back to list") ⑥ 목록으로 돌아가면 모든 화면 공통 오른쪽 아래 조사 중 표시, 누르면 로딩 창 재표시.

## 결정 내용

① **진입 스크립트와 머리 띠(`src/tradesentry/ui/ui_app.py`)** — 사이드바 메뉴를 쓰지 않는다(`st.navigation(..., position="hidden")`). 모든 페이지 위에 머리 띠(브랜드 "TradeSentry" · 부제 "수입통계 경보 검토" · 페이지 링크 3개 "경보 목록/사례 검토/결정 기록"(EN "Alerts/Case review/Decision", `st.page_link`) · 자료 기간 한 줄 "자료: 관세청 수입통계 2022년 1월 ~ 2024년 12월"(스냅샷 ID 없이, 스냅샷 기간에서 읽음) · 언어 전환 "한국어/EN")를 그린다. 관리자 화면(기존 `app.py`, 페이지 이름 "관리자 화면")은 담당자 페이지 하단의 작은 링크로만 들어가고, 관리자 페이지에도 같은 머리 띠가 있어 돌아올 수 있다. `.streamlit/config.toml`에 `[client] toolbarMode = "viewer"`를 더해 개발자 메뉴를 숨겼다(테마 설정 유지). 페이지 꾸밈은 `screens/style.py`의 CSS 한 벌이고, 위치를 고정할 요소는 key를 준 Streamlit 요소에 붙는 `.st-key-<key>` 클래스로 고른다(streamlit 1.64). 진입 스크립트 위치가 `ui/` 안인 까닭은 UI2 기록 ①과 같다(자료 계약 §10.3 N2).

② **스냅샷 선택 이동** — 담당자 화면에는 스냅샷 선택이 없다. 기본값은 정본 빌드가 있는 실자료(`alerts.default_snapshot`, 지금은 `kcs_202201_202412_v2`). 관리자 페이지일 때만 사이드바 맨 위에 "담당자 화면 자료(스냅샷)" 선택(시험·시연용)을 둔다. 확인용 URL 질의 `?snapshot=<id>`는 `app.list_snapshots`에 있는 값일 때만 받고 세션에 옮겨 둔다(페이지 링크·이동은 질의를 버리므로).

③ **배경 조사(`src/tradesentry/ui/screens/jobs.py`)** — "조사 시작"(경보 목록)과 "다시 조사"(결정 기록)는 `app.build_run_case_args`(재생 파일 규칙은 UI2와 같다: 재생 파일이 있으면 재생, 없고 키가 프로세스 환경에 있으면 실제 NIM, 둘 다 없으면 버튼 잠금) → `subprocess.Popen(app.run_case_command(args), cwd=저장소 루트, env=app.child_env(), stdout/stderr=임시 파일(tempfile, 저장소 밖), start_new_session=True)`로 띄운다. 동기 실행 `app.run_case_once`는 쓰지 않는다. 세션에 조사 하나만(`session_state["ts_job"]`, 프로세스 핸들은 `["ts_proc"]`): 사례 ID, 시작 시각, 실행 전 폴더 목록, 로딩 창 표시 여부, 상태. 도는 동안 다른 "조사 시작"은 잠기고 툴팁 "진행 중인 조사가 끝난 뒤 시작할 수 있습니다"를 보인다. 상태 전이는 순수 함수 `progress.next_status`: 프로세스가 돌면 `running`(제한 시간 = `app.wall_limit_seconds` + `app.RUN_GRACE_S`를 넘기면 `timeout`, 이때 프로세스 묶음에 SIGTERM, 5초 뒤 SIGKILL), 끝나면 실행 결과 기록의 `execution_status`가 `COMPLETED`일 때만 `done`, 그 밖은 `failed`. 실행 폴더는 실행 전후 폴더 차이(끝난 뒤에는 CLI 표준 출력의 폴더를 먼저, `app.output_run_dirs`)로 찾는다. 표준 출력·오류와 종료 코드는 화면에 보이지 않는다(N13: 실패는 평이한 문장만).

④ **진행 단계는 trace에서 읽는다(`src/tradesentry/ui/progress.py`, 순수)** — 새 실행 폴더의 `runlog_trace-{시각}.jsonl`(이벤트마다 한 줄씩 flush)을 읽고, 줄바꿈으로 끝나지 않은 마지막 줄(쓰는 중)과 깨진 줄은 건너뛴다. 5단계와 표지: ① 자료 확인 = `tool_call` `check_comparability` ② 이력·상대국 비교 = `get_history`·`compare_partners` ③ 하위품목 구성 = `decompose_hs` ④ 검수·수정 = `stage_start` `critic` ~ `stage_end` `critic` ⑤ 숫자 대조 = `verify_evidence`·`validator_result` `phase`=`verify`; 끝 = `run_end`. 도달한 가장 뒤 단계가 진행 중이고 그 앞은 완료다(조사 흐름이 비교 도구 순서를 바꿔도 뒤로 가지 않는다). 표지가 없으면 예상 순서대로 첫 단계가 진행 중이다. 마지막 모델 이벤트가 `model_error`면 "응답이 늦어 다시 요청하는 중입니다"를 작게 보인다. 진행 막대는 끝난 단계 비율이다.

⑤ **로딩 창과 조사 중 표시** — 진입 스크립트가 페이지를 그리기 전에 상태를 읽고(`jobs.route`: 로딩 창이 떠 있는 채로 `done`이면 사례 검토로 옮길 표시를 남긴다 → 본 스크립트의 `st.switch_page`, 새 실행을 선택한 상태), 페이지 본문 뒤에 `jobs.render_layer`로 그린다. 도는 동안은 `st.fragment(run_every=1.0)`으로 그 부분만 1초마다 다시 그린다. 로딩 창은 key를 준 컨테이너(`ts_overlay`·`ts_modal`)를 CSS `position:fixed`로 화면 전체를 덮게 했다(`st.dialog`는 닫기·재표시·주기 갱신을 한꺼번에 다루기 어려워 쓰지 않았다). 창: 사례 이름(평이한 말 "{국가}산 {품목} · {YYYY년 M월} 경보"), 경과 시간 m:ss, 5단계 목록(완료 ✓/진행 중/대기), 진행 막대, "보통 30초에서 90초가 걸립니다. 끝나면 결과 화면이 바로 열립니다.", "목록으로"(누르면 조사는 계속되고 경보 목록으로 이동해 조사 중 표시가 뜬다). 실패하면 같은 창에 실패 문구 + "다시 시도"·"닫기". 조사 중 표시는 key를 준 버튼을 오른쪽 아래(`right:40px; bottom:18px`, 폭 470px)에 고정한 것이다: "● 조사 중 · {사례 이름} · {n}/5단계 · m:ss ›" + 얇은 진행 막대 → 누르면 로딩 창. 끝나면 "✓ 조사 완료 · {사례 이름} · 결과 보기 ›"(누르면 사례 검토), 실패하면 "! 조사 실패 · {사례 이름} · 다시 시도 ›". 표시가 떠 있으면 페이지 아래 여백을 96px로 늘린다. 경보 목록의 그 행은 "조사 중 · m:ss"(1초마다 그 칸만 갱신하는 조각)와 잠긴 "조사 중" 버튼이다. 관리자 페이지(`app.py`)에도 같은 자리에 뜬다.

⑥ **경보 목록(`screens/home.py` + 순수 `listing.py`)** — 요약 카드 띠(연한 배경): "{YYYY년 M월} 요약" + 설명 한 줄, 카드 5개(이번 달 경보 N건(지난달 M건) · 단가가 크게 바뀐 것(오른 것 a · 내린 것 b) · 점유율이 크게 바뀐 것(수입이 끊긴 나라 n, 없으면 늘어난 것/줄어든 것) · 조사 완료 x / N(제안별 건수 · 조사 중 n) · 내 결정을 기다리는 사례 N건(강조 테두리)). 조회 조건 카드(흰 카드): 월(‹ 선택 ›) · 바뀐 것(전체/단가/점유율) · 진행 상태(전체/조사 전/조사 중/조사 완료·결정 대기/결정 완료) · 정렬(변화 큰 순(기본)/품목/상대국/진행 상태) · 찾기(품목 또는 국가 이름). 데이터 표(흰 카드) 6열: 품목(이름만) · 상대국 · 변화내용(윗줄 "kg당 단가 A → B USD", 점유율만 발동이면 점유율이 윗줄이고 비교월 수입이 없으면 "점유율 A% → B% — {M}월에 수입이 없었습니다"; 아랫줄 작게 다른 지표 또는 "단가는 비교할 수 없음") · 변화(▲/▼ 배지: 단가 %, 점유율만이면 %p) · 진행 상태 · 동작. "내 결정 대기" 행은 연한 파랑 배경. 변화 큰 순은 단가 발동 행을 |변화율| 내림차순, 그 뒤 점유율만 발동 행을 |%p| 내림차순. 진행 상태 판정(`listing.row_progress`): 이 세션에서 도는 조사면 "조사 중", 아니면 그 사례의 최신 결정 기록이 있고 `approval.check`가 `VALID`면 "결정 완료 · {결정}", `REVIEW_REQUIRED`면 "재검토 필요", 아니면 최신 실행이 `COMPLETED`면 "조사 완료 · {제안} 제안 / 내 결정 대기", 실패·무효면 "조사 실패", 없으면 "조사 전". "조사 실패"는 조회 조건 "조사 전"에, "재검토 필요"는 "결정 완료"에 묶었다(목업에 두 상태의 필터가 없어서). 지난달 수는 그 달이 경보가 생길 수 있는 첫 달보다 앞이면 "지난달은 비교 자료가 없음"으로 적는다(첫 경보 달에 "지난달 0건"이 오해를 부르지 않게). 결정 기록 색인은 `records.latest_decisions`(사례별 최신 기록 + 유효 상태)로 한 번만 읽는다. 하단: 용어 한 줄 + 오른쪽 작은 "관리자 화면" 링크.

⑦ **사례 검토(`screens/case.py`, 모형 `plain.py`)와 결정 기록(`screens/assist.py`)** — 사례 검토: 경로(경보 목록 › {YYYY년 M월} › {품목} — {국가}), 평이한 제목, 칩(경보 {월} · 비교 기준 {월} · 조사 {YYYY-MM-DD HH:MM} (최신, N회 중) · 숫자 확인 완료). 머리 행과 본문 행이 같은 열 비율 `[2.6, 1]`(`gap="medium"`)을 써서 "다음 업무 제안" 카드(판정 배지·한 줄 뜻·"내 결정 기록하기" 전체 폭)가 아래 오른쪽 열과 같은 폭·같은 끝선이다. 왼쪽: 무슨 일이 있었나(두 칸) · 조사에서 확인한 것(번호 목록) · 다른 설명 가능성(가설 원문, EN은 "(Korean original)") · 결론(판정 + 한 문장, 보고서 요약 원문은 접힌 `st.expander`). 오른쪽: 제안이 뜻하는 것(3종, 이 사례 강조) · 근거로 삼은 것 4줄(자료 기간 · 기준(단가 {x}%, 점유율 {y}%p — `configs/policy_v1.json`에서 읽되 정책 이름은 쓰지 않음) · 방법 · 확인("보고서의 숫자 N개를 통계 원본과 대조해 모두 일치")) · 읽을 때 유의할 점 · 작은 링크 "조사 과정을 자세히 보려면 관리자 화면 ›". 같은 사례의 다른 조사는 작은 선택 "조사 시각"(예: "2026-09-26 06:59 (최신)")으로만 고른다. 사례 없이 들어오면 "조사 완료된 사례 고르기"(표시 "{품목} · {국가} · {YYYY년 M월} · {제안}", 사례마다 최신 조사 하나). 결정 기록: 오른쪽 위 사례 칩 + "제안: {판정}", 진행 단계 띠(경보 발생 ✓ → 조사 완료 ✓ → 내 결정(지금) → 사후 확인), 세 열 — ① 결정 폼(선택지 3개를 테두리 상자로, 이유(선택), 담당자 이름, "결정 저장" 전체 폭(`width="stretch"`), 그 아래 작게 저장 안내) ② 다시 조사하기(설명, 체크 3개(표시용), 오른쪽 정렬 "다시 조사" → 배경 조사 + 로딩 창) + 사후 확인(설명만, 열리지 않음) ③ 이 사례의 기록 · 용어 3개 · "문의할 때 사례 번호: {case_id} · 관리자 화면". 다시 조사는 그 사례를 조사한 실행의 스냅샷으로 돈다(세션 기본 스냅샷이 달라도).

⑧ **없앤 내부 식별자(담당자 화면 전부)** — 표의 HS6 코드 줄, 칩 "HS6 {코드} · 상대국 {코드}", 근거의 스냅샷 ID("고정 스냅샷 {id}")와 정책 이름("정책 policy_v1"), 실행 폴더 줄("실행 폴더 outputs/run_case-…"), 이력의 "(run_case-…)", 결정 저장 뒤 경로 알림("outputs/approval_record-…"), 재조사 완료 알림의 폴더 이름, "조사 완료된 사례 고르기"의 사례 ID, 사례 선택 없음 안내의 사례 ID, 실행 상태 코드가 들어가던 문구 세 곳(칩·결론·결정 거부), 자료 상태 claim의 EN 원코드(이제 평이한 이름표 `dstat.*`), HS10(10자리 품목 코드) 하위품목 코드(HS6 코드를 품고 있어 "하위품목 1·2…"로 바꿈 — 이름표가 없어서다), 잠긴 버튼 툴팁의 키 변수 이름·CLI 명령, EN 판정 이름의 코드 괄호("Keep under review (MAINTAIN)" → "Keep under review"). 합성 픽스처 가상 상대국 코드 XA·XB·XC는 "가상국 A·B·C"(EN "Synthetic partner A·B·C")로 보인다. 예외는 디자인대로 결정 기록 화면의 "문의할 때 사례 번호: {case_id}" 한 줄뿐이다. 관리자 화면(`app.py`)은 그대로 모든 식별자를 보인다.

⑨ **디자인과 달리 한 것** — (가) 로딩 창 아래 안내의 목업 문장 "조사는 통계 원본만 조회하며 외부로 자료를 보내지 않습니다"는 실제 NIM 실행에서는 사실이 아니라(추론 요청이 NVIDIA 클라우드로 간다) 쓰지 않았다. 실제 실행에는 "조사자와 검수자는 정해진 조회 도구로 통계 원본만 조회합니다", 재생 실행에는 "저장해 둔 모델 응답을 다시 쓰는 시연 실행(재생)이라 외부 모델을 부르지 않습니다"를 쓴다. (나) 픽셀 재현이 아니라 Streamlit 위젯(열·키가 있는 컨테이너·선택 상자·버튼)과 CSS로 영역·문구·순서·정렬을 옮겼다. 조회 조건의 선택 상자는 언어별 key를 쓰고 고른 값은 세션에 따로 둬 언어를 바꿔도 표시가 바로 바뀌고 값은 이어진다. (다) EN 판정 문장 속 이름은 목업대로 소문자("data hold suggested", "Suggested: keep under review")로 쓰는 별도 이름표(`verdict_lc.*`)를 두었다. (라) 결론 칸의 한 문장은 목업의 사례별 해석 문장 대신 판정의 뜻 문장(`meaning.*`)을 쓴다(UI2 기록 ⑧ (나)와 같은 까닭).

## 한계

- 조사 상태는 브라우저 세션(`st.session_state`)에 있다. 새로 고치거나 세션이 끊기면 로딩 창·조사 중 표시가 사라지지만, 자식 프로세스는 따로 돌아(`start_new_session=True`) 끝까지 가고 결과는 `outputs/run_case-{시각}/`에 남아 목록·사례 검토에 나타난다. 제한 시간 감시도 세션이 살아 있을 때만 한다(세션이 없으면 CLI 자체의 wall time 한도가 끝낸다).
- 한 세션에 조사 하나다. 다른 브라우저 세션이 같은 사례를 동시에 돌리는 것은 막지 않는다(각 실행은 별도 폴더라 섞이지 않는다). 실행 전후 폴더 차이로 폴더를 찾는 동안 다른 곳에서 같은 초에 만든 폴더가 끼어들 수 있으나, 끝난 뒤에는 CLI 표준 출력의 폴더를 먼저 쓴다.
- 진행 단계는 trace 표지로 추정한 것이며 흐름 단계의 정확한 경계가 아니다(예: 수정 단계와 최종 검증은 ⑤에 묶인다).
- 조사 중 표시는 CSS 고정 위치와 Streamlit 1.64의 `.st-key-<key>` 클래스에 기댄다. Streamlit을 올리면 다시 확인해야 한다.
- 실자료 사례는 키가 없으면 "조사 시작"·"다시 조사"가 잠긴다(재생 파일은 합성 A·B·C만).
- 작업 폴더의 실자료 결정 기록 하나(850490-PH-202412)는 기록이 가리키는 실행 폴더가 이 작업 폴더에 없어 "재검토 필요"로 보인다(규칙대로의 표시다).
