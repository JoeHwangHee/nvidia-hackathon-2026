| 제목 | X1 대체 경로 규칙의 두 예외 사용자 승인 |
| 결정 | X1(구현 첫날의 세로형 최소 통합 시험. NemoClaw(OpenShell, 곧 에이전트를 격리해 돌리는 NVIDIA 샌드박스 런타임 위에서 에이전트를 돌리는 NVIDIA 참조 스택) 에이전트부터 의도적 위반의 차단 로그까지 한 줄 경로를 한 번에 통과시킨다)이 3시간(조정값)을 넘기면 원인과 무관하게 Brev(드라이버·Docker 등이 미리 갖춰진 NVIDIA 원클릭 클라우드 개발 환경)로 옮긴다는 규칙에 두 예외를 두는 해석을 승인한다. 결정 기록 `20260924-0810-docs-run-review-decisions.md`의 13행이다. 아래 두 경우에는 Brev로 옮기지 않고 즉시 사용자 결정을 받는다. ① 키 주입 방식 두 가지가 모두 실패한 경우. 두 방식은 credential placeholder rewrite(샌드박스에는 자리표시 문자열만 두고, 샌드박스 밖에서 정책을 적용하고 요청을 중계하는 게이트웨이가 실제 키로 바꾸는 방식)와 `inference.local`(샌드박스가 보는 추론 주소)이다. ② 기본 블록을 빼거나 좁힌 정책으로도 시연 샌드박스(NemoClaw 시연 경로가 도는 샌드박스. 채점 대상 실행 샌드박스와 따로 둔다)가 요건 (b)를 채우지 못하는 경우. 요건 (b)는 외부 전송을 NVIDIA 추론 엔드포인트로만 허용하고 L7(HTTP 요청 수준) method·path를 명시하는 OpenShell 정책 요건이다(개발 플랜 §4.1) |
| 이유와 근거 | 두 경우는 시간이 아니라 보안 조건의 문제라, 실행 환경을 Brev로 옮겨도 풀리지 않는다 `[추론]`. 키 주입이 모두 실패했을 때 남는 길은 키를 샌드박스에 넣는 우회(하지 않는다)나 채점용 실행을 OpenShell 없이 돌리는 안(설계 명세 변경이 필요한 사용자 승인 대상)뿐이다 `[사실: 개발 플랜 §5.4, 로드맵 §7.1]`. 시연 샌드박스의 요건 (b)에는 예외를 두지 않는다 `[사실: 로드맵 §7.1]`. Brev로 옮기는 것도 키를 새 클라우드 호스트에서 쓰게 되는 환경 결정이다 `[추론]`. 오케스트레이터(작업을 나누고 PR(GitHub 변경 요청)을 병합하는 주관 에이전트)가 두 안(예외 인정(권장), 설계 명세대로 먼저 Brev로 옮긴 뒤 묻기)을 제시했고, 사용자는 "승인할게"라고 답했다. 오케스트레이터는 이 답을 권장안인 예외 인정으로 읽었다 `[사실: 2026-09-24(목) 채팅]` |
| 검토한 대안 | 설계 명세(2026-09-23(수) 설계 세션에서 사용자가 승인한 문서 세트 목표 명세. 저장소 밖에 있다)의 흐름대로 두 경우에도 먼저 Brev로 옮긴 뒤 묻는 안. Codex(OpenAI의 코딩 에이전트 CLI) 교차 검토가 "설계 명세와 다르다"고 지적한 쪽이다. 오케스트레이터는 PR #14에서 그 지적을 기각하고 사용자 확인 항목으로 올렸다. 버린 이유는 위와 같다. 이 승인으로 사용자는 설계 명세의 흐름과 다른 이 해석을 받아들였다 |
