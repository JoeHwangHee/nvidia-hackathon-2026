| 제목 | X1 대체 경로 규칙의 두 예외 사용자 승인 |
| 결정 | X1(구현 첫날의 세로형 최소 통합 시험. NemoClaw(OpenShell, 곧 에이전트를 격리해 돌리는 NVIDIA 샌드박스 런타임 위에서 에이전트를 돌리는 NVIDIA 참조 스택) 에이전트부터 의도적 위반의 차단 로그까지 한 줄 경로를 한 번에 통과시킨다)이 3시간(조정값)을 넘기면 원인과 무관하게 Brev(드라이버·Docker 등이 미리 갖춰진 NVIDIA 원클릭 클라우드 개발 환경)로 옮긴다는 규칙에 두 예외를 두는 해석을 승인한다. 결정 기록 `20260924-0810-docs-run-review-decisions.md`의 13행이다. 아래 두 경우에는 Brev로 옮기지 않고 즉시 사용자 결정을 받는다. ① 키 주입 방식 두 가지가 모두 실패한 경우. 두 방식은 credential placeholder rewrite(샌드박스에는 자리표시 문자열만 두고, 샌드박스 밖에서 정책을 적용하고 요청을 중계하는 게이트웨이가 실제 키로 바꾸는 방식)와 `inference.local`(샌드박스가 보는 추론 주소)이다. 이때 키를 샌드박스에 넣는 우회는 하지 않고 `BLOCKED`(막힘 보고)로 올린다(운용 규칙 §1.4). ② 기본 블록을 빼거나 좁힌 정책으로도 시연 샌드박스(NemoClaw 시연 경로가 도는 샌드박스)가 요건 (b)를 채우지 못하는 경우. 요건 (b)는 외부 전송을 NVIDIA 추론 엔드포인트로만 허용하고 L7(HTTP 요청 수준) method·path를 명시하며, `rules`(요청 허용 규칙) 생략과 범용 바이너리 + `/**`(모든 경로) 조합을 쓰지 않는 OpenShell 정책 요건이다(개발 플랜 §4.1). 이 요건에는 예외를 두지 않는다(로드맵 §7.1) |
| 이유와 근거 | 두 경우는 시한 초과가 아니라 보안 요건에 걸린 문제다. 하나는 요건 (c)(API 키를 샌드박스 안에 두지 않는 요건)이고, 다른 하나는 요건 (b)다. Brev로 옮기면 풀릴 수도 있지만(원인이 로컬 Docker에서 돈 게이트웨이일 때, 로드맵 §7.1) 보장은 없고, 옮기는 것 자체가 키를 새 클라우드 호스트에서 쓰는 환경 결정이다. 그래서 시한 규칙으로 자동 처리하지 않고 사용자가 정한다 `[추론]`. 사용자에게 올리는 것은 Brev를 막지 않고, 사용자는 그때 Brev를 고를 수 있다 `[사실: PR #14의 검토 이견 결정]`. 키 주입이 모두 실패했을 때의 대안의 예는 채점용 실행을 OpenShell 없이 돌리는 안이다. 이 안은 설계 명세(2026-09-23(수) 설계 세션에서 사용자가 승인한 문서 세트 목표 명세. 저장소 밖에 있다)를 바꿔야 하는 사용자 승인 대상이고, 고르면 채점 실행에 통제 ①(샌드박스 파일시스템 정책이 저장소 안 정답 경로 읽기를 막는 통제)과 요건 (b)의 증거가 없으며 규범 G2(룰북 자기채점에서 NemoClaw나 OpenShell이 아키텍처에 실제로 쓰이는지 보는 항목)가 약해진다 `[사실: 개발 플랜 §5.4, 로드맵 §7.1]`. 오케스트레이터(작업을 나누고 PR(GitHub 변경 요청)을 병합하는 주관 에이전트)가 두 안(예외 인정(권장), 설계 명세대로 먼저 Brev로 옮긴 뒤 묻기)을 제시했고, 사용자는 "승인할게"라고 답했다. 오케스트레이터는 이 답을 권장안인 예외 인정으로 읽었다 `[사실: 2026-09-24(목) 채팅]` |
| 검토한 대안 | 설계 명세의 흐름대로 두 경우에도 먼저 Brev로 옮긴 뒤 묻는 안. Codex(OpenAI의 코딩 에이전트 CLI) 교차 검토(PR #14)는 채택한 해석 가운데 키 주입 실패 예외가 설계 명세의 "3시간을 넘기면 Brev" 규칙과 충돌한다고 지적하며 이 흐름을 따르자고 했다. 시연 샌드박스 예외는 그 지적에 들지 않았다. 오케스트레이터는 그 지적을 기각하고 사용자 확인 항목으로 올렸다. 기각 이유는 명세의 그 규칙이 두 키 주입 방식이 모두 실패한 경우를 다루지 않는다는 것과, 사용자에게 올려도 사용자가 Brev를 고를 수 있다는 것이었다 `[사실: PR #14의 검토 이견 결정]`. 이 안을 버린 이유는 "이유와 근거" 칸과 같다. 이 승인으로 사용자는 설계 명세의 흐름과 다른 이 해석을 받아들였다 |
