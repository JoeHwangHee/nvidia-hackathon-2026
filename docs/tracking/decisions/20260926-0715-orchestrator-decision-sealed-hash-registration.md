## 한계와 다음 일

- 봉인 폴더 위치는 비밀이 아니고 같은 OS 사용자로 도는 에이전트의 열람을 기술적으로 막지 못한다. 해시는 변조를 드러낼 뿐이다(병렬 개발 규칙 §6.4, 자료 계약 §12.4). `real_sealed` 사례 목록은 분할 seed·스냅샷·`policy_v1`·탐지 코드로 다시 계산할 수 있고, 표본 40건은 봉인된 seed 파일 없이는 다시 계산할 수 없다.
- holdout40의 파일 이름은 하위 경로 `input/`(사례 목록 `cases.json`, 수집기 형식 원천 `source/`: 요청 ID 해시 이름의 응답 XML 185개, manifest·수신 기록·raw 결합 해시·빌드 기록·합성 비교국 표)·`answers/`(정답표, 부모 원본 계열 ID 목록, 생성 규칙)·`gen/`(생성·검산 스크립트 3개, seed·nonce 파일)이다. 이름에 기대 상태·분류·품목·상대국·월이 없다 `[사실: 해시 목록의 이름]`.
- `real_sealed` 경보 470건은 43개 시계열 × 36개월 대비 밀도가 높다. `real_dev`(21개 시계열)의 경보 221건과 같은 밀도이며 `policy_v1` 기준값의 알려진 성질이다(개발 플랜 §2.3의 규모 수치). 표본은 한 번만 뽑았고 다시 뽑지 않는다.
- 채점 전 해시 재대조(병렬 개발 규칙 §6.6 5단계)는 평가 스킬 ② 사전 점검이 이 목록으로 한다. holdout40 봉인 입력을 공식 채점 대상 실행 전용 샌드박스에 넣는 방식(빌드한 스냅샷 반입, `input/cases.json`만 허용 목록)은 F2 준비 때 로드맵 MT5·평가 스킬 ②대로 정한다 `[미확인]`.
- 원본 커밋 위치(정답 대조 채점 뒤)는 계획 경로·명령 표에 없다 `[미확인]`. 그때 표를 먼저 고친다.
