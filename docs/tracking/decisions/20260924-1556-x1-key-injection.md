# X1 키 주입 방식과 확인된 명령

X1(구현 첫날의 세로형 최소 통합 시험)에서 정한 두 가지만 적는다. 하나는 채택한 키 주입 방식과 이유, 다른 하나는 확인된 명령이다(`docs/plan/ROADMAP.md` X1 행, `docs/rules/AGENT_OPS.md` §6.4). 시험 세부와 개발 플랜 §5.3 `[미확인]` 항목의 결과는 `artifacts/openshell/violation_tests.md`와 `artifacts/openshell/logs/`에 있다.

용어

- OpenShell: 에이전트를 격리해 돌리는 NVIDIA 샌드박스 런타임. 게이트웨이(제어면, 곧 상태·정책·provider 설정을 보관하고 샌드박스에 내려보내는 부분. 샌드박스 밖 호스트에서 돈다)와 샌드박스로 이뤄진다. 샌드박스 컨테이너 안에서는 감독 프로세스(supervisor, root로 도는 `openshell-sandbox`)가 에이전트를 제한된 자식 프로세스로 띄우고, 정책 프록시(바깥 요청의 목적지·실행 파일·L7 규칙을 검사하고 자리표시 값을 실제 키로 바꾸는 부분)로 정책을 집행한다 `[사실: OpenShell v0.0.116 docs/about/how-it-works.mdx 13·14·107~117행]`.
- NemoClaw: OpenShell 위에서 에이전트를 돌리는 NVIDIA 참조 스택. OpenClaw는 그 기본 하네스(모델이 도구를 부르며 일하도록 감싸는 실행 틀)다.
- S0: 앱 뼈대를 만드는 첫 작업 단위. MT4: 조사 흐름·NIM 호출·NAT(NVIDIA 에이전트 실행 추적·평가 도구 모음) 감싸기 작업. MT5: CLI·런타임 스킬·OpenShell 정책·NemoClaw 경로 작업. MT7: 평가 하네스와 샌드박스 밖 실행기 작업(모두 `docs/plan/ROADMAP.md` §2).
- colima: macOS에서 Docker용 리눅스 가상 머신을 띄우는 도구. compute driver: 게이트웨이가 샌드박스를 띄울 때 쓰는 실행 백엔드(여기서는 Docker).

| 결정 | ① TradeSentry CLI의 NIM(NVIDIA 클라우드 추론 API) 호출은 **credential placeholder rewrite**(샌드박스의 에이전트 쪽 프로세스에는 자리표시 값만 두고, 샌드박스 안 감독 프로세스의 정책 프록시가, 게이트웨이에서 받은 자격 증명으로 요청 시점에 자리표시 값을 실제 키로 바꾸는 방식 `[사실: OpenShell v0.0.116 docs/about/how-it-works.mdx 116행, docs/sandboxes/manage-providers.mdx 327~330행, artifacts/openshell/logs/20260924-x1-demo-openshell-logs.txt 7·13행]`)로 한다. OpenShell 0.0.116에서의 구체 형태는 다음과 같다. provider(게이트웨이에 등록한 자격 증명 묶음)를 프로필로 만들어 샌드박스에 첨부한다. 프로필의 `auth_style: bearer`·`header_name: authorization`은 이 판에서 저장·검증되는 메타데이터이고 치환 위치를 정하지 않는다 `[사실: 같은 판 docs/sandboxes/providers-v2.mdx 216행]`. CLI는 샌드박스 환경변수 `NVIDIA_API_KEY`에 든 자리표시 값을 `Authorization: Bearer` 헤더에 실어 `https://integrate.api.nvidia.com/v1/chat/completions`로 보낸다. 헤더 값은 프록시가 자리표시 값을 바꾸는 위치 가운데 하나다 `[사실: 같은 판 docs/sandboxes/manage-providers.mdx 363행]`. 샌드박스 네트워크 정책은 그 목적지의 `POST /v1/chat/completions` 한 경로만 CLI의 파이썬 실행 파일에 연다. ② 확인된 명령은 아래 "확인된 명령" 절의 목록이다. ③ `inference.local`(게이트웨이가 샌드박스에 주는 관리형 추론 주소)은 채택하지 않는다. 이 결정은 채점 대상 실행 샌드박스의 CLI 경로 기준이다. 시연 샌드박스의 하네스(OpenClaw)가 쓰는 추론 경로는 이 결정에 들지 않는다 |
| 이유와 근거 | ① 실제로 성공했다: OpenShell만 쓴 시험 샌드박스 `x1-os-test`에서 자리표시 값 헤더로 NIM이 HTTP 200을 냈고, 같은 샌드박스의 키 조회 시험에서 샌드박스 사용자(UID 998) 권한으로 닿는 환경변수·파일·읽을 수 있는 `/proc/<pid>/environ`에는 실제 키가 0건이었다(`NVIDIA_API_KEY`는 자리표시 값. PID 1(root 감독 프로세스)은 조회하지 못했다) `[사실: violation_tests.md V0·V5와 머리말 "키 조회 범위", os-test transcript [K2]]`. 실제 키는 샌드박스 컨테이너 안 root 감독 프로세스가 게이트웨이에서 받아 가진다 `[사실: OpenShell v0.0.116 docs/about/how-it-works.mdx 14·116행]`. 개발 플랜 §4.6의 "헤더에 키를 넣는 동작 `[미확인]`"은 이 실측으로 풀렸다. ② 요건 (b)를 정책으로 보일 수 있다: 목적지 하나·method·path·실행 파일을 정책에 적을 수 있고, 비허용 호스트·비허용 실행 파일·L7(HTTP 요청 수준) 위반이 종료 코드와 감사 로그 거부 행으로 막혔다 `[사실: 같은 문서 V1~V3]`. ③ `inference.local`도 NIM 200을 냈지만, 0.0.116에서는 샌드박스 네트워크 정책 밖에서 감독 프로세스의 추론 라우터가 처리한다. 정책 블록이 없어도 `curl`·시스템 파이썬 등 모든 실행 파일이 썼고, 라우터가 chat·completions·responses·embeddings·모델 조회를 모두 받았으며, 블록을 두자 요청이 응답 없이 멈췄다. 그래서 이 경로로는 요건 (b)의 method·path와 실행 파일 제한을 보일 수 없었다 `[사실: 같은 문서 V7·V8]`. ④ OpenShell 저장소 최신판의 공식 스킬 `debug-inference`는 관리형 추론 경로를 "removed"로 적는다. `inference.local`은 판 올림 뒤 사라질 수 있다 `[사실: 2026-09-24(목) 설치한 스킬 문서]`, `[추론: 판 올림 영향]`. ⑤ NemoClaw 뒤에도 유지된다: NemoClaw v0.0.124가 게이트웨이를 다시 구성했다(포트 8080·자체 상태 폴더, 작업 공간 추론 경로 `nvidia-prod`, 내장 `nvidia` 유형 provider 첨부). 그 뒤에도 같은 방식(헤더 자리표시 값 치환, 자리표시 변수 이름은 `NVIDIA_INFERENCE_API_KEY`)으로 시연 샌드박스의 OpenClaw(실행 파일 node)와 그 자식인 CLI(python)가 NIM 200을 받았다. 추론 경로를 지운 상태였고, 키 조회는 UID 998 범위에서 실제 키 0건이었다 `[사실: violation_tests.md §6 DA2·DA4·DH·DH2·DK3·DK4]` |
| 검토한 대안 | ① `inference.local`: 성공했지만 위 ③·④ 때문에 버렸다. 또 클러스터 추론 경로는 내장 유형 provider만 받아 사용자 프로필로 좁힌 provider를 쓸 수 없었다 `[사실: artifacts/openshell/logs/20260924-x1-os-test-transcript.txt I1]`. ② provider 프로필의 목적지를 정책에 자동 합성하는 설정(`providers_v2_enabled`, 게이트웨이 전역): 0.0.116에서는 기본값이 꺼져 있어 첨부만으로는 목적지가 열리지 않았다(V0a). 게이트웨이 전역 설정이라 NemoClaw에도 영향을 주므로 켜지 않고, 목적지는 샌드박스 정책에 직접 적는다 `[사실]`, `[DESIGN]`. ③ 요청 본문 치환(`request_body_credential_rewrite`): NIM은 키를 헤더로 받으므로 필요 없다. ④ 샌드박스에 키를 넣는 우회: 요건 (c) 위반이라 검토 대상이 아니다 |

## 확인된 명령

2026-09-24(목) 이 개발 기계(macOS, Apple Silicon, colima)에서 종료 코드 0으로 확인한 명령이다. 예외는 셋이고 명령 옆에 적었다: OpenShell `install.sh`(게이트웨이 대기에서 1, compute driver 미설정), NemoClaw 설치(키 없이 온보딩 [3/8]에서 1, 예상), `nemoclaw … agent`(OpenClaw 결과는 정상이나 `replayInvalid` 표식으로 1). `<…>`는 자리 표시다. 키 값은 어떤 명령에도 없다.

```bash
# 공식 스킬 설치(개발 환경, --skill 여러 개 지정이 동작함)
npx skills add NVIDIA/OpenShell --skill openshell-cli --skill generate-sandbox-policy --skill debug-inference --agent claude-code -y
npx skills add NVIDIA/skills --skill nemoclaw-user-guide --agent claude-code -y

# OpenShell 설치(공식 install.sh를 내려받아 읽은 뒤 판 고정 실행)
curl -fsSL -o install.sh https://raw.githubusercontent.com/NVIDIA/OpenShell/main/install.sh
OPENSHELL_VERSION=v0.0.116 sh install.sh
# 설치기는 게이트웨이 대기에서 종료 코드 1로 끝났다(compute driver 미설정). 아래 두 줄로 게이트웨이를 띄웠다
# 주의: NemoClaw 설치 뒤에 이 줄을 다시 실행하면 NemoClaw가 다시 쓴 게이트웨이 설정을 덮어써 시연 게이트웨이가 깨진다. 자리표시를 찾는 방법은 spikes/x1/README.md "자리표시" 절
printf 'OPENSHELL_DRIVERS=docker\nDOCKER_HOST=<colima Docker 소켓>\n' > <OpenShell 설정 폴더>/gateway.env
brew services restart nvidia/openshell/openshell
openshell status

# provider(키는 래퍼가 자식 프로세스 환경에만 넣고, 명령에는 변수 이름만 준다)
openshell provider profile import -f <프로필 YAML>
python3 spikes/x1/with_nvidia_key.py --env-file <.env 경로> -- openshell provider create --name <provider 이름> --type <프로필 id> --credential NVIDIA_API_KEY
openshell provider get <provider 이름>

# 샌드박스(colima에서는 이미지 빌드에 DOCKER_HOST가 필요)
DOCKER_HOST=<colima Docker 소켓> openshell sandbox create --name <이름> --from <Dockerfile 폴더> --policy <정책 YAML> --provider <provider 이름> --no-auto-providers --detach
openshell policy set <이름> --policy <정책 YAML> --wait
openshell policy get <이름> --full
openshell sandbox exec -n <이름> --timeout <초> -- <명령>
openshell sandbox upload <이름> <로컬 경로> <샌드박스 경로>
openshell sandbox download <이름> /sandbox/<경로> <로컬 경로>
openshell logs <이름> --since <기간> -n <행 수>
openshell sandbox delete <이름>

# NemoClaw v0.0.124 시연 샌드박스(2단계). 설치는 고지 수락 옵션을 쓰며 사용자 결정 뒤에만 실행한다
env -u NVIDIA_API_KEY -u NVIDIA_INFERENCE_API_KEY -u DATA_GO_KR_SERVICE_KEY DOCKER_HOST=<colima Docker 소켓> NEMOCLAW_INSTALL_TAG=v0.0.124 NEMOCLAW_PROVIDER=build bash nemoclaw.sh --yes-i-accept-third-party-software   # 키가 없어 온보딩 [3/8]에서 종료 코드 1(예상). 실제 실행은 demo transcript [N1]
python3 spikes/x1/with_nvidia_key.py --env-file <.env 경로> --export-as NVIDIA_INFERENCE_API_KEY -- env DOCKER_HOST=<colima Docker 소켓> NEMOCLAW_PROVIDER=build NEMOCLAW_MODEL=nvidia/nemotron-3-super-120b-a12b NEMOCLAW_POLICY_TIER=restricted NEMOCLAW_POLICY_MODE=skip NEMOCLAW_WEB_SEARCH_PROVIDER=none NEMOCLAW_ACCEPT_THIRD_PARTY_SOFTWARE=1 nemoclaw onboard --non-interactive --fresh --name <이름> --yes-i-accept-third-party-software   # 실제 실행은 demo transcript [N3]
openshell inference delete
nemoclaw <이름> skill install <스킬 폴더>
nemoclaw <이름> gateway restart
nemoclaw <이름> agent --agent main --json --timeout <초> -m "<요청>"   # OpenClaw가 replayInvalid를 표시하면 래퍼는 1을 낸다
```
