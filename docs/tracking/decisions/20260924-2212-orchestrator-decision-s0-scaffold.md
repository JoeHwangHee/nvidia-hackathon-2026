| 확정한 위치 | ① 환경: 저장소 루트의 `pyproject.toml`·`uv.lock`·`.python-version`(3.12.13). 가상환경 `.venv/`는 커밋하지 않는다. 시험 `uv run --locked python -m unittest discover -s tests -v`, CLI `uv run --locked tradesentry <명령>`, 단위 하나 실행 `uv run --locked python -m tradesentry.units <단위 ID> --in <입력 파일>`(개발 전용). 시스템 `python3`(3.9.6)로는 새 코드가 돌지 않는다. 수집기 시험만 `python3 -m unittest discover -s tests -p "test_ingest.py"`로 돈다 ② 화면 `app.py`: `src/tradesentry/app.py`(import `tradesentry.app`, 도메인명 `app`) ③ 프롬프트·모델 설정: `configs/model/`(파일 이름·형식은 MT4) ④ 사례 실행 폴더와 묶음 실행 폴더 잇기(자문 명세서 Q9): 사례 실행 폴더는 묶음 폴더 안에 넣지 않고 같은 부모 아래 형제 폴더 `run_case-{시각}`으로 두고, 묶음 기록 `evaluation_batch_run-{시각}.jsonl` 각 줄의 `run_id`로 잇는다 ⑤ 국가 코드 대응표(단위 G3, Q20): `data/reference/country_map.csv`(관세청 `cntyCd` ↔ BACI `country_code` ↔ ISO3, 대만 = BACI 490 주석). D가 만든다 ⑥ 봉인 자료 생성 중 명령의 출력 위치: 함수 인자(출력 부모 폴더)로만 바꾼다. CLI에는 출력 위치 인자를 두지 않는다 |
| ④·⑥에 붙는 조건 | S0 검토(평가 방법론·보안·NVIDIA 스택)의 권고다. ④ 묶음 기록은 샌드박스가 쓸 수 있는 파일이라 믿지 않는 입력이다. `run_id`를 N1·N5 형식(`^[a-z][a-z0-9_]*-\d{12}$`)으로 검사하고 같은 부모의 그 이름 하나만 연다. `..`, 경로 구분자, 심볼릭 링크로 벗어나는 경로는 거부하고 글롭으로 찾지 않는다. 봉인 묶음은 `outputs/sealed/` 형제만, 아닌 묶음은 `outputs/` 형제만 허용한다. 분모는 고정 사례 목록으로 세고, 목록에 있는데 줄이나 폴더가 없으면 실패로 센다. 사례 폴더의 `run_id`·`case_id`·`mode`를 묶음 줄과 대조한다. 재실행을 원래 실행과 잇는 방법(Q9의 4)은 로드맵 MT7·DT8에서 F1 전에 정한다 `[미확인]` ⑥ 조립체의 모든 출력(trace·실행 기록·보고서)은 그 인자 하나에서 온다. 단위 안에 `outputs/` 기본값을 따로 두지 않는다. 샌드박스 안 CLI의 출력 위치 규칙과 호스트가 확보한 실행명을 샌드박스 안에 넘기는 방식은 로드맵 MT5에서 정한다 `[미확인]` |
| 확정한 약속 | ① 단위 파일 머리 주석: `단위 ID`·`도메인명`·`소유`·`입력`·`출력`·`허용 import` 여섯 줄(`tradesentry.units.registry.read_header`가 읽는다) ② 허용 import 계층: contract → dal·runlog → snapshot·metrics·grouping → policy → tools·reports·validator → workflow·approval → evaluation → cli·app. Critic(I11)은 도구를 부르지 않으므로(`docs/plan/DEV_PLAN.md` §7) tools를 import하지 않는다. 넓혀야 하면 그 PR에서 머리 주석을 고치고 검토받는다 ③ 경계 시험: 채점기(`eval.scorer`) 닫힘은 허용 목록(표준 라이브러리, `eval`, `eval.scorer`)으로 보고, `tests/`·`scripts/`·`spikes/`를 거친 import도 따라간다. 채점기 닫힘·V2·E2에는 동적 import·`.env`·키 변수 이름 금지 토큰 시험을 둔다. E2는 `tradesentry.ingest`와 `nat`에 닿지 않는다. E2의 하위 프로세스 인자에 `tradesentry`는 인자 목록이 `openshell`로 시작할 때만 허용한다(샌드박스 안 CLI를 부르는 E2의 본래 일) ④ 골든 시험: 건너뛰는 경우는 진입 함수가 없거나 `run`이 뼈대(몸통이 NotImplementedError 하나)일 때뿐이다. 구현한 `run`의 골든 쌍이 없거나 호출 중 NotImplementedError가 나면 실패다. 비교는 형식까지 본다(Decimal의 끝자리 0, bool과 int, float 금지). 단위의 건너뛰기는 허용 목록(단위 ID와 사유)에 있을 때만 허용한다. 시험 중 봉인 폴더 변수와 `HOME`은 없는 임시 경로로 고정하고 소켓 연결을 막는다 ⑤ 종료 코드(S0 소유, 자료 계약 밖): 공통 실행기 0·2(인자·입력 오류, 실행명 확보 전)·3(미구현)·4(출력 규칙 위반), CLI·채점기 자리 미구현 3·인자 오류 2 ⑥ 공통 실행기: 입력은 JSON 문서 하나, 소수는 Decimal, 출력 확장자는 등록부, 출력 파일은 이미 있으면 실패하는 방식으로 쓴다. 오류 문장에는 예외 이름과 모듈 이름만 적는다(자료 계약 N13) ⑦ CLI: 명령 다섯 개와 공통 옵션 셋은 자료 계약 §10 CLI 행과 같다. 옵션 줄임은 받지 않는다. 값의 형식 검증은 단위 F1 구현(MT5)과 AS1 배선 때 한다 |

| 두 트랙에 넘기는 것 | NAT 1.9.0의 `nat` 명령은 import 때 `.env`를 찾아 읽고, 가상환경이 저장소 안이면 저장소의 `.env`에 닿는다 `[사실: NAT v1.9.0 nat/cli/entrypoint.py 42행과 같은 호출의 재현. NAT 자체는 실행 안 함]`. MT4는 `nat` 명령 대신 파이썬 API를 쓰거나, `nat`을 부를 수 있는 모든 프로세스에 `PYTHON_DOTENV_DISABLED=1`과 `NAT_TELEMETRY_ENABLED=false`를 준다(lock의 python-dotenv가 1.2.0 이상인지 확인). I13·E4의 허용 import에 `yaml`(X1이 씀)을 더하고, `import nat`을 처음 넣는 PR은 같은 PR에서 NAT를 lock에 넣는다. streamlit은 dev 그룹이나 함수 안 import로 둔다. 실행명 확보(N8)는 개발 전용 공통 실행기에만 있으므로 L2·E1·E2·채점기가 각자 구현한다. NIM을 부르는 단위의 골든 쌍은 I8(기록 재생)을 주입해 만든다 |
