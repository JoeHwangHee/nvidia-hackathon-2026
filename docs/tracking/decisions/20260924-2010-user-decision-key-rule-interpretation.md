# 키 규칙 해석 A, 키 재발급 시점, NemoClaw 고지 전문 사용자 결정

| 항목 | 내용 |
|---|---|
| 날짜 | 2026-09-24(목) 20:10(기록 시각). 사용자의 답은 같은 날 19:35 무렵에 채팅으로 받았다 |
| 제목 | 절대 규칙 1·요건 (c)의 "샌드박스 안" 해석 A, NVIDIA 키 재발급 시점, NemoClaw 설치기 고지 전문 |
| 결정 | ① 안내 문서 절대 규칙 1과 개발 플랜 요건 (c)의 "키를 샌드박스 안에 두지 않는다"를 해석 A로 읽는다. 해석 A는 "에이전트와 그 자식 프로세스(샌드박스 사용자 권한으로 도는 프로세스)가 읽을 수 있는 곳에 두지 않는다"는 뜻이다. ② 절대 규칙 1의 문구를 오케스트레이터가 보인 안대로 고친다: "키 원본은 `.env`에 둔다. 사본은 설계된 주입 경로(게이트웨이 저장소, 샌드박스 감독 프로세스, NemoClaw 설정, 옮기면 Brev 호스트)에만 생긴다. 에이전트와 그 자식이 읽을 수 있는 곳에는 두지 않고, 에이전트는 사본 위치를 열거나 출력하지 않는다. 저장소·로그·trace에는 어떤 경우에도 없다." ③ NVIDIA API 키와 그 사본은 대회 마무리(2026-09-28(월) 제출 뒤)까지 그대로 둔다. 마무리 때 사용자가 키를 재발급하고, 오케스트레이터는 그때 재발급과 사본 정리를 안내한다. ④ NemoClaw 설치기 고지 전문에 이의가 없다. 대상은 v0.0.124, 판 `2026-04-01b`이고, 사용자 책임·자기 위험 부담 조항을 포함한다 |
| 사용자 원문 | "A안으로 하고 1. 재발급할게. 마무리시 재발급 안내하도록 기록해둬 2. 이의없어" `[사실: 2026-09-24(목) 채팅]` |
| 선택의 근거 | X1 PR(#19) 검토에서 NVIDIA 스택·보안 검토자가 따로 같은 점을 짚었다. 자리표시 값을 실제 키로 바꾸는 주체가 샌드박스 밖 게이트웨이가 아니라는 것이다. 바꾸는 주체는 샌드박스 안에서 root로 도는 감독 프로세스(supervisor)의 프록시이고, 게이트웨이에서 자격 증명을 받는다. 오케스트레이터가 공식 문서로 확인했다 `[사실: OpenShell v0.0.116 docs/about/how-it-works.mdx(Credentials 행 "Receives credential material from the gateway and injects it only through configured policy paths or request-time proxy rules"), docs/sandboxes/manage-providers.mdx("The agent process inside the sandbox never sees real credential values")]`. X1이 확인한 것은 샌드박스 사용자 권한으로 닿는 곳(환경변수·파일·읽을 수 있는 `/proc` 환경 파일)에서 실제 키가 0건이라는 것이다 `[사실: X1 PR의 artifacts/openshell/violation_tests.md]`. 오케스트레이터는 두 안을 보였다. A(권장)는 공식 설계 그대로이고 X1 결과로 충족된다. 대신 규칙 문구를 고친다. B(컨테이너 전체로 읽기)는 두 키 주입 방식이 모두 규칙 위반이 되어, 승인된 예외 규칙대로 대안을 새로 설계해야 한다. MVP 일정에 큰 영향이 있다 |
| 남는 위험 | 샌드박스를 탈출해 root를 얻으면 키가 드러날 수 있다. 경계는 사용자 분리, Landlock(리눅스 커널의 파일 접근 제한 기능), seccomp(리눅스 시스템 호출 필터)다 `[추론]`. 키는 ③대로 마무리 때 재발급한다 |
