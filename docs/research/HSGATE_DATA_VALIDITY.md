# HSGate 근거자료 링크·데이터 유효성 검증 보고서

> **한 줄 결론**: HSGate가 기대는 관세청 CLIP "품목분류 국내사례"는 **실재하고, 로그인 없이 목록 JSON·상세 HTML을 받을 수 있으며, 물품설명→결정세번(10단위)→결정사유(통칙·해설서 인용)가 사례마다 쌍으로 존재한다** [사실]. 다만 (1) **공공누리 미부착 + "all rights reserved"** 표기라 대량 수집·재배포·파인튜닝 라이선스는 [미확인], (2) 1990년대부터 누적된 54,180건에 **HS 개정판이 혼재**, (3) 참조번호가 고유키가 아니고 결정세번 필드에 서식 노이즈가 있어 **정규화 없이 정답으로 못 쓴다**. 따라서 **"RAG/검색 근거 + held-out 정확도 평가"용으로는 A등급, "파인튜닝 학습자료"로는 부적합(라이선스 미확인·시점 혼재), "실무 신고 정확도" 주장에는 D등급**이다.

### 5.3 "판단근거/검색근거(RAG·인용·게이트 대조)"로서의 적합성 → **적합(조건부)**
- 강점: 관세청이 실제로 내린 결정(제86조 절차)이며 결정사유가 조문·해설서를 인용하는 **설명 가능한 선례**. 사례 인용 시 참조번호·시행일자·검토서번호를 함께 제시하면 관세사가 검증 가능.
- 조건:
  1. **시점 필터**: 기본 2022-01-01 이후(6,227건)만 인덱싱. 그 이전은 "구형 HS, 참고용" 플래그.
  2. **경고 병기**: 사례 원문의 "※ 품목분류는 수출입신고 당시의 물품상태에 따라 변경될 수 있음"과 제86조⑦·제87조(변경·소급)를 UI에 노출.
  3. **효력 한계**: 사전심사 회신은 **그 신청인의 그 물품**에 대한 것(제86조⑤ "통지한 물품과 같을 때"). 타인의 유사 물품에 대한 구속력은 없다 → "근거"이지 "정답"이 아니다.
  4. **HS 6단위 vs 10단위**: 6단위는 국제 공통(WCO), 7~10단위는 한국 HSK. 6단위 정확도는 국제 비교 가능, 10단위는 한국 관세율·요건에 직결되나 세분류 변경이 잦아 시점 민감.
  5. **법적 책임**: 수출입신고의 책임은 신고인(관세사 등)에게 있고 사전심사 신청권자도 법정(제86조①). 에이전트 산출물은 **관세사 승인 전 초안**으로만 취급.

### 5.4 HS 6/10단위 정확도 평가의 한계
- 정답이 "하나"라는 가정이 약하다: 같은 물품이 재심사·위원회에서 바뀔 수 있고(제87조), 과거 사례와 현행 세번이 다를 수 있다.
- 10단위 top-1은 세분류 노이즈·개정으로 과소평가, 6단위는 유사품 누수로 과대평가될 수 있다 → **둘 다 보고하고 분할 방식을 명시**해야 한다.
- 표본이 "어려운 사례"에 치우쳐 있어 실무 평균 정확도로 일반화 불가.

## 6. 6일 해커톤 안전 사용 권고 (실행 체크리스트)

- [ ] **파인튜닝·SFT·임베딩 모델 학습에 CLIP 원문을 쓰지 않는다.** (라이선스 [미확인] + 시점 혼재 + 누수). Retriever는 사전학습 임베딩(예: nemotron embed)으로 **인덱싱만** 한다.
- [ ] **RAG/검색용**: 사용자가 자기 환경에서 `retrieveDmstPrlstClsfCaseLst2.do`(2022-01-01~, 3종) → `...Dtl.do`로 수집해 **로컬 캐시**에만 저장. 요청 간격 ≥1초, 동시성 1, User-Agent에 연락처 명시, 실패 시 중단. 수천 건 이상 전량 수집은 하지 않는다(2022+ 6,227건도 상세 호출 포함 1.2만 요청 → 과하다). **헤드라인 평가용 500~1,000건 + 검색 인덱스용 2022+ 목록만**으로 제한.
- [ ] **원문은 리포지토리에 넣지 않는다.** 리포에는 (a) 수집 스크립트, (b) `manifest.jsonl`(RRDC_NO, REFF_NO, ENFR_DT, 정규화된 DTRM_HS_SGN, 물품설명 SHA-256, 결정사유 SHA-256), (c) held-out ID 목록만 커밋. 재현 시 스크립트가 해시를 대조해 동일 데이터임을 검증한다. README 인용은 5건 이내·출처(참조번호·시행일자·URL) 명시.
- [ ] **held-out 분리**: 키는 `RRDC_NO`. ① 시간 분할(train/index ≤ 2025-12-31, test = 2026년 948건 중 정규화 통과분) 을 기본으로 하고, ② 추가로 **품명 첫 토큰(모델명 앞) + 결정세번 6단위**로 그룹을 만들어 같은 그룹이 양쪽에 걸치지 않게 한다. ③ 물품설명 앞 120자 동일 건은 test에서 제거. ④ 결정세번 공란·복수·비10자리 건은 평가에서 제외하고 제외 수를 보고.
- [ ] **정답 정규화 규칙을 코드로 고정**: `re.sub(r'[^0-9]','',DTRM_HS_SGN)` → 길이 10 검증 → 앞 6자리=HS6, 10자리=HSK. 2026 HS부호 파일(data.go.kr 15049722, 공공누리 1유형)에 없는 10단위는 "현행 미존재" 플래그.
- [ ] **평가 지표**: HS6 top-1/top-3, HSK10 top-1/top-3, **근거 사례 제시율**(예측 세번과 같은 6단위의 2022+ 사례를 1건 이상 인용했는가), 기권률(신뢰도<τ). baseline = 키워드→HS부호 파일 매칭, 제로샷 LLM, Retriever-only.
- [ ] **UNI-PASS는 mock만**: 실제 UNI-PASS Open API는 회원가입·로그인·서비스 신청이 전제이고(공식 안내), 수출입신고는 신고인 자격의 문제다. 샌드박스에 실 자격증명을 두지 않고 `POST /mock-unipass/declarations`에 대해 OpenShell 미들웨어가 "근거 사례 세번 집합 불일치 / 승인 토큰 없음 → 403"을 시연한다.
- [ ] **제출서 문구**: "관세청 CLIP 공개 사례를 **조회·인용**하여 근거로 제시한다. 원문 재배포·모델 학습에 사용하지 않았다. 사례는 해당 신청 물품에 한해 유효하며(관세법 제86조⑤·⑦), 최종 신고 책임은 관세사에게 있다."를 명시.
- [ ] (선택) 관세청 운영지원과에 공공누리/AI유형 부착 여부를 **문의만** 해 두고, 답을 받기 전에는 위 범위를 넘지 않는다.
