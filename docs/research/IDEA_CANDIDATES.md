## 🥇 A. 에이전트 권한 정책 자동생성 · 레드팀 검증기

> **"AI 에이전트에게 최소권한을 주는 일은 지금 전부 수작업이다. 그걸 에이전트가 하게 만든다."**

### 문제
NemoClaw / OpenClaw 같은 자율 에이전트를 실무에 붙이려면 파일시스템·네트워크·자격증명 접근을 정책으로 통제해야 한다. 그런데 OpenShell 정책 YAML은 **사람이 손으로 쓴다.**
너무 빡빡하면 에이전트가 망가지고, 너무 느슨하면 보안 사고가 난다. 이 균형점에 정답이 없고, 검증 방법도 없다.

### 해결 — 3단 에이전트 루프

```
① Profiler Agent
   대상 에이전트를 OpenShell 샌드박스에서 실행
   → 실제 접근 패턴(바이너리/경로/네트워크/추론 호출)을 감사 로그로 수집

② Policy Agent
   nemotron-policy-generator 스킬 + Nemotron 3
   → 최소권한 YAML 정책 초안 생성

③ Red-Team Agent
   공격 시나리오 N종 주입 (자격증명 탈취 / 외부 유출 / 임의 실행)
   → 뚫리면 실패 케이스를 ②에 피드백
   → 수렴할 때까지 반복
```

### NVIDIA 스택 (6종)
`OpenShell` · `NemoClaw` · `Nemotron 3 Nano/Ultra` · `NeMo Agent Toolkit (nvidia-nat)` · `NeMo Guardrails + NemoGuard NIM` · Agent Skills (`nemotron-policy-generator`, `nemoclaw-user-guide`, 자체 SKILL.md)

### 뽑을 숫자 ⭐
| 지표 | baseline | ours |
|---|---|---|
| **공격 차단율** | 기본 정책(default deny 없음) | 생성 정책 |
| **오탐률** (정상 작업 차단) | 과도 제한 정책 | 생성 정책 |
| **정책 작성 시간** | 수작업 측정값 | 자동 생성 |
| **수렴 라운드 수** | — | N회 |
| **기능 보존율** | 정책 없음 | 정책 적용 후 (= 정책이 성능을 안 깎았음을 증명) |

### 가시화
- **정책 YAML diff 타임라인** — 라운드별 룰 추가/완화 이력
- **allow/deny 감사 로그 히트맵** — 경로 × 시간
- **공격 시나리오 매트릭스** — 라운드별 빨강 → 초록 전환

### 채점
| 축 | 점수 | 근거 |
|---|---|---|
| 1. 기술 심도 (35%) | **4.7** | OpenShell이 주제 자체(1b=5) · NemoClaw 하네스 운용(1c=3) · 스킬 조합+자작(1d=5) · Nano/Ultra 라우팅(1e=5) · 기술 6종(1a=5) · MCP(1f=3) |

| 3. 완성도 (30%) | **4.3** | 정량 지표가 구조적으로 발생(3a=5) · 감사 로그가 곧 평가 데이터(3b=5) · 실패 내성이 주제 자체(3e=5) · 가시화 강함(3f=5) · 원클릭 배포는 별도 노력(3c=3) |

### 왜 1위인가
1. **교육 미션(NemoClaw + OpenShell)과 100% 정합.** G2를 가장 깊게 충족하는 유일한 후보
2. **정량 지표가 억지로 만들어지는 게 아니라 시스템에서 자연히 떨어진다.** 감사 로그가 곧 평가 데이터
3. **외부 데이터 승인 의존이 0.** G6 리스크 최소
4. 산출물(정책 템플릿 + 스킬)이 **재사용 가능한 부품** 형태 → 우승 상품인 "NVIDIA 공식 GitHub Recipe 등재"와 서사가 맞음

| 공격 시나리오 설계 품질이 결과를 좌우 | 시나리오 N종을 먼저 고정하고 시작 |

## 🥈 B. 공공 수거·배차 제약 최적화 에이전트

> **"민원 텍스트를 넣으면 제약조건을 뽑아내고, 경로를 다시 짜고, 얼마나 줄었는지 지도에 그린다."**

### 문제
지자체 폐기물 수거, 공공 차량 배차는 제약(시간창, 차량 용량, 민원 우선순위, 도로 통제)이 수시로 바뀌는데 경로 조정은 사람이 손으로 한다.

### 해결
```
① Constraint Agent
   민원/공지 자연어 → cuopt-numerical-optimization-formulation 스킬
   → 제약 · 결정변수 · 목적함수 추출

② Solver Agent
   cuopt-routing-api-python → VRP / PDP 해결

③ Explainer Agent
   cuopt-multi-objective-exploration → 파레토 프론티어
   → "거리 최소 vs 민원 우선" 트레이드오프 설명

전 과정을 OpenShell 샌드박스에서 실행, 외부 API 호출을 정책으로 제한
```

### 데이터
서울열린데이터광장(일반키 **호출 제한 없음**) + 기상청 단기예보(기상 제약, 자동승인) + KOSIS

### NVIDIA 스택 (5종)
`cuOpt` · `Nemotron 3` · `NeMo Agent Toolkit` · `OpenShell` · Agent Skills 4종

| **solve time** | CPU 솔버 | cuOpt GPU (배수) |
| **제약 추출 정확도** | — | 자체 골든셋 N건 기준 % |
| **SLA 위반 건수** | baseline | ours |

### 가시화
지도 위 **before/after 경로 오버레이** + 파레토 프론티어 곡선 + 차량별 간트 차트
