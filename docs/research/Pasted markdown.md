**# TradeSentry 개발계획**



작성일: 2026-09-23 KST. 상태: **\*\*개발 전 계획\*\***. 이 문서는 TradeSentry 구현 범위·계산·판정·평가의 진입점입니다. 기존 해커톤 후보 보고서는 과거 조사로 보존합니다. 현재 앱·데이터 파이프라인·NVIDIA 연동·성능평가는 구현/실행하지 않았습니다.



**\*\*권고:\*\*** \`고정 스냅샷 → 실제 제한 도구 조회 → 반증 검수 → 판단 수정 → 근거 검증\`을 먼저 완성합니다. 사용자가 기존 \`customs\_monthly\` 삭제를 확인했으므로 **\*\*공식 API 소범위 재수집·검증이 핵심 선행 작업\*\***&#xC785;니다. 데이터·HS10·NIM 도구 왕복·대회 적격성 관문을 통과해야 “실제 공개통계와 NVIDIA를 연결한 데모”로 제출합니다. 관문 미충족 상태에서 통제자료 데모를 실제 통계 성능으로 표현하지 않습니다.



**## 1. 확정 범위와 이번에 구체화하는 결정**



사용자 고정 범위는 HS85 내부 HS4 하나/HS6 3\~5개, HS6×상대국×월, 연속 24개월, 단위가치·상대국 점유율 두 신호, 검토 유지·모니터링·자료 보류입니다. 조사자와 Critic은 같은 Nemotron을 별도 문맥에서 사용합니다. 재조사 1회와 전체 도구 호출 8회, 개발20/평가40, 세 비교군을 유지합니다.



이 문서의 수치 임계값·시간 예산·구현 파일명·세부 일정은 **\*\*개발 제안\*\***&#xC774;며 아직 실행된 설정이 아닙니다. 결과를 본 뒤 평가에 유리하게 고치지 않고 개발 세트에서 확정합니다.



\| 기존 설계의 빈칸 | 구현 가능한 결정 |

\|---|---|

\| 추가 조회의 의미 | 외부 API 수집은 먼저 수행하고 동결합니다. 조사 중 도구는 SQLite 스냅샷에서 아직 제시되지 않은 세부 근거를 실제 조회합니다. 실시간 수집 성능으로 주장하지 않습니다. |

\| HS6 구성변화 | 해당 HS6의 **\*\*HS10\*\***&#xACFC; 부모 합계가 필요합니다. HS6끼리 비교하여 같은 HS6 내부를 설명했다고 쓰지 않습니다. |

\| 전체 점유율 분모 | 동일 기준의 공식 HS6 전체국가 합계를 별도로 확보할 수 있으면 일부 비교국만 조회해도 해당 국가/전체 비율을 계산할 수 있습니다. 선택국 합계를 전체로 쓰지 않습니다. |

\| 비교자료 부재와 설명 충돌 | 필요한 자료 부재는 보류, 필요한 비교를 수행했지만 변화가 설명되지 않으면 유지입니다. 코드/모델 실패는 실행 상태에 별도로 기록합니다. |

\| 숫자 검증과 결론 검증 | 코드가 수치·출처·필수 근거·허용 상태를 검사합니다. “원인 규명/위법성 정확성”을 보증하지 않습니다. |

\| 두 신호 동시 발생 | 신호별 결론을 보존하고 전체는 \`유지 > 보류 > 모니터링\` 순으로 집계합니다. 유지 근거가 성립한 신호가 하나라도 있으면 유지하면서 다른 신호의 자료 부족을 표시합니다. |

\| NVIDIA 구성 | NAT를 워크플로 실행·trace·평가에 사용합니다. 런타임 검증기와 사후 NAT 평가기는 별도입니다. |



**### 현재 확인 사실**



\- **\*\*2026-09-23 사용자가 \`customs\_monthly\` 삭제를 확인했습니다.\*\*** 기존 원본 재사용·복구를 일정의 전제로 두지 않고 공식 데이터를 새로 수집합니다. 제한된 경로 검색 결과와 과거 수집 기록은 [데이터 감사]\(research/tradesentry-data-audit.md)에 구분했습니다. 이번 계획 작업에서 복구나 재수집은 실행하지 않았습니다.

\- 2022·2023 PASS와 정수 천 USD/kg 단위는 **\*\*과거 기록\*\***&#xC785;니다. 현재 원본 검증 완료로 승계하지 않습니다. HS10 보유 증거는 없습니다.

\- 공식 국가·품목 API는 HS2/4/6/10, \`impDlr\` 달러, \`impWgt\` 순중량 kg를 명시합니다. 국가코드는 필수이고 요청 기간은 1년 이내이므로 24개월을 최소 두 구간으로 나누어야 합니다. 과거 collector의 천 USD 값과 별도 어댑터로 취급합니다. [관세청 API]\(https\://www\.data.go.kr/data/15100475/openapi.do)

\- 공식 품목별 API는 국가별 API와 구분되는 HS 품목 합계 자료입니다. 전체 분모 후보로 검토하되 실제 응답의 합계 의미·기간·단위는 첫 호출 때 확인합니다. [품목별 API]\(https\://www\.data.go.kr/data/15101609/openapi.do)

\- 현재 폴더는 Git 저장소가 아닙니다. 이번 작업은 계획·검토 문서만 추가하며 앱 구현이나 Git 초기화를 수행하지 않습니다.

**## 3. 데이터 확보를 작게 만드는 방법**



1\. 공식 API에서 HS6 하나·국가 하나·1개월을 먼저 호출해 서비스키·응답 스키마·단위·빈 응답 의미를 확인합니다. 새 수집 manifest와 읽기 전용 원본을 TradeSentry에 별도 저장합니다. 다른 곳에 collector 코드가 남아 있는지는 미확인이고, 이를 찾아야만 시작할 수 있는 계획으로 만들지 않습니다. 과거 PASS와 훅 상태를 새 자료의 검증 결과로 승계하지 않습니다.

2\. HS4 후보 선정은 거래 급변 크기를 보지 않고 자료 완전성, HS 연도별 정의, 중량 유효성, HS10 접근성으로 결정합니다. 품목명과 사유를 선정 manifest에 남깁니다. 현재는 자료가 없어 특정 HS4를 확정하지 않습니다.

3\. HS6 3\~5개·24개월을 핵심으로 확보하고, 비교국은 기준연도 거래 규모와 유효월 수로 고정한 3\~5개를 우선 사용합니다. 비교국을 당월의 유리한 결과를 보고 바꾸지 않습니다.

4\. 전체 점유율은 별도 공식 전체국가 분모가 있는 경우에만 산출합니다. 없으면 고정된 국가 집합의 \`수집 범위 내 비중\`을 화면에 구분하고, 전체 점유율 경보의 결론은 보류합니다. 국가 집합이 달라진 범위 내 비중은 직접 비교하지 않습니다.

5\. HS10은 HS85 전부를 수집하지 않습니다. 선택된 HS6·대표 경보의 대상국·비교월에 필요한 모든 하위 코드만 확보합니다. HS10 존재 목록은 기준연도별 분류표로 확인하며 앞자리 일치만으로 동일 정의를 가정하지 않습니다.

6\. 예선 평가 시점에는 필요한 자료를 동결합니다. 없는 자료를 도구가 만들어 채우지 않고 \`NOT\_COLLECTED\`, \`REQUEST\_FAILED\`, \`UNRESOLVED\_ZERO\`, \`CONFIRMED\_NO\_TRADE\`, \`OBSERVED\`를 구분해 반환합니다. 정상 빈 응답만으로 무거래 확정은 하지 않고 endpoint 의미·페이지/범위 완료를 확인합니다.



외부 수집 요청 수는 \`HS6 수 × 비교국 수 × 연도 구간 + 분모 조회 + 필요한 HS10 조회 + 페이지/재시도\`로 먼저 산정합니다. **\*\*에이전트 도구 8회 한도는 외부 수집 HTTP 횟수와 다른 지표\*\***&#xC785;니다. 두 수치를 각각 보존합니다.



최소 3개 HS6·3개국·2개 연도 구간이면 국가별 HS6 기본 요청은 **\*\*18개 논리 조회\*\***&#xC785;니다. 월별 원본 레코드는 최대216개 조합입니다. 실제 HTTP 수는 페이지·재시도·API 응답 방식에 따라 달라지며, 공식 전체 분모와 HS10 요청은 추가입니다. 먼저 이 작은 수집 경로를 검증하고 국가·품목을 늘립니다. HS4 선정에 필요한 후보 탐색 요청도 따로 기록합니다.

**## 4. 탐지와 반증 계산**



**### 4.1 경보 생성**



기준은 전년동월로 통일합니다. \`U\_t = V\_t / Q\_t\`, \`r\_U = U\_t/U\_(t-12)-1\`, \`s\_t=V\_country,t/V\_world,t\`, \`d\_s=s\_t-s\_(t-12)\`입니다. 점유율 차이는 퍼센트포인트로 표시합니다. 2022\~2023 24개월이면 전년동월 경보를 평가할 수 있는 월은 **\*\*2023년 12개월\*\***&#xC785;니다. 직전월은 보조 문맥이며 별도의 탐지 규칙을 추가하지 않습니다.



초기 개발 제안은 \`|r\_U|≥30%\`와 \`|d\_s|≥10pp\`입니다. 경제적 위험 경계가 아니라 시연 후보를 만드는 값입니다. \`min\_amount\`, \`min\_weight\`, 반올림 민감도, 허용잔차는 개발 자료의 단위/정밀도에 맞춰 고정합니다. 값이 정해지기 전에는 후보 계산을 완료했다고 기록하지 않습니다. 0/미상 기준은 증가율을 계산하지 않습니다.



경보가 없음과 경보를 설명하여 모니터링으로 낮춘 것을 구분합니다. 자료 미달로 탐지할 수 없는 행은 후보 목록에서 숨기지 않고 데이터 품질 목록에 둡니다.



**### 4.2 HS10 구성효과**



동일 HS10 집합의 양 시점 중량이 모두 유효하고 부모 합계가 맞을 때 아래 항등식을 씁니다.



\`\`\`text

u\_i,t = V\_i,t / Q\_i,t

w\_i,t = Q\_i,t / Σ\_i Q\_i,t       # 금액 비중이 아닌 중량 비중

U\_t = Σ\_i w\_i,t \* u\_i,t

ΔU = within\_effect + mix\_effect

within\_effect = Σ\_i ((w\_i,0+w\_i,1)/2) \* (u\_i,1-u\_i,0)

mix\_effect    = Σ\_i ((u\_i,0+u\_i,1)/2) \* (w\_i,1-w\_i,0)

\`\`\`



분해 잔차, 개별 하위품목 변화, 기여도 상쇄를 함께 반환합니다. 합계 within 효과가 작아도 일부 하위품목의 큰 상승·하락이 상쇄됐다면 \`구성변화만으로 설명\`이라 하지 않습니다. \`mix/ΔU\` 비율 하나만으로 판정하지 않으며 ΔU가 작으면 비율을 제시하지 않습니다.



5일 MVP에서는 신설/소멸 HS10의 존재를 식별하되 정의되지 않은 단위가치를 0으로 채워 분해하지 않습니다. 이 경우 완전한 구성 설명은 미확인으로 남깁니다. 모든 하위항목 유효성·부모 일치·개별 안정성까지 만족한 경우에만 모니터링 후보가 됩니다. 신설/소멸의 일반 귀속 모형은 이번 범위에서 제외합니다.



부모/하위 합계 허용오차는 원본 정밀도와 하위항목 수에서 정합니다. 예를 들어 최근접 정수 반올림이 확인되었다면 합계 가능한 오차를 계산할 수 있습니다. 반올림 방식이 미확인이면 임의 1% 허용으로 덮지 않습니다. 금액과 중량을 각각 검증합니다.



**### 4.3 상대국 비교**



동일 HS6/기간/단위/정의의 미리 정한 비교국에 대해 전년동월 단위가치와 비중 변화를 계산합니다. 비교국 수·유효월·제외사유를 반환하고 미수집 국가를 “변화 없음”으로 보지 않습니다. 다른 국가에서도 하락했다는 결과는 공통 설명의 후보이며 정상 거래나 시장가격 하락의 증명은 아닙니다.



점유율에서는 해당국 금액 변화와 전체 분모 변화를 함께 제시합니다. 분모 축소로 비중이 오른 사실은 **\*\*산술 설명\*\***&#xC774;며 업무상 중요성이 사라졌다는 뜻은 아닙니다. 5일 기본 정책에서는 유효한 점유율 급변이 남으면 검토 유지합니다. 잘못된 범위·단위·버전이 교정되어 같은 정책의 경보 조건에서 벗어난 경우에만 모니터링을 제안할 수 있습니다. 과거 snapshot은 보존합니다.



**## 5. 판정 계약과 실행 계약**



**### 5.1 신호별 판정**



\| 상황 | 처리 상태 | 반드시 남길 근거 |

\|---|---|---|

\| 필요한 월·단위·HS정의·분모·구성자료가 없어 주장 검증 불가 | 자료 보류 | 부족 항목, 실패/미수집 구분, 판단 가능한 범위, 필요한 다음 자료 |

\| 완전한 하위 자료에서 해당 단위가치 경보가 구성효과로 설명되고 개별 하위 변동·잔차도 기준 내 | 모니터링 | 부모 대조, 분해 수치, 하위 안정성, 비교조건, 해당 신호의 모니터링 사유 |

\| 자료 교정 후 동결 정책으로 재계산한 경보가 해소 | 모니터링 | 교정 전후 snapshot, 재계산 값, 변경 사유; 정상 확정 문구 금지 |

\| 필수 비교를 완료했지만 경보가 설명되지 않거나 설명이 충돌 | 검토 유지 | 잔존 변화와 검사한 대안 설명, 반대 근거, 미확인 원인 |

\| 다른 상대국도 비슷하게 변화 | 이 사실만으로 하향 불가 | 다른 확인을 계속 수행하고 최종 필수근거 충족 여부로 유지/보류 |

\| 작은 기준값·반올림 때문에 변화 방향/경보 충족 여부가 불안정 | 자료 보류 | 정밀도·유효범위·민감도; 작은 금액 자체를 정상 근거로 쓰지 않음 |



정책에 필요한 자료가 부족한데 “설명되지 않는다”는 이유만으로 유지하지 않습니다. 반대로 어떤 비교 자료든 하나 없다고, 이미 독립적으로 입증된 다른 신호의 검토 필요까지 지우지 않습니다. 케이스 전체 상태는 **\*\*모든 조사의 완결성\*\***&#xC774; 아니라 **\*\*담당자의 다음 업무\*\***&#xB97C; 나타내며, 신호별 결과를 보존한 뒤 1절 우선순위로 집계합니다. \`maintain + hold → maintain, unresolved\_evidence=true\`입니다. 모든 발동 신호가 모니터링 조건을 충족해야 전체 모니터링이 됩니다. 미발동 신호는 \`NOT\_TRIGGERED\`로 구분합니다.



**### 5.2 도구 계약**



공통 입력은 case\_id, snapshot\_id, 허용된 scope입니다. 공통 출력은 query\_id, 실제 scope, snapshot\_id, source\_kind, evidence\_ids, metrics, comparability, missingness, retryable\_error, elapsed\_ms입니다. DB 경로·임의 SQL·외부 URL·셸은 모델 인자로 받지 않습니다.



\| 도구 | 조회와 제한 |

\|---|---|

\| \`check\_comparability\` | 기간/요청완료/단위/HS버전/분모/하위자료의 존재 상태. 존재 여부와 내용 조회를 구분하며 정답 상태를 반환하지 않습니다. |

\| \`get\_history\` | 대상 HS6/국가의 24개월과 전년동월 비교. 페이지 대신 정해진 작은 결과 구조 및 원본 행 포인터를 반환합니다. |

\| \`compare\_partners\` | 사전 허용된 비교국·같은 HS/월/기준으로 조회. 분모의 종류와 미포함 범위를 표시합니다. |

\| \`decompose\_hs\` | 필요한 두 시점의 모든 HS10, 부모 대조, 중량비중 분해, 개별변화·상쇄·잔차·불가 사유. |

\| \`verify\_evidence\` | 이미 반환된 evidence/metric과 연결된 읽기 전용 snapshot 원본을 대조하여 수치·단위·원본행·출처·필수 근거·허용 상태를 검사합니다. 명시적 금지 문구도 검사합니다. 다른 4도구를 내부 재호출하거나 새 비교 근거를 생성하지 않으며 평가 정답 파일은 보지 않습니다. |



도구가 반환한 품목명·설명은 데이터로 취급하며 모델 지시문으로 실행하지 않습니다. 사실 문장은 typed claim과 evidence ID를 연결합니다. 숫자는 템플릿 렌더러가 검증된 metric에서 삽입하고, 모델의 설명/미확인 가설은 별도 필드에 둡니다. 이 구조에서도 자유문장의 인과적 타당성은 자동 보증하지 않습니다.



공개 정책의 \`이 주장을 하려면 이 근거가 필요하다\`는 조건은 런타임·세 비교군 모두 사용할 수 있습니다. 숨기는 대상은 사례별 예상 상태·생성 계열·평가 oracle입니다. 체크리스트가 숨겨진 시나리오 클래스를 알아서 순서를 선택하거나, validator가 정답 파일을 읽어 상태를 고치는 일은 금지합니다.



**### 5.3 8회 예산과 재조사 1회**



\`\`\`text

코드: 후보·case 생성

&#x20;→ check\_comparability [1]

&#x20;→ get\_history [2, 비교 가능할 때]

&#x20;→ 조사자: 다음 비교 선택 [기본적으로 2회 이내]

&#x20;→ 조사자: 근거 포함 초안

&#x20;→ Critic: 누락·반대 설명·비교조건 검수

&#x20;→ verify\_evidence [1회 예약]

&#x20;→ 필요한 경우 수정/재조회 한 번 [최대 2조회]

&#x20;→ verify\_evidence [최종 1회 예약]

&#x20;→ 코드 종료·검토서

\`\`\`



\`tool\_attempts ≤8\`입니다. 이는 5개 도구의 호출 시도 횟수로, 자동 검사·실패·동일 도구 재호출·캐시 적중·verify를 모두 포함합니다. 도구 내부의 순수 계산과 원본행 대조는 별도 도구 호출이 아니며, 다른 도구를 숨겨 재호출하지 않습니다. 기본 경로 최대5회, 재조회 최대2회, 최종검증1회입니다. 모델은 남은 횟수와 필수근거를 받지만 예산을 늘릴 수 없습니다. 비교불가가 이미 확정된 경우 이력/하위 조회를 생략하고 보류 보고서를 검증합니다.



Critic은 조사자가 이미 반환받은 근거와 초안만 검수하고 도구를 직접 호출하지 않습니다. 누락된 비교를 지적하거나 재조회 요청을 구조화해 반환하면, 조사자가 단일 수정 단계에서 실행합니다. Critic을 수정 후 다시 호출하지 않습니다.



\`재조사 1회\`는 Critic/코드 지적 후의 단일 수정 단계입니다. 그 안에서 최대2개의 제한 조회를 허용합니다. 최초 단계에서 잘못된 범위를 조회했으면 그 실패도 카운트하고 같은 예산에서 복구합니다. 동일 snapshot의 영구적 자료 부재를 같은 인자로 반복 조회하지 않습니다. **\*\*최초 초안의 schema 실패도 코드 지적에 포함\*\***&#xD569;니다. 이때는 Critic을 생략하고 남은 모델/도구 예산 안의 수정 단계 1회로 바로 진입합니다. schema 재생성과 필요한 재조회는 같은 단계에 묶으며 추가 수정 단계를 보장하지 않습니다. 다시 실패하면 \`INVALID\`로 종료합니다. 두 모델 비교군에 같은 규칙을 적용하고 Critic 생략 사유를 trace에 남깁니다. 숨은 형식 복구·SDK 자동 재생성을 두지 않습니다.



개발용 추가 상한 제안: \`model\_request\_attempts ≤10\`(재전송 포함), 사례 전체 wall time300초, 누적 입력+출력 토큰32,000입니다. **\*\*상한 중 먼저 도달한 것이 실행을 중단\*\***&#xD558;며, 10개 요청을 끝까지 보장하는 예산이 아닙니다. 요청별 timeout은 \`min(60초, 전체 deadline까지 남은 시간-종료기록 예약시간)\`로 설정하고 남은 시간이 없으면 요청하지 않습니다. 세부 provider 자동 retry는 끄며 명시적 모델 재전송은 모델 요청 횟수에만 포함합니다. 도구 8회에 모델 HTTP 요청을 섞지 않습니다. 도구는 로컬 snapshot만 조회하므로 외부 데이터 HTTP 요청은 사전 수집 단계의 별도 \`collection\_http\_attempts\`로 기록합니다.



실제 NIM 지연에 맞춰 개발 단계에서 이 상한과 종료기록 예약시간을 고정하고 세 방식에 같은 상한을 적용합니다. 로컬 종료기는 모델 timeout 뒤에도 실패 원인·누적 시도·마지막 정상 근거를 기록해야 합니다.



\`review\_status\`와 \`execution\_status\`를 분리합니다. 타임아웃/스키마 실패/코드 검증 실패/예산 소진으로 미완료인 실행은 \`FAILED/TIMEOUT/INVALID/BUDGET\_EXCEEDED\`로 남고 공유 승인할 수 없습니다. UI의 보류 안내와 평가의 정답 보류를 동일시하지 않습니다. 유효한 최종 보고서가 없으면 평가 성공이 아닙니다. 코드가 모델의 잘못된 상태를 조용히 정답으로 고쳐 성공 처리하지 않습니다.



**## 6. 승인·근거 변경**



공유용 검토서 승인만 모의로 구현합니다. 별도 계정/권한 시스템 대신 reviewer\_label, timestamp, report\_hash, evidence\_digest, snapshot\_id, policy\_version, code\_version을 기록합니다. 실제 기관 승인이나 통관 조치로 표현하지 않습니다.



핵심 의존성 목록을 기준으로 데이터·정책·수치·보고서가 바뀌면 기존 승인의 기록은 보존하고 유효 상태만 \`REVIEW\_REQUIRED\`로 바꿉니다. 승인 버튼 시점에도 현재 digest를 다시 대조하여 화면을 연 뒤 생긴 변경을 놓치지 않습니다. 과거 보고서와 변경 전후 값, 재검토 이유를 화면에서 확인할 수 있어야 합니다.

**## 8. 평가 설계**



**### 8.1 자료 분리**



실제 통계는 원본 대조·조건·재현·숫자·trace를 확인합니다. 정상/불법 정답을 만들지 않으며 아래 합성 처리정확도와 합산하지 않습니다. 통제자료 20/40은 검수 정책을 만족하는 다음 업무를 평가하는 별도 표입니다.



\| 통제 조건 | 개발 | 평가 | 사전 기대 처리/검사 |

\|---|---:|---:|---|

\| 하위 단위가치 고정, 구성비만 변화 | 3 | 6 | 모니터링; 합계 일치·중량비중·상쇄 검사 |

\| 구성효과 제거 후 잔존 변화 | 3 | 6 | 유지; 하위/비교국·잔차 증거 |

\| 비교국 동반변화, 구성설명 미성립 | 2 | 4 | 유지; 단순 동반 하락의 성급한 하향 방지 |

\| 단위·HS버전·하위합계 불일치 | 2 | 4 | 보류; 불일치 식별, 임의 허용오차 금지 |

\| 작은 기준/반올림 불확실/중량0 | 2 | 4 | 보류; 계산불가와 작은 거래의 구분 |

\| 정상 점유율 계산에서 잔존 급변 | 2 | 4 | 유지; 분모 산술설명만으로 하향 금지 |

\| 복구 가능한 잘못된 조회 범위 | 1 | 2 | 수정조회 후 원래 근거 기반 상태; 재조사1회 |

\| 두 신호의 판정이 다름 | 1 | 2 | 신호별 판정과 전체 우선순위 검증 |

\| **\*\*합계\*\*** | **\*\*20\*\*** | **\*\*40\*\*** | 각 기대 상태는 생성 전에 scenario spec에 명시 |



각 행의 2배 숫자 변형을 개발/평가로 나누는 방식은 금지합니다. 공통 업무 규칙은 공개하되 기초 수입 시계열·하위품목 구조·결측/교란 메커니즘·부모 원본 계열 ID 단위로 분할합니다. 같은 부모 원본이나 같은 템플릿의 규모/seed만 바꾼 사례는 한쪽에만 둡니다. 규칙을 구현하는 일반 계산 라이브러리는 공유 가능하지만 독립 oracle을 운영 코드 그대로 복사하지 않습니다.



각 scenario spec은 **\*\*두 신호 각각의 발동 여부·예상 상태·필수 근거와 전체 상태\*\***&#xB97C; 생성 전에 정합니다. 단일 신호 사례의 다른 신호는 \`NOT\_TRIGGERED\`로 구성합니다. 복합신호 사례에서만 의도적으로 다른 상태를 결합합니다. 따라서 구성변화 모니터링 사례가 실수로 점유율 급변 유지 조건까지 만족하지 않도록 생성 자료를 독립 검사합니다.



이 구성은 같은 정책 안의 제한된 구조 변화 시험이며 현실 분포 일반화 검증은 아닙니다. 60개의 구별 가능한 사례를 확보하지 못하면 그 사실과 실현한 개수를 표시합니다. 평가 뒤 부족한 성능을 보고 어려운 사례를 삭제하지 않습니다.



승인 무효화, 의도적 숫자/출처 변조, 8회 초과 차단, 모델 timeout 등은 별도 불변식 시험으로 둡니다. 이를 40개 성공 사례에 더해 처리정확도를 부풀리지 않습니다. 평가40에 자연스럽게 발생한 runtime failure는 그대로 실패로 남습니다.



**### 8.2 공정한 비교**



\| 방식 | 동작 | 공통 조건 |

\|---|---|---|

\| 고정 체크리스트 | 비교조건 → 이력 → 필요한 하위/비교국의 고정 순서 → 정책 기반 결과. 비교불가 조기종료 허용 | 같은 자료·도구·정책·검증기·8도구/시간 상한 |

\| Critic 없는 Nemotron | 조사자 선택과 근거 보고, 코드 검증 오류에 대한 동일한 1회 수정 기회 | 같은 model ID/설정·도구·상한·코드 피드백 |

\| 전체 TradeSentry | 조사자 + 분리 문맥 Critic + 같은 코드 검증과 1회 수정 | Critic 비용·토큰도 동일 전체 예산에 포함 |



체크리스트는 모든 도구를 무조건 끝까지 부르는 약한 상대가 아닙니다. 결정적인 조기종료와 동일 캐시 정책을 허용합니다. 필수 근거는 \`정확히 어떤 호출 순서를 썼는가\`가 아니라 \`검증에 필요한 정보를 얻었는가\`로 정의합니다. 도구 결과가 이미 필요한 근거를 포함하면 중복 호출을 요구하지 않습니다.



첫 평가: 40사례×3방식=120run. 순서는 교차/무작위로 배치하고 동일 warm snapshot을 사용합니다. 모델 없는 checklist의 토큰은 0으로 표시합니다. 재시도 포함 실제 tool 시도·LLM 요청·토큰·wall time·에러를 기록합니다. 모델 반복성은 여력이 있을 때 사전 고정한 공통10사례에 각 모델방식 2회 추가하고, 독립 표본수는 늘리지 않습니다.



동시성1·사례당300초 상한이면 120run의 보수적 순차 상한은 **\*\*10시간\*\***&#xC785;니다. 실제 예상시간은 모델 왕복과 개발 사례 trace로 재산정하여 평가 실행 시간을 확보합니다. 동시성은 할당량·실패율을 확인한 뒤에만 올리고 모든 모델 비교군에 같은 설정을 적용합니다. 시간이 부족하다고 40건의 실패·미실행을 분모에서 빼지 않습니다.



**### 8.3 지표와 합격 의미**



\`\`\`text

근거 충족 처리정확도 =

&#x20; (예상 상태 일치 AND 필수근거 AND 수치/단위 AND 출처/버전 AND 정상 실행) 사례 / 40



불필요 보류율 = 예상 비보류 사례 중 최종 보류 사례 / 예상 비보류 사례

잘못된 모니터링률 = 예상 유지/보류 사례 중 모니터링 사례 / 예상 유지/보류 사례

\`\`\`



상태별 혼동행렬, 실행 실패 수/40, 비교군 간 같은 사례의 개선·악화 목록, 도구수/모델토큰/시간의 중앙값·범위를 같이 제시합니다. 모델 원초안→Critic 후 제안→코드 검증 후의 상태를 구분해 복구와 악화를 기록합니다. Critic 전후 변화만으로 전체 구조의 성능 향상을 추정하지 않습니다.



미실행/timeout/invalid도 분모40에 포함됩니다. 실행 실패로 표시된 보류 화면은 기대 보류와 일치하더라도 성공이 아닙니다. 모든 사례를 보류하는 기준의 점수를 함께 제시하여 무기력한 보류의 한계를 드러냅니다.



**\*\*개발 완료 기준과 성능 우위는 다릅니다.\*\*** 세 분기·복구·예산·근거검증·승인 무효화가 재현되고 120run 표가 생성되면 평가 파이프라인 완료입니다. 전체 방식이 더 좋은지는 결과가 정합니다. 체크리스트보다 개선도 비용절감도 없으면 “이 범위에서 LLM 추가 가치 미확인”으로 보고합니다. 같은 모델 두 번 사용을 정확성 보증으로 표현하지 않습니다.

세 갈래 시연은 동일한 **\*\*합성\*\*** 초기 경보 \`-40%\`를 사용합니다. 아래 숫자는 설계용 oracle이며 통계 실행 결과가 아닙니다.



A/B/C 모두 단위가치 신호만 발동하도록 공식 전체 분모에 대응하는 합성 값과 해당국 금액을 함께 설계해 점유율 변화는 10pp 미만으로 둡니다. 예를 들어 해당국 금액/전체금액을 기준월600/6000, 비교월360/6000으로 두면 비중 변화는 -4pp입니다. C도 부모 HS6 수치는 동일하고 HS10 근거만 부족합니다.



\| 분기 | 기준월 | 비교월 | 기대 수치/행동 |

\|---|---|---|---|

\| A 구성변화 | 두 HS10의 U=(10,2), Q=(50,50), 부모 U=6 | U=(10,2), Q=(20,80), 부모 U=3.6 | -40%, within=0, mix=-2.4. 다른 필수조건 충족 시 모니터링 |

\| B 잔존변화 | A와 동일 | U=(6,1.2), Q=(50,50), 부모 U=3.6 | -40%, within=-2.4, mix=0. 비교조건 충족 후 검토 유지 |

\| C 자료누락 | A와 같은 초기 HS6 경보 | 필요한 HS10 응답 실패 | 실패를 0으로 채우지 않고 자료 보류 |



A/B/C를 실제 사건이라고 부르지 않습니다. UI에는 각 분기의 조회 이유, 실제 실행 도구, 반대 근거, 판정 전후, 원본행 링크를 보여줍니다.



처음 상태는 \`조사 전 경보\`로 고정합니다. 최종 검토 유지였다가 바뀐 것처럼 이력을 꾸미지 않습니다. 별도로 Critic이 잘못된 범위/근거 누락을 지적하고 실제 수정 조회가 발생한 사례를 1건 보여줍니다. 실패를 의도적으로 주입한 경우 주입 시험이라고 표시하며 자연 발생 실패처럼 말하지 않습니다.



실자료 사례는 확보 후 별도로 1\~3개를 보여주며 “2022\~2023 자료의 고정 시점 재조회”로 표시합니다. 단위가치 변화는 개별 판매가격, 원산지 조작, 위법성의 증거가 아닙니다.
