TradeSentry(관세청 수입통계에서 kg당 단가와 상대국 점유율이 전년 같은 달보다 크게 바뀐 경우를 경보로 잡고, 제한된 조회 도구로 반증을 시도해 담당자의 다음 업무를 제시하는 에이전트 시스템)는 도메인(책임 하나와 소유자 하나를 가진 기능 묶음)마다 앱을 따로 만든 뒤 조립한다. 여기서 앱은 혼자 실행하고 시험할 수 있는 단위이고, 조립은 따로 만든 단위들을 이어 CLI(명령줄 실행 도구 `tradesentry <명령>`) 명령 하나가 도는 묶음으로 만드는 일이다. 조립할 때 버릴 것과 합칠 것을 명시적으로 가린다. 이 방식은 사용자 결정이다 `[DESIGN: 사용자 결정]`.

**근거 태그.** `[사실]`은 직접 확인한 것, `[추론]`은 근거가 있는 판단, `[DESIGN]`은 팀 설계 규칙(대회 공식 규칙이 아니다), `[미확인]`은 검증하지 않은 것이다. 따로 적지 않은 규칙은 `[DESIGN]`이다.

## 1. 최소 단위의 기준

단위는 셋으로 나눠 센다.

| 형식 | 기준 | 개수 |
|---|---|---|
| 앱 | 아래 네 조건을 모두 채운다 | 54 |
| 커널 | 입출력 없이 정의만 모아 여러 단위가 import하는 공유 단위. 앱의 조건 2·3을 채우지 않으므로 따로 센다 | 1 |
| 구성 | 코드 진입 함수가 없는 설정·정책·프롬프트·명세·해시 목록·시험 스크립트 같은 파일 단위 | 9 |

앱의 네 조건:

1. **책임 하나**: 한 문장으로 말할 수 있는 일 하나만 한다.
2. **계약 객체 입출력**: 입력과 출력이 자료 계약(`docs/rules/DATA_CONTRACT_V1.md`. 두 트랙이 주고받는 객체·필드·값의 약속)의 객체나 정해진 파일이다.
3. **픽스처로 혼자 시험**: 다른 단위를 띄우지 않고 픽스처(시험용으로 미리 만든 고정 자료)만으로 돌리고 시험할 수 있다.
4. **소유 하나**: 모델 트랙(M: 판정 정책·조사 흐름·NVIDIA 연동·그룹핑), 데이터 트랙(D: 수집·지표·평가 자료·채점기), 공동 가운데 한 곳이 소유한다.

- 집계는 §3 표를 센 결과다 `[사실]`. 커널은 계약 타입(단위 K1) 하나이고, 다른 단위를 합칠 때 목적지가 된다.
- 단위를 세는 목적은 동시 작업과 조립 판단이다. 한 도메인 안에서도 단위 파일별로 동시에 작업하고, 조립 때 버릴 것과 합칠 것을 표로 가린다.

## 2. 단위 앱 규약

- **파일 하나**: 단위 하나가 파일 `{패키지}/{단위}.py` 하나다(자료 계약 §10.3 N3). 도메인명은 `{패키지}_{단위}`다(N4).
- **진입 함수**: 앱 단위는 진입 함수 `run(입력) -> 출력`을 둔다. 입력과 출력은 §3 표의 "입력 → 출력"과 같은 계약 객체나 파일이다.
- **머리 주석**: 파일 맨 앞 주석에 단위 ID, 소유, 입력, 출력, 허용 import(그 단위가 import해도 되는 패키지·단위 목록)를 적는다.
- **골든 시험 한 쌍**: 단위마다 `tests/units/{단위 ID}/`에 고정 입력과 기대 출력 한 쌍을 두고, `run`의 출력이 기대 출력과 같은지 본다. 네트워크와 키 없이 돈다.
- **경계 시험**: 단위 파일이 머리 주석의 허용 import 밖을 import하지 않는지, 독립 채점기(`eval/scorer/`)가 `tradesentry` 패키지(등록부·커널 포함)와 `eval/datagen`을 직접이든 간접이든(그것들을 부르는 모듈을 거쳐) import하지 않는지, dev20 생성 도구(단위 V2)가 `metrics/`·`policy/`와 그것들을 부르는 모듈을 직접이든 간접이든 import하지 않는지를 코드를 실행하지 않고 import 문만 읽어 확인하는 시험이다.
- **등록부·공통 실행기**: `src/tradesentry/units/`에 단위 ID와 진입 함수의 대응표(등록부)와 공통 실행기를 둔다. 실행은 `python -m tradesentry.units <단위 ID> --in <입력 파일>`이고 개발 전용이다. 단위를 혼자 돌리면 실행 이름은 그 단위의 도메인명이고, 출력은 이름·출력 규칙대로 `outputs/{실행명}/`에 쓴다(N5·N6).
- **S0가 뼈대를 만든다**: S0는 이 표로 패키지와 단위 파일의 뼈대(머리 주석과 빈 `run`), 등록부, 공통 실행기, 골든 시험 틀, 경계 시험을 만든다. 저장소 밖 봉인 폴더에서만 만드는 단위 V3·V6은 뼈대를 만들지 않고 등록부에도 넣지 않는다. 구성 단위는 진입 함수 뼈대 없이 위치만 잡는다.
- **채점기 독립**: 독립 채점기는 등록부·커널을 포함해 `src/tradesentry/` 아래 어떤 패키지도 import하지 않는다(룰북 `docs/eval/RULEBOOK.md` B3, 자료 계약 §10.3). 간접 import(런타임 패키지를 부르는 모듈을 거쳐 부르는 경우)도 금지이고, `eval/datagen`도 import하지 않는다. 계약 상수가 필요하면 채점기 안에 따로 적는다.
- **지표 단위를 보지 않는 실행자**: 채점기, dev20 정답표, dev20 생성 도구(`eval/datagen`, 단위 V2)는 지표 단위 구현자와 다른 실행자가 `metrics/` 아래 어느 단위도 보지 않고 만든다(로드맵 `docs/plan/ROADMAP.md` DT5·DT8).
- **구성 단위**: 진입 함수가 없다. 그 단위를 맡은 작업(로드맵 §2)의 검사로 확인한다.
- **새 이름 다섯 개**: `contract`(공유 커널: 계약 타입·근거 ID·정책 수치 읽기·도구 봉투 키), `snapshot`(스냅샷 빌드·검증과 합성 스냅샷 생성), `runlog`(trace·실행 결과 기록·원인 분류 코드), `units`(등록부와 공통 실행기. 물리 단위나 표시 자릿수와 관계없다), `eval/datagen`(평가 자료 도구. holdout40 생성 코드는 두지 않고 봉인 폴더에만 둔다)이다. 뜻과 경계의 정본은 자료 계약 §10.3이다.

## 3. 단위 표

- 64행이다. 판정 집계는 유지 44, 합침 후보 10, 버림 후보 1, 런타임 밖 9이고, 형식 집계는 앱 54, 커널 1, 구성 9다 `[사실: 이 표를 센 결과]`.
- **조립 판정 열은 후보다.** 조립 점검(§5)에서 확정하고, 확정한 판정으로 이 표를 고친다. "합침 후보(→ X)"의 X가 합칠 대상이다. "런타임 밖"은 수집·합성·평가 자료 도구처럼 런타임 조립에 들지 않는 단위다(§6).
- **동결 경로 열**의 "예"는 `RB-1`(평가 룰북의 첫 동결 버전) 전에 끝내야 하는 판정 정책·검증기 단위다. 이 단위들의 합치기는 조립 점검 작업 AS4에서만 하고, MVP(최소 기능 제품) 시험 뒤에는 건드리지 않는다(§7).
- **비고의 "고정 규칙과 충돌"**은 조립 판정을 그대로 따르면 이미 정한 규칙과 부딪치는 단위다. 판정을 바꾸려면 그 규칙의 절차(사용자 승인 등)를 거친다.
- **도메인명 "없음(구성)"**은 출력 파일을 내지 않는 구성 단위다. 위반 시험(단위 F7)은 구성 단위지만 시험표를 내므로 도메인명이 있다.
- **ID가 다른 문서와 겹친다.** 단위 ID는 이 표 안의 번호다. 로드맵 작업 ID(`X1` 세로형 최소 통합 시험, `V1` MVP 시험, `F1` 룰북 동결, `F2` 봉인 묶음 채점, `R1` 결과표, `P1`~`P3` 제출 준비), 룰북 절 번호(A1·A2 등), 채점 규범 게이트(G1~G6)와 글자가 같다. 그래서 다른 문서에서는 로드맵의 "맡는 단위" 열을 포함해 "단위 V1"처럼 앞에 "단위"를 붙인다. 로드맵 작업 X1과 단위 X1(단가·변화율)도 다른 것이다.
- 조립체 열의 번호는 §4의 조립체다. "공유"는 모든 조립체가 import하는 계약 커널·자료 접근, "CLI"는 CLI 조립 층이다.

## 5. 조립 점검 절차

조립 점검은 버릴 것과 합칠 것을 확정하는 절차다. 조립 작업 AS4가 이 여섯 단계를 차례로 한다. AS1~AS3은 자기 조립체에 대해 1·2·5단계를 먼저 돌려 둔다.

1. **정적 import 그래프**: 단위 파일의 import 문을 모아 그래프를 만든다. 머리 주석의 허용 import와 다른 곳, 순환 import, 채점기가 `tradesentry` 패키지를 import하는 곳을 찾아 고친다. 경계 시험과 같은 검사다.
2. **MVP 실행 커버리지**: MVP 시험(로드맵 §3)이 쓰는 명령(`detect`, `run-case`, `evaluate`, 채점기)을 합성 시험자료와 dev20으로 돌려 단위마다 실제로 불렸는지 확인한다. 확인 방법(trace 사건, 시험 커버리지 도구)은 AS4가 정해 결정 기록에 적는다. 불리지 않은 단위는 버림 후보로 올린다. 런타임 밖 단위는 이 단계에서 세지 않는다.
3. **합칠 쌍 찾기**: "합침 후보"인 단위와 합칠 대상이 여전히 같은 입력을 받고, 같은 명령 묶음 안에서만 불리고, 소비자가 하나인지 본다. 그렇지 않으면 유지로 되돌린다. 새로 보이는 합칠 쌍은 후보로 더한다.
4. **고정 규칙 충돌 검사**: 버리거나 합치려는 단위가 이미 정한 규칙(동결 경로, 채점의 대체 기본값 `g0`, 자문 명세서(`docs/plan/SCAFFOLD_BRIEF.md`) §5.1 고정 사항, 로드맵 §5 줄이는 순서)에 걸리는지 본다. 걸리면 판정을 유지로 되돌리거나 사용자 승인 대상으로 올린다. 동결 경로 단위의 합치기는 AS4에서만 한다.
5. **동작 불변 확인**: 합치거나 버린 뒤 골든 시험·경계 시험과 해당 CLI 명령의 조립 시험(픽스처로 명령을 처음부터 끝까지 돌려 기대 출력과 비교하는 시험)이 전과 같이 종료 코드 0이고 같은 출력을 내는지 본다. 출력 파일의 도메인명이 단위 표 그대로인지도 본다(자료 계약 §10.3 N4).
6. **결정 기록**: 버린 것, 합친 것, 유지한 것과 이유, 검사 명령과 종료 코드를 결정 기록에 남기고 §3 표의 판정 열을 고친다.

## 6. 합침·버림·유지 기준과 조립 부산물

**판정 기준**

| 판정 | 기준 |
|---|---|
| 유지 | 책임이 따로 있고 소비자가 둘 이상이다. 또는 고정 규칙이 그 단위를 요구한다(동결 경로, 채점의 대체 기본값 `g0` 등) |
| 합침 | 같은 입력을 받고 같은 명령 묶음 안에서만 불리며 소비자가 하나다. 합칠 대상(소비자)의 파일로 합친다. 계약 정의(키 목록·상태값·정책 수치 읽기 등)는 커널(단위 K1)로 모은다. 합쳐도 도메인명과 출력 파일 이름은 바꾸지 않는다(자료 계약 §10.3 N4) |
| 버림 | MVP 실행 경로에서 불리지 않고, 고정 규칙이 요구하지 않는다. 로드맵 §5 줄이는 순서가 정한 대상(화면)은 그 순서가 발동할 때만 버린다 |
| 런타임 밖 | 수집·합성·평가 자료 도구처럼 런타임 조립에 들지 않는다. 조립 점검에서 버리지 않고, 맡은 작업의 검사로 따로 확인한다 |

**조립 부산물 버림 목록**(조립을 마치면 지운다)

1. **공통 실행기의 제품 노출**: `python -m tradesentry.units`는 개발 전용이다. CLI 명령, 런타임 스킬, 샌드박스 정책에서 부르지 않는다.
2. **임시 대역**(stub: 진짜 자료나 단위 대신 정해진 값을 돌려주는 가짜 함수): 시험 파일 밖에 남은 것을 지운다.
3. **단위 사이 중간 파일**: 단위를 혼자 돌리며 넘겨 주던 중간 파일. 조립 뒤에는 함수 호출로 넘기고, 이름·출력 규칙의 도메인 출력(자료 계약 §10.3 N6)만 남긴다.
4. **복사된 계약 상수**: 상태값·키 목록 같은 계약 상수를 단위마다 복사해 둔 것은 커널(단위 K1)에서 import하게 바꾼다. 예외는 채점기의 사본이다. 채점기는 런타임을 import하지 않는 독립 구현이라 사본을 남긴다.
5. **X1 임시 코드**: `spikes/x1/`의 코드는 앱에 섞지 않는다. 앱에 옮겨 온 흔적이 있으면 지운다.
6. **`inference.local` 경로**: X1에서 키 주입 방식으로 채택하지 않은 경로(`inference.local`, 게이트웨이가 샌드박스에 주는 관리형 추론 주소)를 쓰는 코드와 설정. 채택 결과의 근거는 X1 PR의 결정 기록이다.

## 용어 설명

- **TradeSentry**: 관세청 수입통계의 단가·점유율 급변 경보를 Nemotron(NVIDIA 언어 모델) 조사자와 검수자(Critic)가 반증 검수해 담당자의 다음 업무를 제시하는 에이전트 시스템. 부정·위법 판정 시스템이 아니다.
- **도메인**: 책임 하나와 소유자 하나를 가진 기능 묶음. 이 문서에서는 패키지 하나가 도메인 묶음 하나다.
- **패키지**: 파이썬 모듈 파일을 여럿 담는 폴더(예: `src/tradesentry/metrics/`).
- **단위**: 혼자 실행하고 시험할 수 있게 파일 하나로 만든 가장 작은 구현 조각. 형식은 앱·커널·구성이다(§1).
- **앱 / 커널 / 구성**: 네 조건을 채우는 실행 단위 / 정의만 모은 공유 단위 / 진입 함수가 없는 설정·명세 파일 단위.
- **도메인명**: 단위마다 붙인 출력용 이름 `{패키지}_{단위}`. 출력 파일 이름의 앞부분이 되고, 조립 때 합쳐도 바꾸지 않는다.
- **실행 이름 / 실행명(`run_id`)**: 시각이 붙지 않은 실행의 이름(예: `run_case`) / 실행 이름에 시작 시각을 붙인 `{실행 이름}-{yymmddhhmmss}`. 실행 폴더 `outputs/{실행명}/`의 이름이다(자료 계약 §10.3 N5).
- **조립 / 조립체 / CLI 조립 층**: 따로 만든 단위를 이어 명령 하나가 도는 묶음으로 만드는 일 / 그렇게 만든 묶음(§4) / CLI 명령을 받아 조립체를 부르는 배선 단위.
- **조립 판정 후보**: 유지·합침 후보·버림 후보·런타임 밖 가운데 지금 예상한 판정. 조립 점검에서 확정한다.
- **조립 점검**: 버릴 것과 합칠 것을 확정하는 여섯 단계 절차(§5). 작업 AS4가 한다.
- **골든 시험**: 고정 입력과 기대 출력 한 쌍으로 단위의 출력이 바뀌지 않았는지 보는 시험.
- **경계 시험**: 단위가 허용 import 밖을 import하지 않는지, 채점기가 `tradesentry` 패키지와 `eval/datagen`을 직접이든 간접이든 import하지 않는지, dev20 생성 도구(단위 V2)가 `metrics/`·`policy/`와 그것들을 부르는 모듈을 직접이든 간접이든 import하지 않는지 import 문만 읽어 확인하는 시험.
- **조립 시험**: 픽스처로 CLI 명령 하나를 처음부터 끝까지 돌려 기대 출력과 비교하는 시험.
- **등록부 / 공통 실행기**: 단위 ID와 진입 함수의 대응표 / 등록부로 단위 하나를 혼자 돌리는 개발 전용 명령 `python -m tradesentry.units <단위 ID> --in <입력 파일>`.
- **픽스처**: 시험용으로 미리 만든 고정 자료.
- **임시 대역(stub)**: 진짜 자료나 단위 대신 정해진 값을 돌려주는 가짜 함수.
- **동결 경로**: `RB-1` 동결 전에 끝내야 하는 판정 정책·검증기·채점기·룰북 개정. 이 표에서는 판정 정책·검증기 단위에 "예"를 적었다.
- **`RB-1`**: 평가 룰북의 첫 동결 버전.
- **MVP 시험**: 2026-09-25(금) 오후에 전체 경로가 최소 범위로 끝까지 도는지 보는 중간 시험(로드맵 §3).
- **S0 / X1**: 앱 뼈대를 만드는 첫 작업 단위(외부 자문 체크포인트) / 구현 첫날의 세로형 최소 통합 시험. 단위 X1(단가·변화율)과 다르다.
- **모델 트랙(M) / 데이터 트랙(D)**: 판정 정책·조사 흐름·NVIDIA 연동·그룹핑을 맡는 트랙 / 수집·지표·평가 자료·채점기를 맡는 트랙.
- **독립 채점기**: 런타임 코드를 import하지 않고 따로 만든 정답 대조 채점 프로그램(`eval/scorer/`). 샌드박스 밖에서 돈다.
- **봉인 폴더**: 개발 중 보지 않도록 평가 자료를 두는 저장소 밖 폴더(`TRADESENTRY_SEALED_DIR`, 기본값 `~/.tradesentry/sealed/`).
- **격리된 생성 에이전트**: 대화 문맥을 물려받지 않고 봉인 자료만 만들어 봉인 폴더에 쓰는 Claude 보조 에이전트.
- **trace**: 실행 중 호출과 응답을 순서대로 남긴 기록.
- **NAT / NIM / OpenShell**: NVIDIA 에이전트 실행 추적·프로파일·평가 도구 모음 / NVIDIA 클라우드 추론 API / 에이전트를 격리해 돌리는 NVIDIA 샌드박스 런타임.
- **`inference.local`**: OpenShell 게이트웨이(샌드박스 밖에서 정책을 적용하고 요청을 중계하는 구성요소)가 샌드박스에 주는 관리형 추론 주소.
- **승격(무거래 확정)**: 승인된 `policy_v1` 규칙으로 빈 응답 달의 `UNRESOLVED_ZERO` 행을 무거래 확정 `CONFIRMED_NO_TRADE`로 바꾸는 일. 단위 S2가 파생 SQLite에만 적용한다(자료 계약 §3.4). 이 문서에서 "승격"은 이 뜻으로만 쓴다.
- **증거 복사 / 커밋 사본**: 실행 폴더와 같은 이름의 폴더를 `artifacts/{종류}/` 아래에 만들고, 종류마다 정한 커밋 증거 파일만 복사해 커밋하는 일 / 그렇게 커밋한 폴더와 파일. trace는 빼고, 봉인 묶음은 금지 해제 조건(자료 계약 §10.3 N10)이 채워진 뒤에만 한다(자료 계약 §10.3 N11).
