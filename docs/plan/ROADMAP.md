TradeSentry(관세청 수입통계에서 kg당 단가와 상대국 점유율이 전년 같은 달보다 크게 바뀐 경우를 경보로 잡고, 제한된 조회 도구로 반증을 시도해 담당자의 다음 업무를 검토 유지·모니터링·자료 보류 중 하나로 제시하는 에이전트 시스템)의 구현을 날짜별로 어디까지 끝내야 하는지 정한 문서다. 구현은 모델 트랙(M: 판정 정책·조사 흐름·NVIDIA 연동·유사도 그룹핑)과 데이터 트랙(D: 수집·지표·합성과 평가 자료·채점기)이 동시에 진행한다. 이 문서는 두 트랙의 작업 목록과 순서, 작업별 실행자·검토자, 2026-09-25(금) MVP 합격 체크리스트, 시간 예산, 줄이는 순서, 사용자 확인 항목, 위험과 대체 경로를 한곳에 담는다. 부정·위법 판정을 하는 시스템이 아니며, 이 로드맵의 어떤 작업도 그런 판정을 만들지 않는다.

## 요지

1. 2026-09-24(목)에 S0 앱 스캐폴딩(프로젝트 뼈대를 만드는 첫 작업 단위, 외부 자문 체크포인트)과 X1 세로형 최소 통합 시험(NemoClaw 에이전트부터 차단 로그까지 한 줄로 이어진 최소 경로를 한 번에 통과시키는 시험)을 병렬로 시작한다. S0가 `main`에 병합되면 두 트랙이 갈라져 동시에 움직인다.
2. 2026-09-25(금)의 MVP 시험(전체 경로가 최소 범위로 끝까지 도는지 보는 중간 시험)은 §3의 9개 항목으로 판정한다. 그 전 오전에 조립 작업 AS1~AS4(단위별로 따로 만든 앱을 CLI 명령으로 잇고, 버릴 것과 합칠 것을 확정하는 작업)를 끝낸다. MVP 시험은 조립 점검(AS4) 병합 직후 시작하고, 첫 실행에서 실패한 항목은 2026-09-26(토) 11:00까지 고친다. 범위는 줄이지 않는다(결정 기록 `docs/tracking/decisions/20260924-2315-user-decision-impl-plan-approval.md` D7).
3. 룰북 `RB-1`(평가 룰북의 첫 동결 버전)은 2026-09-26(토) 18:00(조정값)에 동결한다(2026-09-25(금) 사용자 결정 11로 12:00에서 늦췄다. 순서는 MVP 수정 → 탐지·CLI 코드 동결 → holdout40 생성·봉인 해시 등록 → 동결). 봉인 자료(holdout40과 `real_sealed`) 채점 대상 실행은 목표 2026-09-26(토) 20:00 `[추론: 옛 목표(동결 두 시간 뒤)를 같은 간격으로 옮겼다]`, 늦어도 2026-09-27(일) 06:00에 시작하고, 한 번만 채점한다.
4. 일정이 밀리면 승인 불변식 시험 → 같은 사례 반복 실행 → 화면 3번째 → 화면 2번째 순으로 줄인다. 대표 지표(`real_sealed`), holdout40 비교군 3개 실행, OpenShell 증거, 유사도 그룹핑(`g1`)은 끝까지 지킨다. (2026-09-26(토) 08:10 사용자 결정으로 `g1`은 `g0` 대체 선언. 2026-09-25(금) 사용자 결정 11의 D10이 허용한 경로, 결정 기록 `docs/tracking/decisions/20260926-0810-user-decision-rb1-g0-substitute-and-prose-ex2.md`)
5. 사용자 확인 항목(§6)이 늦어지면 그 항목에 기대는 작업만 멈춘다. `policy_v1`(동결 판정 정책) 승인이 늦으면 봉인 묶음 생성(DT6, DT7)과 `RB-1` 동결(F1)이 함께 밀리므로 가장 먼저 챙긴다.

## 0. 이 문서를 읽는 법

### 0.1 근거 태그와 기본값

- `[사실]`: 직접 확인한 것. 저장소 파일이면 파일과 절을 적는다.
- `[추론]`: 근거가 있는 판단.
- `[DESIGN]`: 팀 설계 규칙. 대회 공식 규칙이 아니다.
- `[미확인]`: 검증하지 않은 것.
- 이 문서의 날짜·작업·순서는 2026-09-23(수) 설계 세션에서 사용자가 확인한 결정과 병합된 규칙 문서를 옮긴 것이다. 그래서 따로 적지 않은 문장은 `[DESIGN]`이다. 결정의 원천은 "명세"(이번 문서 실행의 정본 명세. 저장소에 커밋하지 않는 계획 문서이며, 결정과 이유는 `docs/plan/DEV_PLAN.md` §13 결정 기록에서 확인한다)의 §3.7이다.
- 병합된 문서가 정하지 않은 빈칸을 이 로드맵이 채운 곳은 `[DESIGN: 로드맵 배정]`으로 따로 표시한다. 검토자가 한눈에 찾아 받아들이거나 고칠 수 있게 하려는 것이다.
- "조정값"은 지금 정한 출발값이다. 정해진 절차로만 바꾸고, 바꾸면 결정 기록에 남긴다.

### 0.2 이 문서의 ID

- 구현 작업 ID는 다음과 같다. 접두사 `DT`·`MT`·`AP`는 분담 문서의 결정 번호 "분담 D0~D12"와 헷갈리지 않게 붙였다.
  - 공통: `S0`(앱 스캐폴딩), `X1`(세로형 최소 통합 시험)
  - 데이터 트랙: `DT1`~`DT8`
  - 모델 트랙: `MT1`~`MT7`
  - 통합·평가·제출: `V1`(MVP 시험), `F1`(`RB-1` 동결), `F2`(봉인 묶음 채점 대상 실행과 정답 대조 채점), `U1`(화면), `AP1`(승인 불변식 시험), `R1`(결과표), `P1`(README·재현 묶음), `P2`(공개 방식 결정), `P3`(제출 문서)
  - 조립: `AS1`(탐지 조립), `AS2`(사례 조사 조립), `AS3`(평가 실행·채점 연결), `AS4`(조립 점검). 단위(혼자 실행하고 시험할 수 있게 파일 하나로 만든 가장 작은 구현 조각)별로 따로 만든 앱을 이어 CLI 명령으로 만들고, 버릴 것과 합칠 것을 확정하는 작업이다(`docs/plan/UNITS.md` §7)
- 다른 문서의 ID에는 출처를 붙인다. 예: "규범 G4"(채점 규범의 재현 가능성 게이트)와 "구 개발계획 G4"(NIM 도구 왕복 관문 시험)는 다른 것이다. "분담 D6"은 분담 문서의 합성 시험자료 우선 넘기기 결정, "룰북 부록 12번"은 룰북 부록 표의 12번 행이다.
- 단위 표 `docs/plan/UNITS.md`의 단위 ID(`S1`~`S4`, `K1`~`K5`, `X1`~`X4`, `P1`~`P5`, `G1`~`G3`, `I1`~`I13`, `R1`~`R4`, `F1`~`F7`, `A1`·`A2`, `E1`~`E4`, `V1`~`V7`, `C1`~`C4`, `L1`~`L3`)에는 이 문서의 작업 ID(`X1`, `V1`, `F1`, `F2`, `R1`, `P1`~`P3`)와 글자가 같은 것이 있다. 그래서 이 문서는 단위를 "단위 V1"처럼 앞에 "단위"를 붙여 가리킨다. §2 표의 "맡는 단위" 열도 같다.
- "채점 대상 실행"은 OpenShell 샌드박스 안에서 TradeSentry CLI로 사례를 돌려 보고서를 만드는 실행이다. "정답 대조 채점"은 샌드박스 밖 독립 채점기가 그 결과를 정답·원본과 비교하는 일이다. 두 말을 섞어 쓰지 않는다.

   - 증거: 시험 명령(S0에서 정한 가상환경의 시험, 또는 `python3 -m unittest discover -s tests -v`)의 종료 코드 0과 비밀값·로컬 경로 검사(NVIDIA API 키 접두어, 공공데이터포털 서비스키 요청 파라미터, 로컬 절대경로를 찾는 검사. 실제 패턴 문자열은 검사 스크립트에만 두고 문서에는 적지 않는다)의 종료 코드 0. 검사 명령은 `python3 scripts/secret_scan.py`(추적 파일 전체)와 `python3 scripts/secret_scan.py origin/main..HEAD`(그 브랜치 커밋의 추가 행)이다.

**판정 규칙**

- 9개 항목이 모두 통과해야 MVP 합격이다. 항목마다 명령·종료 코드·산출물 경로를 증거로 남긴다. 에이전트의 자기 보고는 증거가 아니다(운용 규칙 §7).
- MVP 시험은 조립 점검(AS4) 병합 직후 시작하고, 첫 실행에서 실패한 항목은 2026-09-26(토) 11:00까지 고친다. 범위는 줄이지 않는다(결정 기록 2315 D7).
- 이월 뒤에도 1번(끝까지 가는 경로)이 통과하지 못하면 자기채점의 규범 G6(완주 가능성 게이트)이 FAIL이 된다(룰북 A1).

### 4.2 재전송과 재실행

- **재전송**(한 실행 안에서 같은 모델 요청을 다시 보내는 것): NIM의 HTTP 5xx(서버 오류 응답)와 HTTP 429(호출 한도 초과)는 요청당 최대 3회, 대기 5·10·20초의 지수 대기(조정값)로 명시 재전송한다(2026-09-25(금) 15:52 사용자 결정, 결정 기록 `docs/tracking/decisions/20260925-1552-user-decision-429-retry.md`). 응답에 `Retry-After`(다시 시도할 때까지 기다릴 시간을 알려 주는 응답 헤더)가 있으면 대기는 max(지수 대기, min(`Retry-After`, 60초))이고 횟수는 그대로다(2026-09-25(금) 22:22 사용자 결정 ④, 결정 기록 `docs/tracking/decisions/20260925-2225-user-decision-code-boundaries.md`. 규칙의 정본은 개발 플랜 `docs/plan/DEV_PLAN.md` §6.6·§6.7). provider(모델 호출 클라이언트)의 자동 재시도는 끈다. 재전송은 모델 요청 10회 한도에 세지 않고, 요청당 3회와 사례당 300초로만 묶는다(2026-09-25(금) 18:05 사용자 결정, 결정 기록 `docs/tracking/decisions/20260925-1805-user-decision-retry-budget.md`). NIM 무료 키에서 HTTP 500이 간헐적으로 난다 `[사실: TRADESENTRY_FACTS_MEMO.md §5]`.
- **재실행**(실행 하나를 처음부터 다시 돌리는 것): 룰북 B5의 인프라 실패 재실행 규칙을 따른다. `RB-1` 동결 때 사용자가 확인하는 항목이다(룰북 부록 23번, §6.2).
  - 조건: `execution_status`가 `FAILED`이고 원인이 모델 제공자 쪽 오류(재전송 한도를 다 쓴 HTTP 5xx, 재전송 한도를 다 쓴 HTTP 429, 연결 실패)뿐인 실행. 다른 4xx가 있으면 대상이 아니다. 원인 분류 코드로 적은 정본은 룰북 B5다.
  - 조건을 채운 실행은 모두 같은 설정으로 1회 재실행한다. 첫 실행이 모두 끝난 뒤, 첫 실행과 같은 순서로 돌린다.
  - `TIMEOUT`·`INVALID`·`BUDGET_EXCEEDED`와 모델 출력 문제는 재실행하지 않는다. 원래 기록은 지우지 않는다.
- **재실행 여유**: 2026-09-27(일)을 NIM 오류 재실행 여유 시간으로 둔다.

### 4.4 늦어질 때의 보고

- 동결이나 실행이 늦어지면 끝난 만큼만 보고하고 미완료 사실을 표시한다(룰북 B3-3 A등급 주장 조건).
- `real_sealed`: 조건을 못 채우면 A등급 대표 주장을 보류하고, 실제 건수·신뢰구간·미완료 사실과 함께 참고치로만 보고한다.
- holdout40: 실행이 다 끝나지 않으면 끝난 부분만 실패 집계와 함께 보고한다. 분모는 40 그대로 두고 미실행 건은 실패로 센다. 미완료 부분에 대한 주장은 하지 않는다.
- `RB-1` 동결이 늦어지면 늦어진 사실을 결과 요약에 적는다(룰북 B6).
- 승인(`policy_v1`, 공용 약속 변경)이 늦어져 MVP 시험이나 `RB-1` 동결이 위험해지면 오케스트레이터가 그 사실을 승인 요청에 적는다(병렬 규칙 §4.3).
- 결과 요약에는 실행 기간(KST), 동시성, 순서 seed, 재실행 건수를 적는다(룰북 B7).

### 6.4 생기면 바로 올리는 결정

미리 시한을 정할 수 없고, 일이 생기는 즉시 오케스트레이터가 사용자에게 올리는 항목이다.

- [ ] **공용 약속 변경 승인(발생 시)**: 자료 형식(계약 필드), 상태값, 기준값, 도구 한도, 품목·국가 확정, 평가 구성, 제출서 주장 문구를 바꿀 때. 절차는 계약 버전 올림 → 합성 시험자료 재생성 → 양 트랙 검토 → 사용자 승인이다(병렬 규칙 §4.2).
- [ ] **S0 자문 대기가 2026-09-24(목) 안에 끝나지 않을 때**: 뼈대와 무관한 작업(예: MT6 `g1`과 그 입력인 단위 G3)을 먼저 착수할지.
- [ ] **X1에서 두 키 주입 방식이 모두 실패할 때**: 우회하지 않는다(샌드박스에 키를 넣지 않는다). 대안의 예와 그 대가는 §7.1에 있다.
- [ ] **Brev 단계도 시한을 넘겼고 원인이 NemoClaw 구간이 아닐 때**: OpenShell 게이트웨이 자체, NAT 실행 추적, 감사 로그가 원인이면 OpenShell만 단계로는 풀 수 없다. 우회하지 않고 즉시 사용자 결정을 받는다(§7.1). 로컬 X1 단계에서는 원인과 무관하게 먼저 Brev로 옮기고, 원인이 NemoClaw 밖이면 그때 알리기만 한다(단, 키 주입 두 방식이 모두 실패한 경우와, 기본 블록을 빼거나 좁힌 정책으로도 시연 샌드박스가 요건 (b)를 채우지 못한 경우는 §7.1 "따로 다루는 두 경우"대로 즉시 사용자 결정).
- [ ] **시연(NemoClaw) 샌드박스가 요건 (b)를 채우지 못할 때**: 예외를 두지 않고 즉시 사용자 결정을 받는다. 대안의 예는 NemoClaw 없이 OpenShell만 쓰는 대체 경로다.

## 7. 위험과 대체 경로

### 7.1 NemoClaw 경로

- **알아채는 신호**: X1이 착수 뒤 3시간(조정값) 안에 한 줄 경로를 통과하지 못한다. Brev 단계에서도 다시 3시간(조정값) 안에 통과하지 못한다.
- **대체 경로**(개발 플랜 §5.4, 사용자 결정)
  1. OpenShell과 NemoClaw는 로컬 Docker로 먼저 시도한다. OpenShell 게이트웨이는 Linux(glibc 2.28 이상) 전용이라 macOS에서는 Docker 안에서 돌린다 `[사실: HSGATE_R3_NVIDIA_STACK_CHECK.md §7]`. NemoClaw는 알파 단계다 `[사실: 대회 조사 문서 §9]`.
  2. X1이 3시간을 넘기면 원인과 무관하게(단, 아래 "따로 다루는 두 경우"는 제외) Brev(드라이버·Docker 등이 미리 갖춰진 NVIDIA 원클릭 클라우드 개발 환경)로 옮긴다. Brev는 실행 환경을 클라우드 Linux로 옮기는 단계라, 로컬 Docker에서 난 게이트웨이·NAT·로그 문제도 여기서 풀릴 수 있다 `[추론]`. 원인이 NemoClaw 밖이면 이때 사용자에게 알린다. Brev 단계에도 기본 시한 3시간을 둔다 `[DESIGN, 조정값]`.
  3. Brev 단계도 3시간을 넘기면 원인을 판별한다. 원인이 NemoClaw 구간이면 OpenShell만 쓰고 제출서에 사실대로 적는다.
- **OpenShell만 단계가 풀지 못하는 경우** `[DESIGN, 조정값]`: Brev 단계에서도 시한을 넘긴 원인이 OpenShell 게이트웨이 자체, NAT 실행 추적, 감사 로그일 때가 있다. 이 셋은 NemoClaw를 빼도 남으므로 OpenShell만 단계는 이 셋을 풀지 못한다. 이때는 우회하지 않고 즉시 사용자 결정을 받는다(§6.4).
- **바뀌지 않는 것**: 채점 대상 실행은 처음부터 OpenShell 안 CLI로 직접 돌리고 NemoClaw를 거치지 않는다. 그래서 대표 지표와 보조 지표의 실행 방식은 그대로다.
- **바뀌는 것**
  - §3 체크리스트 1번은 대체 경로와 사실 표기로 대신한다.
  - 제출서에는 시도한 환경(로컬 Docker, Brev), 실패한 지점, 대신 쓴 경로를 적는다. OpenShell만 쓴 경우 NemoClaw 시연과 스킬 호출 성공률은 "측정하지 못함"으로 적고, 쓰지 않은 기능을 쓴 것처럼 적지 않는다.
  - 자기채점에서 OpenShell만 쓰는 단계까지 가면 규범 `1c`는 0 또는 1, 규범 `1a`는 구성요소 4개 이하가 된다. Brev에서 NemoClaw 경로가 서면 `1c`는 실제 증거대로 매긴다(룰북 `1c` 주석과 부록 39번, 개발 플랜 §5.4). OpenShell 증거가 있으면 CAP-2(`1b`와 `1c`가 모두 0일 때의 축 1 상한)는 발동하지 않는다.
  - Brev로 옮기면 실행 환경이 로컬과 다르다는 사실을 결정 기록과 재현 안내에 적는다. 이것은 X1이 확인한 결과가 아니라 사용자가 정한 대체 경로를 적용한 환경 결정이다(개발 플랜 §5.4). X1의 세부 진단은 X1 임시 시험 기록(옛 이름, 자료 계약 §10.3)과 X1 PR 본문에 둔다.
- **따로 다루는 두 경우**(대체 경로와 별개로 즉시 사용자 결정, §6.4)
  - 두 키 주입 방식(credential placeholder rewrite와 `inference.local`)이 모두 실패: 키를 샌드박스에 넣는 우회를 하지 않는다. 대안의 예는 채점용 실행을 OpenShell 없이 돌리는 안이다. 이 안은 "채점 대상 실행"의 정의와 실행 규칙을 바꾸므로 명세 변경이 필요한 사용자 승인 대상이다. 고르면 채점 실행에 통제 ①(샌드박스 파일시스템 정책이 저장소 안 정답 경로 읽기를 막는 통제)과 요건 (b)의 증거가 없고 규범 G2가 약해진다는 점을 결정 자료에 함께 적는다.
  - 시연 샌드박스가 요건 (b)(외부 전송은 NVIDIA 추론 엔드포인트만, L7 method·path 명시, `rules` 생략과 범용 바이너리 + `/**` 조합 금지)를 채우지 못함: 예외를 두지 않는다. 대안의 예는 위 3번(NemoClaw 없이 OpenShell만)이다.

### 7.2 `g1`

- **알아채는 신호**: 2026-09-26(토) 18:00까지 `g1` 동결 결정 기록이 없거나, D 검수(병렬 규칙 §3.4)를 통과하지 못했다.
- **대체 경로**: `g0`로 채점하고 제출서에 사실대로 적는다. 실행 기록의 `grouping_version`에는 실제로 쓴 값(`g0`)을 적는다.
- **왜 동결 조건인가**: 비교 대상이 `g0`에서 `g1`로 바뀌면 실자료 사례의 조사 경로와 보고서 숫자가 바뀐다. 그래서 `g1` 동결 또는 `g0` 대체 선언이 `RB-1`의 동결 조건이다.
- **위험을 줄이는 방법**: `g1`은 2026-09-27(일)로 미루지 않고 2026-09-24(목)부터 병렬로 진행한다. BACI 원본이 이미 로컬에 있다(개발 플랜 §8.2). 동결 뒤 바꾸려면 새 `grouping_version`과 사유가 필요하다(평가 구성 → 사용자 승인).
- 합성 자료(`dev20`, holdout40)의 비교 대상은 자료 안의 합성 `peer_group`이라 `g0`·`g1`과 무관하다.
