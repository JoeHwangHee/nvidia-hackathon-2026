## 1. 대회 요건 — 두 시나리오에 공통

제출물은 제품의 크기와 무관하게 아래로 정해져 있다 `[사실: 대회 조사 문서 §3·§4 Section 02]`. 형식 요건과 별도로 "Skill API 활용 데모 프로젝트"라는 내용 요건이 있다(아래 참가 조건 행). "Skill API"는 공식 명칭이 아니어서 충족을 단정할 수 없고, TradeSentry는 그 두 실체(Agent Skills, NIM 추론 API)를 모두 쓰므로 대응한다고 본다 `[추론]`.

| 요건 | 내용 |
|---|---|
| 파일 | 1개, 최대 100MB, 양식 제한 없음. GitHub 링크는 pdf·word 문서 안에 기입. 파일명 `[NVIDIA 해커톤_팀명_프로젝트명]` |
| 글 | Problem Definition 300자 내외, Solution 500자 내외, Tech Stack(제한 없음. NVIDIA 모델명·라이브러리·프레임워크와 전체 스택을 구체적으로 나열) |
| 불필요 | 데모 영상·배포 URL(선택 항목) |
| 참가 조건 | 2~5인 팀만(개인 불가), 팀원 전원이 같은 팀명으로 각자 폼 제출, 팀장만 Section 02 작성, 2007년 이후 출생자 포함 시 팀 전체 무효, 지정 교육 미션(DLI "Securing Agents with NemoClaw and OpenShell") 선행, 그리고 **build.nvidia.com의 "Skill API"를 활용한 데모 프로젝트 제출**(공식 제품명이 아니라 Agent Skills(`build.nvidia.com/skills`)와 NIM 추론 API(`integrate.api.nvidia.com/v1`) 두 가지를 뜻하며 둘 다 쓰는 것이 안전하다. TradeSentry는 둘 다 쓴다: 공식 스킬 3개와 자체 SKILL.md, NIM의 Nemotron 호출. 충족 여부의 최종 판단은 주최 측이 한다 `[추론]`) `[사실: 같은 문서 §3·§7]` |
| 심사 기준(순서 그대로) | ① NVIDIA Agent 기술 활용 심도 ② 실용성·산업가치·혁신성 ③ 완성도 ④ 커스터마이징 수준·독창성 등 `[사실: 같은 문서 §5]` |

참가 조건은 저장소에서 확인할 수 없는 사항이라 사용자가 직접 확인한다. 이 문서의 어느 시나리오도 참가 조건을 대신하지 못한다.

## 2. 공통 작업 — 어느 시나리오를 골라도 해야 하는 것

MVP 합격(로드맵 §3의 9개 항목 통과) 뒤 제출까지 남는 공통 작업이다. 로드맵 §5 "끝까지 지키는 것"(대표 지표, holdout40 비교군, OpenShell 증거)이 모두 여기에 든다. 이 문서는 봉인 자료의 내용을 다루지 않는다. 봉인 자료의 생성·해시 등록은 격리된 생성 에이전트가, 채점은 샌드박스 밖 독립 채점기가 하며(병렬 개발 규칙 §6, 룰북 B6), 여기서는 작업 이름·시각·완료 기준만 적는다.

| 1 | MVP 1번의 `real_dev` NemoClaw 시연 | V1 | NemoClaw 에이전트 → tradesentry 스킬 → OpenShell 안 CLI 경로로 `real_dev` 경보 1건이 유효한 최종 보고서까지 간 증거. A/B/C 합성 사례는 2026-09-25(금) 09:24에 통과했고, `real_dev` 시연은 두 번(12:49 무효, 15:5x 제공자 한도) 실패해 남아 있다 | 0.5시간(제공자가 안정된 시간대) | 실패가 이어지면 로드맵 §7.1 대체 경로와 사실 표기 |
| 2 | 자기채점 1회차 | V1(체크리스트 8번) | 평가 스킬 ①로 `artifacts/scorecard/scorecard-{시각}/scorecard-{시각}.md` | 1시간 | 점수마다 근거 한 줄과 경로 |

## 3. 시나리오 A — MVP 수준 제출

MVP 9개 항목 + 공통 작업 + 심사위원이 저장소를 열어 볼 때 필요한 최소한. 화면과 승인 모의는 만들지 않는다.

| 작업 | 로드맵 ID | 내용 | 시간 `[추정]` | 자기채점 영향(룰북 A2) |
|---|---|---|---|---|
| README | P1(최소형) | 저장소 루트에 README를 새로 쓴다(지금은 없다 `[사실: 저장소 루트에 README.md 없음]`). 문제·구조·설치·키 없는 스모크·평가 실행·재현 명령·증거 위치·자료 이용 조건·비밀값 검사 | 1.5~2시간 | `3c` 1점(README대로 여러 단계 실행. 룰북 A2의 점수 단계는 0·1·3·5) |
| 키 없는 스모크 재현 | P1(최소형) | README의 명령 하나(`tradesentry <명령>`)로 커밋된 합성 픽스처(`controlled_fixture_v0`의 A/B/C)와 기록된 응답으로 모델 모드 사례가 끝까지 돈다. 지금 있는 것: 호스트 백엔드(같은 프로세스 실행, 시험·스모크용)와 재생 전송(단위 I8 `ReplayTransport`) `[사실: `src/tradesentry/cli/dispatch.py` 머리 주석, `src/tradesentry/workflow/replay.py`]`. 없는 것: CLI에서 기록된 응답 파일을 고르는 옵션과 커밋된 재생 픽스처 `[사실: 2026-09-26(토) 확인. `dispatch.py` 인자 파서에 재생 옵션 없음]` | 코드 1.5~2시간 + 픽스처 기록 0.5시간 | `3c` 3점 |

- 합계 `[추정]`: 카드 없이 4~5시간, 카드 포함 5~6.5시간. 2026-09-27(일) 하루 안에 F2·R1과 나란히 할 수 있다.
- 결과: 자기채점 `3c` 3점, `3f` 1점(채점 요약의 표만), `3d` 5점(NAT 프로파일러 결과를 결과 요약에 옮겨 제시 — 채점 요약 4절 "NAT 프로파일 요약(참고)" `[사실: artifacts/eval/score-260926003407/scorer_summary-260926003407.md]`. 앵커 문구 대조는 자기채점 2회차에서 한다). 승인 모의는 룰북 Part A의 채점 앵커가 아니라 점수에 직접 들지 않는다(룰북 399줄 근처: 불변식 시험은 따로 둔다).

- 위험: 심사 기준 ③ 완성도에서 "CLI만 있는 데모"로 읽힐 수 있다. README의 실행 사례 화면 갈무리(터미널 출력, 보고서 한국어 렌더)를 넣어 보완한다.

| 시연 갈무리 | P3 보조 | NemoClaw 경로·화면의 갈무리(GIF·스크린샷)를 제출 pdf에 넣는다. 키·토큰·로컬 경로가 화면에 없어야 한다 | 1시간 | 심사 기준 ①·③ 전달력 |

- 합계 `[추정]`: 화면 셋 6.5~7시간 + 승인 모의 2~3시간 + 카드 1~1.5시간 + 갈무리 1시간 = 10.5~12.5시간(원클릭 2~3시간 제외). 시나리오 A 4~6.5시간을 더하면 14.5~19시간. 토요일 오후~일요일 내내 F2·R1과 병렬로 진행해야 맞출 수 있다.
- 동결과의 관계: `app.py`·`approval/`은 채점 경로(탐지·조사·검증·채점)가 아니어서 `RB-1` 동결 뒤에도 고칠 수 있다. 다만 봉인 묶음(F2)은 동결 커밋의 이미지로 돌리고, 화면·승인 PR은 그 뒤 커밋이라는 점을 결과 요약과 README에 적는다. 채점 경로 파일을 건드리는 순간 동결 위반이다.
- 결과: `3c` 3점(원클릭이면 5점), `3f` 5점, 심사 기준 ③·④에서 "데모 가능한 애플리케이션"으로 읽힌다.
- 위험: 시간이 F2·R1·P3의 품질과 경쟁한다. 봉인 채점·결과표·제출 문서가 밀리면 화면 3번째 → 2번째 → 승인 모의 순으로 뺀다(로드맵 §5의 역순 = 만든 순서의 역순). 화면은 봉인 실행 결과를 금지 해제 조건 전에 보여 주지 않는다(자료 계약 §10.3 N10).

## 5. 한눈에 비교

| 항목 | A: MVP 수준 | B: 풀 애플리케이션 수준 |
|---|---|---|
| 추가 시간 `[추정]` | 4~6.5시간 | 14.5~19시간 |
| 심사 ① 기술 심도 | 같다(5개 구성요소 실행 증거) | 같다 |
| 심사 ② 실용성·가치 | 같다(대표 지표는 공통 작업의 F2에서) | 같다 |
| 심사 ③ 완성도 | CLI 데모 + README + 재현 | 화면 3개 + 승인 흐름 + 재현 묶음 |
| 심사 ④ 커스터마이징·독창성 | 정책·워크플로·스킬·검증 설계 | 같다 + 화면의 before-after 대조 |
| 자기채점 `3c`/`3f`(점수 단계 0·1·3·5) | 3점 / 1점 | 3~5점 / 5점 |
| 주된 위험 | "CLI만 있다"는 인상 | F2·R1·P3 시간 압박 |
| 고르는 조건(제안) | 토요일 18:00에 F1이 늦어졌거나 V1 5차에 새 막힘이 있으면 | 토요일 18:00 전에 F1이 끝나고 F2 시작 준비가 됐으면 |

중간 선택지 "A + 화면 1개"도 가능하다(추가 2.5~3시간. 화면에 차트를 넣으면 `3f` 3점, 표·글만이면 1점). 심사 기준 ③에서 가장 적은 비용으로 인상을 바꾸는 항목이 화면 1(사례 보기)이다.

## 6. 어느 쪽이든 미리 해 두면 좋은 것

- 스모크 재현의 코드 작업(재생 옵션 + 픽스처 기록)은 두 시나리오에 다 필요하니 V1 5차가 도는 동안 시작할 수 있다. 채점 경로를 건드리지 않는 CLI 옵션 추가라 `RB-1` 전에 넣는 것이 깔끔하다.
- README 골격(구조·설치·명령·증거 위치)도 미리 쓴다. 숫자는 R1 뒤에 채운다.
- 시연 갈무리는 F2 전용 샌드박스가 아니라 시연용(x1-demo)에서 찍는다.
